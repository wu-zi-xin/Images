在 Linux 中，我們用 mount 指令把光碟機 (/dev/sr0) 裡面的資料，投射到系統內建的空資料夾 (/media) 裡面。

(使用 9dd 刪除中間兩個不要的區塊，用 dG 刪除最下方的區塊) (找到 [baseos] 區塊，把 metalink 那行前面加上 # 註解掉) (在 [baseos] 區塊加入這行👇) baseurl=file:///media/BaseOS (找到 [appstream] 區塊，把 metalink 那行前面加上 # 註解掉) (在 [appstream] 區塊加入這行👇) baseurl=file:///media/AppStream

D. 試ping (IP與路由通訊)

💻 PC1 任務
1. 圖形介面設定 IP (記得勾選自動連線。核對 MAC 末2碼，確認哪片是橋接網卡)：
(enp1s0 網卡)設定為： IP: 200.100.X.254 子網路遮罩: 255.255.255.0 通訊閘: 0.0.0.0 (enp1s2 網卡)設定為： IP: 10.1.X.1 子網路遮罩: 255.255.255.0 通訊閘: 10.1.X.254
2. 開啟防火牆對應的服務通道：
firewall-cmd --add-service=http --permanent firewall-cmd --add-service=https --permanent firewall-cmd --add-service=ftp --permanent firewall-cmd --add-masquerade --permanent
3. Masquerade 要搭配 IP Forwarding (兩個是同一組觀念)：
關聯： Masquerade 負責把 PC2 封包的來源 IP 偽裝成 PC1 的對外 IP；IP Forwarding 則負責允許 Linux 把封包從一張網卡轉送到另一張網卡。
所以 PC1 要當 NAT 路由器，兩個都要有。
先查目前 IP Forwarding 狀態：
sysctl net.ipv4.ip_forward # 看到以下結果代表已開啟 net.ipv4.ip_forward = 1
如果沒開：暫時啟用 (重開機後失效)
sysctl -w net.ipv4.ip_forward=1
永久啟用：
echo "net.ipv4.ip_forward = 1" >> /etc/sysctl.conf sysctl -p
考場記法：Forwarding＝「准許轉送」；Masquerade＝「換來源 IP」。看到 --add-masquerade，就一起想到 net.ipv4.ip_forward=1。
4. 重新載入防火牆規則：
firewall-cmd --reload
5. 重新啟動網頁服務 (先關再開比較穩)：
systemctl stop httpd systemctl start httpd
6. 進行 Ping 測試 (先 ping 自己網卡，再 ping 別台)：
ping 10.1.X.1 ping 10.1.X.2 ping 10.1.X.254 ping 10.1.200.200 ping 200.100.X.254 ping 200.100.X.2 ping 200.100.X.1
🖥️ PC2 任務
1. 圖形介面設定 IP：
(enp1s0 網卡) 分別加入以下三個 IP： IP1: 200.100.X.1 / 子網路遮罩: 255.255.255.0 IP2: 200.100.X.254 / 子網路遮罩: 255.255.255.0 IP3: 200.100.X.2 / 子網路遮罩: 255.255.255.0
2. 開啟 FTP 防火牆通道：

3. 重新載入防火牆規則：

4. 重新啟動 FTP 服務：

G. 設定 (核心配置檔)

💻 PC1 任務
1. 編輯 Apache 網頁伺服器的設定檔：
vim /etc/httpd/conf.d/userdir.conf
2. 在 vim 內執行以下修改：
第 17 行：在 UserDir disabled 前面加上 # 註解掉 第 24 行：把 #UserDir public_html 的 # 刪掉，並把 public_html 改成 www 第 31 行：把 <Directory "/home/*/public_html"> 改成 www (游標停在31行，輸入 5yyp 往下貼上 5 行，並將貼上的這區塊改成下方內容👇) <Directory "/home/WebX-2/www"> AllowOverride All Order deny, allow Deny from all Allow from 200.100.X.1 </Directory>

I. 考場觀念與避坑指南

🖥️ PC1 與 PC2 到底誰是 Server 誰是 Client？
這是一個對稱的「雙向主從架構」！兩台機器互為對方的 Server 與 Client：
  • PC1 (網頁伺服器 Web Server)：提供 Web 網站。同時作為 FTP 用戶端 (Client) 使用終端機去連線測試 PC2。
  • PC2 (FTP 伺服器 FTP Server)：提供檔案下載與 Quota 空間限制。同時作為 網頁用戶端 (Client) 打開瀏覽器去測試 PC1 的網頁。
你可以把它當作 API 的 Request 與 Response 來想像——PC1 提供 Web 端點等著被 Call，PC2 提供 FTP 端點等著接收檔案。
💡 考場除錯與避坑指南
1. 實體層與網路層 (OSI Layer 1 & 3) 的陷阱：
  • 做線是生死關： 如果「步驟 D (試 Ping)」失敗了，絕對不要先回去改防火牆或設定檔！百分之八十的問題出在實體層。請檢查網路線有沒有壓緊、色序對不對，或是網卡 IP（200.100.X 系列與 10.1.X 系列）有沒有綁錯張。
  • 路由不通： 測試 Ping 時，如果可以 Ping 到自己的網卡，卻 Ping 不到對面，通常是子網路遮罩 (Subnet Mask) 打錯，或是 PC1 的 NAT (Masquerade) 轉發沒有成功啟動。
2. 系統與應用層 (OSI Layer 7) 的陷阱：
  • Linux 嚴格區分大小寫： 例如 Apache 設定檔中的 AllowOverride All 或 Order deny, allow，只要大小寫打錯一個字，重啟服務時就會報錯。
  • 權限死胡同： 在 PC1 建立網頁目錄時，為什麼一定要下 chmod o+x？因為 Apache 服務在系統中的身分是「其他人 (Others)」，如果沒有給予執行 (x) 權限，Apache 就無法穿越使用者的 Home 目錄去讀取裡面的網頁，這時瀏覽器就會顯示 403 Forbidden。
  • 設定檔生效的唯一條件： 只要你用 vim 修改了任何設定檔，都必須執行 systemctl restart [服務名稱]。系統服務只認記憶體裡面的規則，沒有重啟就等於沒改。
3. 終端機 (Vim) 的操作效率：
  • 善用 Tab 鍵補全： 在輸入像 firewall-cmd --add-masquerade 這種長指令時，打到 masq 就按下 Tab 鍵。這不僅能加快速度，還能保證你沒有拼錯字。
  • 不怕 Vim 改錯： 如果在用 9dd 或 5yyp 複製刪除時不小心手滑把設定檔弄亂了，千萬別慌張。只要按下 Esc，然後輸入 :q! (強制不存檔離開)，再重新 vim 打開一次檔案，一切就會回到原本的樣子。

  • 網路與主機名稱 → 輸入主機名稱 → 套用 → 完成。
③ 軟體選擇
PC1勾選 Basic Web Server；來源資料註記位置在右側清單拉到底第 1 個。
PC2勾選 FTP Server；來源資料註記位置在一開始第 4 個。
④ Root 密碼
  • 點 Root 密碼 → 輸入密碼 → 完成兩次。
⑤ 建立使用者
PC1安裝資料示例為 Web3X-2，並取消「需要密碼才能使用此帳號」。
PC2安裝資料示例為 Ftp3X-2，密碼同名。

K. NAT / 雙網卡路由完整指南

整合來源：已把你新上傳的「Linux 雙網卡路由與 NAT 架構指南」完整觀念併入這一站，依手機閱讀方式改成 5 個主題卡片。
🧠 先記一句話
PC1（左側機器）是「雙網卡路由器／防火牆」；PC2（右側機器）是「純內網伺服器」。PC2 要去外網，先把封包交給 PC1 的對內網卡，再由 PC1 做 IP Forwarding + NAT / Masquerade 往外送。
① 網路架構與封包傳遞路線
實體線路與角色定位
  • PC1／左側機器：有兩張網卡，一張對內、一張對外，負責把內網封包轉發到外網。
  • PC2／右側機器：只在內部網段，沒有直接對外能力，必須經過 PC1 才能連外。
封包接力路線
PC2（200.100.X.1） ↓ 目的地不在本網段 → 丟給預設閘道 PC1 對內網卡（200.100.X.254） ↓ IP Forwarding ↓ NAT / Masquerade：來源 IP 改成 10.1.X.1 PC1 對外網卡（10.1.X.1） ↓ 預設閘道 10.1.X.254 考場／機房實體路由器 ↓ 外部網路
記法：PC2 找「大門」 → 大門是 PC1 對內卡 → PC1 換身分（NAT）→ 再走自己的外網大門。
② 純內網伺服器（PC2）預設閘道
預設閘道就是「離開目前網段的大門」

PC2 位在 200.100.X.0 網段。只要它要去的目的地不在這個網段，就會把封包交給預設閘道，所以閘道要指向 PC1 的對內 IP。

# PC2 範例 網卡：enp1s0 IP：200.100.X.1 Mask：255.255.255.0 Gateway：200.100.X.254
核心觀念：PC2 的 Gateway 不是直接填機房路由器，而是填「PC1 對內網卡」。因為 PC2 的第一跳就是 PC1。
③ 路由器主機（PC1）雙網卡配置
對內網卡
IP：200.100.X.254 Mask：255.255.255.0 Gateway：留空／0.0.0.0
  • 用來接 PC2 從內網送過來的封包。
  • 不要在這張卡設定預設閘道。
對外網卡
IP：10.1.X.1 Mask：255.255.255.0 Gateway：10.1.X.254
  • 連到考場／機房實體網路。
  • 真正的預設閘道設在這張卡，指向機房路由器。
容易混：兩個網段都可能看到 .254，但意義不同：200.100.X.254 是 PC1 自己的「內網卡 IP」；10.1.X.254 才是 PC1 對外要走的「實體路由器 Gateway」。
④ IP 偽裝與 NAT（Masquerade）
Masquerade 實際做什麼？
  1. PC1 從對內網卡收到 PC2 想連外的封包。
  2. 把來源 IP 從 PC2 的 200.100.X.1 改成 PC1 對外卡的 10.1.X.1。
  3. 再把封包送往 PC1 的外網 Gateway 10.1.X.254。
# 啟用 NAT / IP 偽裝 firewall-cmd --add-masquerade --permanent firewall-cmd --reload
為什麼需要 NAT？ 外部網路不會直接把 PC2 的內部位址當成可回傳的來源；PC1 先把來源偽裝成自己的外網 IP，回應才會先回到 PC1，再由 PC1 對應回 PC2。
⑤ 核心 IP Forwarding（轉發開關）
IP Forwarding 是什麼？

Linux 若只是一般主機，收到「目的地不是自己」的封包時不會自動幫別人轉送。PC1 要當路由器，就要開啟 net.ipv4.ip_forward，讓封包能在兩張網卡之間轉發。

先查目前狀態
sysctl net.ipv4.ip_forward # 看到以下結果代表已開啟 net.ipv4.ip_forward = 1
暫時啟用（重開機後失效）
sysctl -w net.ipv4.ip_forward=1
永久啟用
echo "net.ipv4.ip_forward = 1" >> /etc/sysctl.conf sysctl -p
兩個都要理解：IP Forwarding 負責「允許跨網卡轉送」，Masquerade 負責「修改來源 IP」。只開其中一個，都不能完整達成 PC2 經 PC1 對外通訊的效果。
📱 通勤 30 秒總複習
PC2：200.100.X.1 GW → 200.100.X.254 PC1 內：200.100.X.254 GW → 不設 PC1 外：10.1.X.1 GW → 10.1.X.254 PC1 還要： ① ip_forward = 1 ② firewall masquerade
口訣：右機找左機、左機才找外；先能「轉」，再做「換」。
