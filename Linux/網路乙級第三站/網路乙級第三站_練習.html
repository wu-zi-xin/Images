C. 套件 (軟體庫與掛載)

💡 為什麼要掛載光碟？
考場沒有外網，所以我們要把安裝光碟當作「本地下載點」。
在 Linux 中，我們用 mount 指令把光碟機 (/dev/sr0) 裡面的資料，投射到系統內建的空資料夾 (/media) 裡面。
💻 PC1 任務

📌 事前準備：將光碟放入光碟機

1. 進入系統軟體庫目錄：
cd /etc/yum.repos.d
2. 建立備份資料夾：
mkdir backup
3. 將現有檔案複製到備份區 (如果有錯誤訊息不用理它)：
cp * backup
4. 刪除不需要的擴充套件清單：
rm centos-addons.repo -y
5. 打開並編輯主要設定檔：
vim centos.repo
6. 在 vim 編輯器內執行以下修改：
(使用 9dd 刪除中間兩個不要的區塊，用 dG 刪除最下方的區塊) (找到 [baseos] 區塊，把 metalink 那行前面加上 # 註解掉) (在 [baseos] 區塊加入這行👇) baseurl=file:///media/BaseOS (找到 [appstream] 區塊，把 metalink 那行前面加上 # 註解掉) (在 [appstream] 區塊加入這行👇) baseurl=file:///media/AppStream
7. 檢查系統是否有抓到光碟機：
df -h
8. 將光碟掛載到 /media 資料夾 (畫面出現 read-only 警告代表成功)：
mount /dev/sr0 /media
9. 安裝架站與系統所需套件 (一個一個裝，確認都有成功)：
dnf install httpd -y dnf install mod_ssl -y dnf install ftp -y dnf install firewall-config -y dnf install ibus-table-cangjie -y
10. 編輯系統安全設定檔，準備關閉 SELinux：
vim /etc/selinux/config
11. 在 vim 編輯器內修改：
SELINUX=disabled
12. 重新開機 (必須重開機，剛裝的中文輸入法才會生效)：
reboot
🖥️ PC2 任務

📌 第 1 到 8 步的掛載光碟動作，與 PC1 完全相同

9. 安裝 FTP 與系統所需套件：

10. 編輯系統安全設定檔：

D. 試ping (IP與路由通訊)

💻 PC1 任務
1. 圖形介面設定 IP (記得勾選自動連線。核對 MAC 末2碼，確認哪片是橋接網卡)：
(enp1s0 網卡)設定為： IP: 200.100.X.254 子網路遮罩: 255.255.255.0 通訊閘: 0.0.0.0 (enp1s2 網卡)設定為： IP: 10.1.X.1 子網路遮罩: 255.255.255.0 通訊閘: 10.1.X.254
2. 開啟防火牆對應的服務通道：

3. 重新載入防火牆規則：

4. 重新啟動網頁服務 (先關再開比較穩)：
systemctl stop httpd systemctl start httpd
5. 進行 Ping 測試 (先 ping 自己網卡，再 ping 別台)：
ping 10.1.X.1 ping 10.1.X.2 ping 10.1.X.254 ping 10.1.200.200 ping 200.100.X.254 ping 200.100.X.2 ping 200.100.X.1

G. 設定 (核心配置檔)

💻 PC1 任務
1. 編輯 Apache 網頁伺服器的設定檔：
vim /etc/httpd/conf.d/userdir.conf
2. 在 vim 內執行以下修改：
第 17 行：在 UserDir disabled 前面加上 # 註解掉 第 24 行：把 #UserDir public_html 的 # 刪掉，並把 public_html 改成 www 第 31 行：把 <Directory "/home/*/public_html"> 改成 www (游標停在31行，輸入 5yyp 往下貼上 5 行，並將貼上的這區塊改成下方內容👇) <Directory "/home/WebX-2/www"> AllowOverride All Order deny, allow Deny from all Allow from 200.100.X.1 </Directory>

⚠️ 檢查：改完後檔案裡面要有 2 塊獨立的 <Directory> 區塊！

3. 進入第二個網站的資料夾：
cd /home/WebX-2/www

4. 複製一份設定檔給第二台 FTP 使用：

I. 考場觀念與避坑指南

🖥️ PC1 與 PC2 到底誰是 Server 誰是 Client？
這是一個對稱的「雙向主從架構」！兩台機器互為對方的 Server 與 Client：
  • PC1 (網頁伺服器 Web Server)：提供 Web 網站。同時作為 FTP 用戶端 (Client) 使用終端機去連線測試 PC2。
  • PC2 (FTP 伺服器 FTP Server)：提供檔案下載與 Quota 空間限制。同時作為 網頁用戶端 (Client) 打開瀏覽器去測試 PC1 的網頁。
你可以把它當作 API 的 Request 與 Response 來想像——PC1 提供 Web 端點等著被 Call，PC2 提供 FTP 端點等著接收檔案。
💡 考場除錯與避坑指南
1. 實體層與網路層 (OSI Layer 1 & 3) 的陷阱：
  • 做線是生死關： 如果「步驟 D (試 Ping)」失敗了，絕對不要先回去改防火牆或設定檔！百分之八十的問題出在實體層。請檢查網路線有沒有壓緊、色序對不對，或是網卡 IP（200.100.X 系列與 10.1.X 系列）有沒有綁錯張。
  • 路由不通： 測試 Ping 時，如果可以 Ping 到自己的網卡，卻 Ping 不到對面，通常是子網路遮罩 (Subnet Mask) 打錯，或是 PC1 的 NAT (Masquerade) 轉發沒有成功啟動。
2. 系統與應用層 (OSI Layer 7) 的陷阱：
  • Linux 嚴格區分大小寫： 例如 Apache 設定檔中的 AllowOverride All 或 Order deny, allow，只要大小寫打錯一個字，重啟服務時就會報錯。
  • 權限死胡同： 在 PC1 建立網頁目錄時，為什麼一定要下 chmod o+x？因為 Apache 服務在系統中的身分是「其他人 (Others)」，如果沒有給予執行 (x) 權限，Apache 就無法穿越使用者的 Home 目錄去讀取裡面的網頁，這時瀏覽器就會顯示 403 Forbidden。
  • 設定檔生效的唯一條件： 只要你用 vim 修改了任何設定檔，都必須執行 systemctl restart [服務名稱]。系統服務只認記憶體裡面的規則，沒有重啟就等於沒改。
3. 終端機 (Vim) 的操作效率：
  • 善用 Tab 鍵補全： 在輸入像 firewall-cmd --add-masquerade 這種長指令時，打到 masq 就按下 Tab 鍵。這不僅能加快速度，還能保證你沒有拼錯字。
  • 不怕 Vim 改錯： 如果在用 9dd 或 5yyp 複製刪除時不小心手滑把設定檔弄亂了，千萬別慌張。只要按下 Esc，然後輸入 :q! (強制不存檔離開)，再重新 vim 打開一次檔案，一切就會回到原本的樣子。
