主題一：PHP 與 MariaDB 資料庫整合

動作目的

動作目的：
為了讓網頁前端能夠順利存取並顯示後端的 MariaDB 資料庫內容，必須在伺服器安裝指定的溝通套件，並修改範例 PHP 程式碼來撈取精確的表單資料（如七大洲清單），最後確保服務與防火牆設定皆已放行連線。

執行步驟與指令範例

步驟 1：安裝 PHP 與資料庫連線套件
指令解釋： 僅有 Apache 伺服器無法讓 PHP 網頁去撈取資料庫。我們需透過本地掛載光碟，利用 dnf install 安裝 php-mysqlnd 套件，為 PHP 提供存取 MariaDB (相容 MySQL) 的能力。
透過套件管理器安裝 PHP 資料庫連線模組
dnf install php-mysqlnd
步驟 2：啟動 HTTP 服務與防火牆放行
指令解釋： 套件安裝完畢後，必須使用 systemctl 啟動 Apache (httpd) 伺服器。接著，使用 firewall-cmd 在防火牆開啟 HTTP 服務 (Port 80)，讓外部的電腦（如 .72 的機器）能夠檢視您寫好的 PHP 網頁。
啟動 Apache 網頁伺服器
systemctl start httpd
於防火牆永久開啟 HTTP 服務
firewall-cmd --add-service=http --permanent
firewall-cmd --reload
步驟 3：修改 PHP 存取資料庫之程式碼
指令解釋： 透過修改範例檔案 select.php，將 SQL 語法修改為從 nation 資料庫抓取 continent 表單。網頁上僅需呈現大洲編號與名稱，因此需將無關的學生欄位刪除，僅留下 cid 與 name。
於 select.php 修改 SQL 查詢與顯示欄位 (PHP 語法示意)
$sql = "SELECT cid, name FROM continent ORDER BY cid ASC";
HTML 表格列印迴圈中，僅保留兩個對應欄位
echo "<td>" . $row["cid"] . "</td>";
echo "<td>" . $row["name"] . "</td>";

主題二：LVM 邏輯捲軸管理 (磁碟擴充)

動作目的

動作目的：
解決單顆硬碟容量不足的困境。透過 LVM (Logical Volume Manager) 技術，將多顆較小容量的實體硬碟 (PV)，整合成一個超大型的捲軸群組 (VG)，再依照需求從群組中切割出彈性的邏輯硬碟 (LV) 供系統掛載使用。

執行步驟與指令範例

步驟 1：硬碟分割與更改 LVM 類型
指令解釋： 裝上新硬碟後，使用 fdisk 指令進入磁碟分割介面。建立主要分割區後，最關鍵的是按 t 修改類型，輸入 8e 或是 lvm 將類型變更為 Linux LVM，否則後續將無法建立實體捲軸。
針對新掛載的硬碟 /dev/sdb 進行分割
fdisk /dev/sdb
互動指令流程說明
n (新增分割) -> p (主要分割) -> Enter (預設大小全用)
t (更改類型) -> lvm (或 8e) -> w (寫入並離開)
步驟 2：建立 PV (實體捲軸) 與 VG (捲軸群組)
指令解釋： pvcreate 能將處理好的分割區轉為實體捲軸。接著使用 vgcreate 將多個 PV 綑綁為名為 VG99 的捲軸群組，並使用 -s 16M 將基礎存儲單位 (PE, Physical Extent) 大小自訂為 16MB 以提升效能。
將三顆硬碟的分割區一起轉換為 PV
pvcreate /dev/sdb1 /dev/sdc1 /dev/sdd1
將這些 PV 整合成 VG99，並指定 PE 大小為 16M
vgcreate -s 16M VG99 /dev/sdb1 /dev/sdc1 /dev/sdd1
步驟 3：切割 LV (邏輯捲軸) 與格式化
指令解釋： 使用 lvcreate 從 VG99 中切出特定容量 (例如 5G) 並命名為 LV99。隨後，這顆切出的邏輯硬碟必須使用 mkfs.xfs 格式化為 XFS 檔案系統才能夠儲存資料。
建立容量為 5G，名稱為 LV99 的邏輯捲軸
lvcreate -n LV99 -L 5G VG99
將建立好的 LV 格式化為 xfs 檔案系統
mkfs.xfs /dev/VG99/LV99
步驟 4：設定開機自動掛載
指令解釋： 手動 mount 重開機會失效。我們利用 blkid 查出 LV 的專屬 UUID，並將其嚴謹地寫入 /etc/fstab 設定檔。請極度小心，此檔案若改錯會導致系統無法開機！
查詢該邏輯捲軸的 UUID
blkid
編輯 /etc/fstab 加入自動掛載設定 (範例)
vim /etc/fstab

# 在最下方加入這行：
UUID="你的UUID字串"  /mnt/D99  xfs  defaults  0 0

主題三：XFS 磁碟配額限制 (Quota)

動作目的

動作目的：
為避免單一惡意或粗心的使用者耗盡伺服器所有資源，系統管理員需限制特定使用者家目錄 (/home) 可使用的「磁碟容量大小 (Block)」與「建立檔案數量的總和 (Inode)」。

執行步驟與指令範例

步驟 1：啟動 Quota 配額機制
指令解釋： Linux 預設未開啟配額功能。必須編輯掛載點設定檔 /etc/fstab，在掛載 /home 的選項行中加入 usrquota 參數，並將伺服器重新啟動後，配額機制才會正式啟動。
編輯 fstab 檔案
vim /etc/fstab
找到 /home 掛載行，在 defaults 後方加入逗號與 usrquota 並重新開機
/dev/mapper/ol-home  /home  xfs  defaults,usrquota  0 0

reboot
步驟 2：設定容量與數量的軟/硬限制
指令解釋： 利用 xfs_quota 指令進入專家模式 (-x) 來限制帳號。bsoft/bhard 代表容量的軟/硬限制，isoft/ihard 則代表檔案數量的軟/硬限制。軟限制可以被短暫超越，但硬限制是系統絕對不允許跨越的底線。
針對 user71 同時設定容量 (6M軟/8M硬) 與數量 (12軟/14硬) 的限制
xfs_quota -x -c 'limit bsoft=6M bhard=8M isoft=12 ihard=14 user71' /home
步驟 3：產生測試檔與驗證配額阻擋
指令解釋： 我們可以藉由 dd 搭配 zero 裝置，快速產生指定大小的假檔案（如 6MB）來測試容量是否達標；亦可連續使用 touch 建立空檔測試數量限制。若測試寫入超過硬限制，系統將回應「磁碟配額已滿」。
利用 zero 虛擬裝置建立一個剛好 6MB 的測試檔案
dd if=/dev/zero of=6M bs=1M count=6
再次拷貝試圖超越 8MB 硬限制 (將遭系統阻擋，顯示配額已滿)
cp 6M 6M_2
步驟 4：查看報表與修改寬限期 (Grace Period)
指令解釋： 當超越軟限制時，系統會進入 7 天的「寬限期」。管理者可利用 report -ubi 印出包含容量與數量的全體報表。亦可透過 timer 修改寬限期（如改為 7 週或 7 小時），須注意修改適用「不溯及既往」原則。
列出所有使用者的 Quota 詳細報表與寬限期倒數
xfs_quota -x -c 'report -ubi' /home
修改全域容量寬限期為 7 週 (-b)，數量寬限期為 7 小時 (-i)
xfs_quota -x -c 'timer -u -b 7weeks -i 7hours' /home
