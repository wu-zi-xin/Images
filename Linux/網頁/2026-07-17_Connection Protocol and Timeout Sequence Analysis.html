主題一：基礎安裝與網路準備

動作目的

在 Linux 系統中透過套件管理員安裝 vsftpd 伺服器與 FTP 用戶端軟體。同時進行基礎的 IP 網路配置與防火牆設定，確保伺服器與用戶端之間能夠互相連通，並讓 FTP 封包順利通過防火牆 。

執行步驟與指令範例

步驟 1：安裝伺服器與用戶端軟體
使用 dnf install 透過本機光碟或網路資源安裝 FTP 伺服器套件與用戶端指令工具 。 
# 於伺服器端安裝 vsftpd
dnf install vsftpd

# 於用戶端安裝 ftp 連線指令
dnf install ftp
步驟 2：啟動與重新啟動服務
安裝完成後，伺服器並不會自動啟動。必須使用 systemctl start 啟動。日後只要修改了設定檔，皆須執行重啟指令才能套用 。 
# 啟動 FTP 服務
systemctl start vsftpd

# 重新啟動 FTP 服務 (設定檔修改後必備)
systemctl restart vsftpd
步驟 3：網路連通測試與防火牆放行
確認用戶端 (如 .82) 可 ping 通伺服器 (如 .81)。若 FTP 連線時顯示「被拒絕」，須至伺服器端防火牆放行 FTP 通訊協定 。 
# 1. 確認網路連線
ping 192.168.x.81

# 2. 開放防火牆 FTP 封包 (示意指令)
firewall-cmd --add-service=ftp --permanent
firewall-cmd --reload

# 3. 用戶端進行 FTP 連線
ftp 192.168.x.81

主題二：帳號登入與權限控管

動作目的

透過編輯 /etc/vsftpd/vsftpd.conf 檔案，精準管理本機帳號與匿名帳號 (anonymous) 的登入權限，並控制整體伺服器的上傳總開關，以實作更彈性的檔案共享環境 。

執行步驟與指令範例

步驟 1：開放匿名免密碼登入
預設情況下匿名登入是關閉的。編輯主要設定檔，將參數改為 anonymous_enable=YES (需全大寫) 才可允許無密碼登入 。 
# 編輯設定檔
vim /etc/vsftpd/vsftpd.conf

# 內部修改此行 (允許匿名登入)
anonymous_enable=YES

# 儲存後重新啟動
systemctl restart vsftpd
步驟 2：控制伺服器上傳總開關
write_enable=YES 為伺服器寫入的總樞紐，若將此值改為 NO，則包含原本可以上傳的本機帳號也會喪失上傳權限 。 
# 編輯設定檔，尋找 write_enable
vim /etc/vsftpd/vsftpd.conf

# YES 表示允許寫入，NO 表示全域禁止上傳
write_enable=YES
步驟 3：開放匿名上傳與資料夾權限
除了在設定檔中解開 anon_upload_enable=YES 外，還必須在 /var/ftp 建立專屬資料夾，修改群組為 ftp 並賦予寫入權限才能成功上傳 。 
# 1. 設定檔中允許匿名上傳
anon_upload_enable=YES

# 2. 建立專屬上傳資料夾
mkdir /var/ftp/upload

# 3. 變更群組為 ftp，並賦予寫入權限
chown :ftp /var/ftp/upload
chmod g+w /var/ftp/upload

主題三：單一登入類型限制

動作目的

藉由修改設定檔中的布林值，嚴格限制伺服器環境為「僅限匿名登入」或「僅限本機使用者登入」。若登入帳號不符規定，伺服器將直接拒絕連線 。

執行步驟與指令範例

步驟 1：只允許匿名登入
將設定改為 anonymous_enable=YES 且 local_enable=NO。此時若輸入一般本機帳號 (如 81)，會被拒絕並顯示 "anonymous only" 。 
# 於 vsftpd.conf 進行配置
anonymous_enable=YES
local_enable=NO

# 用戶端測試，若輸入非匿名帳號會顯示：
# 530 This FTP server is anonymous only.
步驟 2：只允許本機使用者登入
相反地，將設定改為 local_enable=YES 且 anonymous_enable=NO。此時 anonymous (匿名) 連線將被完全阻擋 。 
# 於 vsftpd.conf 進行配置
anonymous_enable=NO
local_enable=YES

# 儲存後執行重啟
systemctl restart vsftpd

主題四：設定專屬歡迎詞 (Banner)

動作目的

設定登入 FTP 時的「歡迎詞」，可以明確告知連線者伺服器的存取規則。系統支援直接撰寫單行文字，或指定外部文字檔來呈現多行訊息 。

執行步驟與指令範例

步驟 1：設定單行歡迎詞
在設定檔中搜尋並解開 ftpd_banner= 註解，於等號後方接上自訂字串。請注意字數與標點須完全正確，錯一字即扣分 。 
# 修改設定檔
vim /etc/vsftpd/vsftpd.conf

# 填入單行歡迎詞
ftpd_banner=歡迎光臨 您的名字 第八週 第一個 FTP server，只允許匿名登入
步驟 2：設定多行歡迎詞 (利用文字檔)
若內容較多，可使用 banner_file= 參數指定一組文字檔路徑。接著手動建立該資料夾與文字檔並編寫內容 。 
# 1. 在設定檔中加入路徑
banner_file=/var/banner/banner1.txt

# 2. 建立資料夾與文字檔
mkdir /var/banner
vim /var/banner/banner1.txt

# 3. 寫入多行歡迎文字並存檔
步驟 3：解除 SELinux 讀取阻擋
若因 SELinux 導致無法讀取 banner 檔案 (出現 can't read banner file)，需使用 setsebool -P 永久開啟 ftpd_full_access 權限 。 
# 檢查布林值狀態
getsebool -a | grep ftp

# 開啟 FTP 存取檔案的 SELinux 權限 (-P 代表永久生效)
setsebool -P ftpd_full_access=1

# 重新啟動服務
systemctl restart vsftpd

主題五：連線與超時限制

動作目的

為避免伺服器效能被過多連線拖垮，或遭逢使用者閒置佔用資源 (佔著茅坑不拉屎)，可設定「最高同時連線數」及「閒置超時自動斷線」機制 。

執行步驟與指令範例

步驟 1：限制最高連線數
預設允許 2000 條連線。設定 max_clients=1 可極端限制同時連線數，超過此數量時會拒絕新連線並顯示 "too many users" 。 
# 於設定檔加入此參數
max_clients=1

# 若超過 1 人連線，終端機會顯示：
# 421 There are too many connected users, please try again.
步驟 2：閒置超時自動斷線
透過 idle_session_timeout 參數設定秒數，若使用者在指定時間內未下達指令，系統將主動將其斷線以釋放資源 。 
# 於設定檔加入此參數，設定為 5 秒
idle_session_timeout=5

# 儲存後套用設定
systemctl restart vsftpd

主題六：磁碟配額 (Quota) 限制

動作目的

為防止單一帳號無限制地上傳檔案並塞滿伺服器硬碟，可透過 xfs_quota 工具對該使用者設立「硬限制 (Hard Limit)」，做到精準的容量控管 。

執行步驟與指令範例

步驟 1：設定硬體磁碟配額
利用指令針對特定使用者 (例如 84) 在根目錄 (/) 設置 8MB 的硬體空間最高上傳限制 。 
# 針對使用者 84 設置 8MB 上傳硬限制
xfs_quota -x -c "limit -u bhard=8M 84" /
步驟 2：建立測試用假檔案
在用戶端利用 dd 指令，將 /dev/zero 作為來源，產生指定大小 (例如 6MB) 的測試檔案，並複製備用以進行突破上限的測試 。 
# 建立名稱為 6M，大小剛好為 6MB 的檔案
dd if=/dev/zero of=6M bs=1M count=6

# 複製一份命名為 6M2
cp 6M 6M2
步驟 3：批次上傳測試 (驗證配額)
登入 FTP 並使用 mput * 一次性上傳。第一個 6MB 會成功，但第二個檔案上傳到 2MB (總和達到 8MB 上限) 時，便會被伺服器阻斷 。 
# 在 FTP 連線中批次上傳當前目錄下的檔案
ftp> mput *

# 第二個檔案將會因為配額已滿而上傳失敗，證實 8MB 配額生效
