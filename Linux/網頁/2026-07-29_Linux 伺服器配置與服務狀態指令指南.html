主題一：Alias 別名指令與 Shell 環境設定

動作目的： 掌握 Linux 終端機別名（Alias）設定技巧，學習建立暫時與永久指令別名，並透過修改使用者家目錄下的 .bashrc 隱藏檔，確保使用者重新登入後別名設定依然自動生效。
步驟1：新增使用者與切換環境
使用 useradd 建立測試帳號，並透過 su - 切換身分。務必加上減號 -，系統才會載入該帳號專屬的家目錄與環境變數。 
# 新增測試使用者帳號 101
useradd 101

# 切換至使用者 101 (加上 - 以同時切換至家目錄並套用個人環境)
su - 101
步驟2：設定暫時性 Alias 並測試執行
直接在命令列執行 alias [別名]='[指令]' 即可建立別名。當前工作階段可直接呼叫，但此別名會在帳號登出後消失。 
# 查看當前使用者設定的所有 Alias 清單
alias

# 新增暫時性別名 z (輸出自訂字串)
alias z='echo n99-101'

# 測試執行別名指令 z
z
步驟3：修改 .bashrc 檔寫入永久 Alias
使用文字編輯器修改家目錄下的 ~/.bashrc，將別名規則加入其中。登出帳號後重新登入，驗證別名是否成功自動載入。 
# 編輯個人家目錄下的 .bashrc 檔案
vi ~/.bashrc

# 於檔案開頭加入別名定義：
# alias z='echo n99-101'

# 登出當前帳號
exit

# 重新登入使用者並檢視 Alias 是否保留
su - 101
alias

主題二：Firewalld 防火牆服務與通訊埠管理

動作目的： 學習使用 firewall-cmd 工具開放與移除特定的網路服務（HTTP、HTTPS、DNS、FTP）及 TCP/UDP 通訊埠，並掌握 --permanent 永久寫入與 --reload 設定強制生效。
步驟1：開啟與檢視預設網路服務
使用 --add-service 將特定服務名稱加入防火牆放行清單，並透過指令歷史過濾開通紀錄。 
# 放行常用網路服務 (HTTP, HTTPS, DNS, FTP)
firewall-cmd --add-service=http
firewall-cmd --add-service=https
firewall-cmd --add-service=dns
firewall-cmd --add-service=ftp

# 使用 history 與 grep 過濾歷史紀錄
history | grep add-service
步驟2：新增 TCP 與 UDP 通訊埠規則
利用 --add-port=[埠號]/[協定] 分別針對 TCP 及 UDP 埠進行開放（如 50099 與 51099）。 
# 放行自訂 TCP 通訊埠
firewall-cmd --add-port=50099/tcp
firewall-cmd --add-port=51099/tcp

# 放行自訂 UDP 通訊埠
firewall-cmd --add-port=50099/udp
firewall-cmd --add-port=51099/udp

# 查看歷史紀錄
history | grep add-port
步驟3：永久生效設定與強制重新載入
加上 --permanent 可將規則永久寫入設定檔，但當下不會立即生效，必須執行 firewall-cmd --reload 重新載入設定。 
# 新增永久性防火牆服務規則
firewall-cmd --add-service=http --permanent
firewall-cmd --add-service=https --permanent
firewall-cmd --add-service=dns --permanent
firewall-cmd --add-service=ftp --permanent

# 強制重新載入防火牆組態檔以套用永久規則
firewall-cmd --reload

# 查看當前啟用的所有防火牆規則狀態
firewall-cmd --list-all
步驟4：移除規則與進階過濾查詢
使用 --remove-port 移除通訊埠，並善用 grep -- --permanent 搜尋帶有雙減號參數的歷史紀錄。 
# 移除已開啟的 TCP 通訊埠
firewall-cmd --remove-port=50099/tcp

# 搜尋包含 --permanent 關鍵字的歷史紀錄
history | grep -- --permanent

主題三：Systemd 服務狀態管理與自動啟動

動作目的： 掌握 systemctl 控制指令，學會查詢服務狀態（status）、設定開機自動啟動（enable），以及利用 --now 參數同步進行立即啟動與開機預設開啟。
步驟1：檢視服務當前執行狀態
使用 systemctl status [服務名稱] 檢查 Apache (httpd)、FTP (vsftpd) 或 DNS (named) 的即時運作狀態。 
# 檢查 Apache Web 伺服器運作狀態
systemctl status httpd
步驟2：設定開機自動啟動並立即啟用服務
單純 enable 僅作用於下一次開機；加上 --now 參數可以同時達到「立即啟動服務」與「開機自動啟動」效果。 
# 一鍵啟用 HTTPD、VSFTPD、NAMED 服務並設定開機自啟
systemctl enable --now httpd
systemctl enable --now vsftpd
systemctl enable --now named

# 驗證歷史紀錄中的 enable --now 執行指令
history | grep enable | grep -- --now

主題四：BIND DNS 主從 (Master/Slave) 伺服器建置與備援

動作目的： 學習建置 BIND DNS 伺服器，設定 Master (Primary) 與 Slave 伺服器的區域轉移（Zone Transfer），自動同步區域解析檔，並驗證當主 DNS 故障關閉時 Slave 伺服器的無縫解析備援能力。
步驟1：安裝 BIND 與基礎全域監聽設定
使用 dnf install bind 安裝套件，並修改 /etc/named.conf 將監聽介面與查詢權限開放為 any;。 
# 安裝 BIND 服務套件
dnf install -y bind

# 修改 /etc/named.conf 主要設定檔 (設定全域監聽與允許查詢)：
# listen-on port 53 { any; };
# allow-query     { any; };

# 啟動並設定開機自啟 DNS 服務
systemctl enable --now named
步驟2：設定 Master 主 DNS 伺服器區域
在 Master 主機 (192.168.x.101) 的 /etc/named.rfc1912.zones 定義區域，加入 allow-transfer 與 also-notify 允許 Slave (102) 同步資料。 
# 編輯 Master 端 (192.168.x.101) 的 /etc/named.rfc1912.zones：
# zone "n99-101.gov.tw" IN {
#     type primary;
#     file "named.101";
#     allow-transfer { 192.168.x.102; };
#     also-notify { 192.168.x.102; };
# };

# 在 /var/named/ 建立檔案 named.101 並設定正向紀錄，完成後重啟服務
systemctl restart named
步驟3：設定 Slave 副 DNS 伺服器同步區域
在 Slave 主機 (192.168.x.102) 設定 type slave; 並指向 Master IP，指定同步檔存於 slaves/ 目錄。 
# 編輯 Slave 端 (192.168.x.102) 的 /etc/named.rfc1912.zones：
# zone "n99-101.gov.tw" IN {
#     type slave;
#     file "slaves/named.101";
#     masters { 192.168.x.101; };
# };

# 重啟 Slave 端 named 服務觸發同步
systemctl restart named

# 確認 /var/named/slaves/ 目錄下自動生成同步區域資料檔
ls -l /var/named/slaves/
步驟4：解析測試與 Master 故障容錯驗證
修改 /etc/resolv.conf 將 DNS 指向 Slave IP (102)，使用 dig 驗證解析。關閉 Master 服務後測試 Slave 依然可獨立正常運作。 
# 修改 /etc/resolv.conf 將 DNS 指向 Slave 伺服器 IP (192.168.x.102)
# nameserver 192.168.x.102

# 測試網域解析
dig w.n99-101.gov.tw

# 在 Master 主機關閉服務模擬故障
systemctl stop named

# 再次於用戶端查詢，確認 Slave 能無縫完成網域解析
dig w.n99-101.gov.tw
