主題一：基礎網路與系統操作

動作目的

在管理 Linux 伺服器前，必須確保網路連線正常且熟悉基本的指令與終端機快捷鍵。本主題將實作手動設定伺服器 IPv4 位址、透過 ping 測試網路連通性，並使用常用快捷鍵快速切換帳號與建立檔案。

執行步驟與指令範例

步驟 1：檢視並確認 IP 位址
手動設定網路後，於終端機輸入 ip a 指令（ip address 的縮寫），確認系統的 IPv4 網路設定與子網路遮罩是否生效。 
# 檢視系統上所有網卡與 IP 位址狀態
ip a

# 若看到 "inet 192.168.x.31/24" 即代表設定成功
步驟 2：測試網路連通性 (ping)
使用 ping 指令發送 ICMP 封包至目標機器（例如 192.168.x.31），若有回應表示網路暢通。測試完畢後需使用 Ctrl + C 來中斷連線指令。 
# 從用戶端測試與伺服器 (假設為 31) 的網路是否暢通
ping 192.168.x.31

# 出現 64 bytes from 192.168.x.31... 後，按 Ctrl+C 中止
步驟 3：善用快捷鍵與基礎帳號操作
建立帳號並切換身分，在終端機中可按下 ESC 鬆開後再按 .（句點），此快捷鍵可自動將「前一個指令的最末端參數」複製並貼上，大幅提升指令輸入效率。 
# 1. 建立使用者帳號並設定密碼
useradd n199-31
passwd n199-31

# 2. 連帶家目錄環境一起切換身分 (su -)
su - n199-31

# 3. 建立檔案 (touch) 與清空終端機畫面 (Ctrl + L)
touch f199-31
# (按下 Ctrl+L 清潔終端機版面)

主題二：檔案與目錄權限 (RWX)

動作目的

Linux 將權限分為擁有者 (u)、群組 (g)、其他使用者 (o) 三種身分。本主題在於理解並操作讀取 (r)、寫入 (w)、執行 (x) 在「檔案」與「目錄」上所代表的不同意義，並透過 chmod 指令靈活地調整這些權限。

執行步驟與指令範例

步驟 1：檢視目錄與檔案權限
使用 ls -l（或 alias ll）可列出檔案的詳細權限。字首為「-」代表檔案，「d」代表目錄（資料夾）。接下來的 9 個字元分別為 u、g、o 三個身分的 rwx 權限。 
# 列出目前目錄下所有內容的權限細節
ls -l

# 您也可以使用簡寫別名來檢視
ll
步驟 2：利用加減符號修改特定權限
使用 chmod 搭配 u（擁有者）、g（群組）或 o（其他使用者）與加號 +、減號 - 來單獨增刪某項權限。例如移除擁有者對檔案的讀取 (r) 權限。 
# 移除擁有者 (u) 對特定檔案的讀取 (r) 權限
chmod u-r f199-31

# 為擁有者 (u) 加上寫入 (w) 權限
chmod u+w f199-31
步驟 3：使用等號進行權限的絕對設定
有時為了快速設定所有身分的權限，可使用等號 = 強制賦予特定權限組合。不管原本權限為何，都會直接被覆蓋成等號後方的設定。使用逗號 , 可同時為 u,g,o 派發不同權限。 
# 直接將擁有者設為 rwx，群組設為 rx，其他人設為 x
chmod u=rwx,g=rx,o=x d199-32

# 將所有人 (All = a = ugo) 的權限一次改為 r (只讀)
chmod a=r f199-32

主題三：系統特殊權限設定 (SUID, SGID, Sticky Bit)

動作目的

在基礎的 RWX 之外，Linux 提供了 SUID (4)、SGID (2) 與 Sticky Bit (1) 特殊權限。透過設定這些進階權限，能讓一般使用者暫時取得 Root 或群組權限以執行特定程式，或者保護共用暫存目錄下的檔案不被其他人刪除。

執行步驟與指令範例

步驟 1：設定 SUID (暫時擁有擁有者權限)
SUID 位元作用於擁有者 (u) 的 x 權限上。當賦予可執行檔 SUID 時，任何使用者在執行該檔案期間，都會「暫時取得」檔案擁有者的權限（例如一般人暫用 root 權限修改密碼檔）。 
# 幫檔案擁有者的 x 權限位置加上 SUID 特殊權限 (s)
chmod u+s f199-33

# 檢視時，擁有者的 x 將變成小寫 s (若原本無 x 則顯示大寫 S)
ls -l f199-33
步驟 2：設定 SGID (暫時擁有群組權限)
SGID 位元作用於群組 (g) 的 x 權限上。常用於如 `locate` 查檔指令，讓執行者能暫時以該指令群組身分讀取被限制存取的系統資料庫。 
# 幫檔案群組的 x 權限位置加上 SGID 特殊權限 (s)
chmod g+s f199-33

# 修改成功後，群組的 x 會呈現 s 或 S
步驟 3：設定 Sticky Bit (防刪除位元)
Sticky Bit 作用於其他使用者 (o) 的 x 權限上。常用於如 /tmp 這類共用目錄，加上後雖所有人皆可新增檔案，但「僅有檔案原創作者與 root」才有權限刪除或修改它。 
# 幫共用目錄加上 Sticky Bit 特殊防護權限 (t)
chmod o+t d199-33

# 也可以用等號一次同時設定 SUID、SGID 與 Sticky Bit
chmod u=rwxs,g=rx,o=rwt d199-33

主題四：群組管理與存取控制清單 (ACL)

動作目的

在實際的專案運作中，經常需要將特定人員歸納為專案群組以統一管理讀寫權限。然而，若遇到跨部門的高階主管需要唯讀權限，為不變更既有群組結構，必須運用 ACL (Access Control List) 為特定對象開啟「特例」存取通道。

執行步驟與指令範例

步驟 1：建立群組與指派檔案所屬群組
利用 groupadd 建立新群組，並使用 usermod -G 將使用者加入該群組。隨後，具有 root 權限的管理者可透過 chown 將檔案轉交給該群組管理。 
# 1. 建立專案群組
groupadd G_Project32

# 2. 將帳號 31 附加加入至該群組中
usermod -G G_Project32 n199-31

# 3. 變更檔案的所屬群組為 G_Project32 (冒號後接群組名稱)
chown :G_Project32 f1
步驟 2：檢視檔案的 ACL 設定
使用 getfacl 可以詳細檢視該檔案目前的完整權限清單，這比單純看 ls -l 能取得更多特例使用者 (ACL) 的資訊。 
# 檢視檔案目前的權限清單 (包含隱藏的特例設定)
getfacl f1

# 結果將詳細列出 owner, group, other 的具體讀寫執行權限
步驟 3：透過 setfacl 開放特例權限
若要讓未納入專案群組的高層 (例如帳號 34) 取得讀取權，可使用 setfacl -m 修改清單，針對指定對象 (u:帳號:權限) 賦予特例，此時使用 ls -l 檢視該檔案，其權限末端會多出一個 + 號。 
# 設定 (modify) 使用者 n199-34 具有對 f1 的讀取 (r) 特例權限
setfacl -m u:n199-34:r f1

# 設定後再使用 ls -l 查看，權限最右側會出現 "+" 號
ls -l f1

主題五：Root 密碼重置救援 (單人模式)

動作目的

這是一項網管必備的「起手式」技能：當系統管理者遺失或遭惡意竄改 root 密碼時，只要具備實體操作機器的權限，即可在開機階段攔截進入 GRUB 選單，切換至單人模式 (Single User Mode) 強制重設密碼並重新奪回系統控制權。

執行步驟與指令範例

步驟 1：攔截開機並修改核心參數
伺服器重新啟動時按下 ESC 暫停開機程序。選取救援項目按下 e 進入編輯模式，尋找 linux 開頭的那行，於行尾加入特定的 bash 初始化參數。 
# 1. 於開機選單按下 e 進入編輯
# 2. 尋找 linux 開頭行，按 End 鍵跳至尾端，並加上：
init=/bin/bash

# 3. 按下 Ctrl + X 啟動，系統將跳過密碼檢查進入單人模式終端機
步驟 2：重新掛載根目錄為可寫入模式
預設進入單人模式時，系統根目錄 (/) 是唯讀狀態。我們必須利用 mount 指令，將根目錄重新掛載 (remount) 為可讀寫 (rw)，才能將新密碼順利寫回設定檔中。 
# 重新將根目錄掛載為 Read/Write 模式
mount -o remount,rw /

# 輸入 passwd 直接變更 root 的密碼
passwd
步驟 3：建立 SELinux 標記檔並強制重啟
變更密碼後極度重要的一步，必須透過 touch 在根目錄下建立一個隱藏的重標記檔案。若遺漏此步驟，SELinux 機制會阻斷密碼更新。最後再呼叫絕對路徑指令強制重啟即可。 
# 在根目錄建立引發 SELinux 重標籤的隱藏檔 (檔名絕不可打錯)
touch /.autorelabel

# 執行完畢後，強制重新開機 (系統在開機途中會自動執行 relabel 程序)
/sbin/reboot -f
