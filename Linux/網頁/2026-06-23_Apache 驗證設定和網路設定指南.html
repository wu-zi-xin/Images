主題一：Apache 網頁伺服器帳號密碼保護

動作目的

確保特定網站資料夾（如 P2）的機密性，當使用者透過瀏覽器存取該網頁時，伺服器會強制要求輸入帳號密碼，阻止未經授權的連線請求[cite: 1]。

執行步驟與指令範例

步驟 1：修改 Apache 核心設定檔
使用編輯器進入 /etc/httpd/conf/httpd.conf，透過 <Directory> 標籤指定要保護的資料夾，並將 AllowOverride None 修改為 AllowOverride AuthConfig[cite: 1]，以此啟用帳號認證條件。
編輯 httpd 設定檔
vim /etc/httpd/conf/httpd.conf
新增或修改資料夾保護區塊
<Directory "/var/www/html/P2">
    AllowOverride AuthConfig
</Directory>
步驟 2：在指定資料夾建立 .htaccess 隱藏檔
切換至要保護的資料夾中[cite: 1]，建立名稱為 .htaccess 的控制檔。需撰寫四行基本認證設定：設定彈出視窗文字 (AuthName)、基礎認證類型 (AuthType Basic)、密碼檔位置 (AuthUserFile) 與要求有效用戶 (Require valid-user)[cite: 1]。
切換到保護資料夾並建立檔案
cd /var/www/html/P2
vim .htaccess
在 .htaccess 內輸入以下四行
AuthName "Protected Area"
AuthType Basic
AuthUserFile /var/www/html/P2/htpasswd
Require valid-user
步驟 3：建立密碼檔與專用帳號
因為是第一次建立密碼檔，使用 htpasswd 建立網頁專屬認證密碼。務必加上 -c (create) 參數來新建檔案。此帳號僅供存取網頁使用，非系統登入帳號[cite: 1]。
新建密碼檔，並為使用者 (如 51) 建立密碼
htpasswd -c /var/www/html/P2/htpasswd 51
💡 執行後依照提示連續輸入兩次密碼（New password / Re-type new password）。
步驟 4：重新啟動服務與測試
設定檔修改完畢後，必須重新啟動 Apache (httpd) 服務才會套用[cite: 1]。用戶端測試時，需確認防火牆已開 80 port，且若瀏覽器留有快取，需先清除歷史紀錄再重整，方會跳出密碼輸入框[cite: 1]。
重新啟動 httpd 服務以套用設定
systemctl restart httpd
💡 若用戶端先前成功連線過，請至瀏覽器清除歷史紀錄，再重新輸入網址：http://192.168.x.51/P2

主題二：使用兩個 IP 架設兩個網站 (IP-based)

動作目的

利用單一伺服器主機，透過網路設定新增多個 IP 位址 (例如 .51 與 .53)，並在 Apache 內為不同的 IP 配置獨立的虛擬主機 (VirtualHost)，讓它們分別對應到不同的網站目錄以提供服務[cite: 1]。

執行步驟與指令範例

步驟 1：網卡新增第二個 IP 位址
透過伺服器的網路設定工具，除了原有的 IP (.51)，再新增加一組不相衝的 IP (.53)[cite: 1]。設定完成後重啟網卡使新 IP 生效[cite: 1]。
檢視網路卡 IP 狀態
ip addr show
💡 透過圖形介面或設定將網路卡新增 IP 192.168.x.53/24，關閉網卡再開啟套用後，應該要能看見同一張網卡同時具備 .51 與 .53 兩個 IP。
步驟 2：設定虛擬主機對應目錄
修改 /etc/httpd/conf/httpd.conf，於檔案最尾端加入兩個 <VirtualHost> 區塊，分別將不同的 IP 導向獨立的 DocumentRoot 資料夾 (如 W51 與 W53)[cite: 1]。
在設定檔最末端加上虛擬主機設定
<VirtualHost 192.168.x.51:80>
    DocumentRoot /var/www/html/W51
</VirtualHost>

<VirtualHost 192.168.x.53:80>
    DocumentRoot /var/www/html/W53
</VirtualHost>
步驟 3：建立目錄、首頁與重啟服務
建立剛剛在設定檔指定的資料夾，放入不同的首頁檔案 (index.html) 供辨識，接著重新啟動服務，用戶端即可分別透過 .51 與 .53 存取不同網頁[cite: 1]。
建立目錄並寫入測試首頁
mkdir /var/www/html/W51 /var/www/html/W53
echo "This is site .51" > /var/www/html/W51/index.html
echo "This is site .53" > /var/www/html/W53/index.html
重新啟動服務
systemctl restart httpd

主題三：BIND DNS 伺服器安裝與基礎設定

動作目的

由於 IP 位址純數字難以記憶，透過架設由柏克萊大學開發的 BIND (named) DNS 系統，協助將具有階層性的人類可讀網址（正向解析）轉換成電腦連線所需的 IP 位址[cite: 1]。

執行步驟與指令範例

步驟 1：聯網安裝 bind 套件並啟動
伺服器需先變更為 NAT 模式連上外部網路，使用 dnf 安裝 bind[cite: 1]。安裝完成後，啟動名為 named 的守護行程[cite: 1]。
安裝 bind 系統套件
dnf install bind -y
安裝完成後啟動 named 服務
systemctl start named
步驟 2：修改全域監聽與查詢權限
基於安全考量，DNS 預設僅監聽 127.0.0.1 且僅允許本機查詢[cite: 1]。須編輯 /etc/named.conf，將 listen-on 及 allow-query 皆改為 any; 才能接受外部用戶端存取[cite: 1]。
編輯 DNS 主設定檔
vim /etc/named.conf
修改監聽與查詢權限 (保留分號)
listen-on port 53 { any; };
allow-query       { any; };
步驟 3：宣告自訂網域 (Zone)
編輯 /etc/named.rfc1912.zones，複製既有區塊，自訂需要管理的網域名稱 (例如 centos.vbird) 以及負責該網域的對應檔案名稱[cite: 1]。
編輯 zone 定義檔
vim /etc/named.rfc1912.zones
新增自訂網域區塊
zone "centos.vbird" IN {
        type master;
        file "named.centos.vbird";
        allow-update { none; };
};
步驟 4：建立網域對應檔並測試
至 /var/named/ 下建立對應檔，將內部主機名稱對應至伺服器 IP (.51)[cite: 1]。重啟 named，防護牆開放 DNS，用戶端將 DNS 指向 .51 後，利用 dig 驗證解析結果[cite: 1]。
準備好 zone 檔案內容並修改 IP 後重啟 named
systemctl restart named
放行伺服器端防火牆 dns 服務
firewall-cmd --add-service=dns
用戶端執行 DNS 解析測試指令
dig www.centos.vbird

主題四：使用一個 IP 架設兩個網站 (Name-based)

動作目的

在主機 IP 資源有限的情況下，透過 DNS 伺服器將兩組不同的網址（如 www1 與 www2）指向同一個 IP[cite: 1]。接著設定 Apache 的 ServerName 來辨識連線來源網址[cite: 1]，從而提供各自專屬的網頁內容[cite: 1]。

執行步驟與指令範例

步驟 1：DNS 新增多組主機紀錄
編輯網域的 zone 檔案，新增多筆主機 (A紀錄)，例如 www1 與 www2，將兩者的 IP 都設定為同一部伺服器 (.51)[cite: 1]。改完記得重啟 DNS[cite: 1]。
在自訂網域檔內加入兩筆 A 紀錄 (IP 皆為同一部)
www1    IN  A       192.168.x.51
www2    IN  A       192.168.x.51
儲存後重啟 named 服務
systemctl restart named
步驟 2：設定基於網址名稱的虛擬主機
開啟 /etc/httpd/conf/httpd.conf，複製兩套同一個 IP 的 <VirtualHost> 區塊，並加入 ServerName 參數區分使用者輸入的完整網址，導引至不同網頁根目錄[cite: 1]。
編輯 httpd 設定檔加入基於名稱的虛擬主機
<VirtualHost 192.168.x.51:80>
    ServerName www1.xxx.gov.tw
    DocumentRoot /var/www/html/W51-1
</VirtualHost>

<VirtualHost 192.168.x.51:80>
    ServerName www2.xxx.gov.tw
    DocumentRoot /var/www/html/W51-2
</VirtualHost>
步驟 3：建立資料夾並驗證結果
建立對應的兩個網頁資料夾，重啟 HTTP 服務[cite: 1]。此時在用戶端瀏覽器分別輸入 www1 網址與 www2 網址，即使都是連到同一個伺服器 IP，也能看到兩份完全不同的網頁[cite: 1]。
重新啟動 httpd 服務
systemctl restart httpd
💡 在瀏覽器中分別訪問網址進行測試：
- http://www1.xxx.gov.tw
- http://www2.xxx.gov.tw
