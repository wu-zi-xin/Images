主題：TCP/IP 網路模型 (多選題)
176. TCP/IP 模型包含下列哪些層？（多選題）
①應用層（Application）
②交談層（Session）
③傳輸層（Transport）
④網際網路層（Internet）
💡 點擊展開解答與解析
✅ 正確答案：①、③、④ (多選題)
【綜合解析】

與 OSI 的七層模型不同，TCP/IP 參考模型被簡化為四個階層，由上而下分別為：
1. 應用層 (Application Layer)：對應 OSI 的應用、表現、交談層。
2. 傳輸層 (Transport Layer)：對應 OSI 的傳輸層。
3. 網際網路層 (Internet Layer)：對應 OSI 的網路層。
4. 網路存取層 (Network Access Layer)：對應 OSI 的資料鏈結與實體層。

【各選項解析】
  • ①應用層 (Application)：正確，為 TCP/IP 模型的最高層。
  • ②交談層 (Session)：錯誤，這是 OSI 七層模型獨有的階層，在 TCP/IP 中已被合併至應用層。
  • ③傳輸層 (Transport)：正確，負責端對端連線控制 (TCP/UDP)。
  • ④網際網路層 (Internet)：正確，負責定址與路由 (IP)。
主題：ICMP 協定 (多選題)
177. 關於 ICMP 封包，下列哪些正確？（多選題）
①ICMP 確認已收到 TCP 區段（Segment）
②ICMP 保證資料包（Datagram）送達
③ICMP 可提供主機有關網路問題相關資訊
④ICMP 被囊封在 IP 資料包（Datagram）中
💡 點擊展開解答與解析
✅ 正確答案：③、④ (多選題)
【綜合解析】

ICMP（網際網路控制訊息協定）主要運作在網路層，其功用是「回報網路傳輸過程中的錯誤與探測網路狀態（如 Ping 指令）」。它並不負責保證封包的可靠傳送，也沒有與 TCP 進行交握確認的功能。在結構上，ICMP 的訊息是封裝在「IP 封包（IP Datagram）」的資料欄位中進行傳輸的。

【各選項解析】
  • ①ICMP 確認已收到 TCP 區段：錯誤，這是 TCP 協定中 ACK 訊息負責的工作。
  • ②ICMP 保證資料包送達：錯誤，ICMP 只負責「報錯」，不提供可靠性保證機制。
  • ③可提供主機有關網路問題相關資訊：正確，如「目的地不可達 (Destination Unreachable)」。
  • ④被囊封在 IP 資料包中：正確，ICMP 是 IP 協定的附屬協定，依賴 IP 進行封裝傳輸。
主題：傳輸層 TCP 協定應用 (多選題)
178. 下列哪些服務預設採用 TCP 協定？（多選題）
①DHCP
②SMTP
③SNMP
④FTP
💡 點擊展開解答與解析
✅ 正確答案：②、④ (多選題)
【綜合解析】

TCP（傳輸控制協定）是一種要求高可靠度、連線導向的傳輸協定，會確保資料完整無誤地到達。需要精準傳輸的服務如：檔案傳輸（FTP, Port 20/21）、電子郵件寄送（SMTP, Port 25）、網頁瀏覽（HTTP/HTTPS）等，都會採用 TCP。

【各選項解析】
  • ①DHCP：採用 UDP（Port 67/68），因為客戶端剛開機還沒有 IP，只能用廣播/UDP快速通訊。
  • ②SMTP：正確，寄信不能掉字，採用高可靠的 TCP。
  • ③SNMP：簡單網路管理協定，為了減少網路設備負擔，採用快速的 UDP（Port 161/162）。
  • ④FTP：正確，檔案傳輸絕不能有漏失，採用 TCP。
主題：傳輸層 UDP 協定應用 (多選題)
179. 下列哪些服務預設採用 UDP 協定？（多選題）
①DHCP
②SMTP
③TFTP
④HTTP
💡 點擊展開解答與解析
✅ 正確答案：①、③ (多選題)
【綜合解析】

UDP（使用者資料包協定）是一種非連線導向、輕量快速但「不保證送達」的協定。通常用於需要即時性（如影音串流）、廣播探索（如 DHCP）、或是極小檔案與低運算需求的環境（如 TFTP 微型檔案傳輸）。

【各選項解析】
  • ①DHCP：正確，使用 UDP 進行快速 IP 探索與配發。
  • ②SMTP：需要可靠傳輸，使用 TCP。
  • ③TFTP：正確，Trivial FTP（簡易檔案傳輸協定）為減輕負擔而採用 UDP（Port 69）。
  • ④HTTP：網頁傳輸需要可靠性，主流（HTTP 1.1/2）採用 TCP。
主題：OSI 應用層服務 (多選題)
180. 下列哪些為應用層（Application Layer）服務？（多選題）
①IP
②TCP
③Telnet
④FTP
💡 點擊展開解答與解析
✅ 正確答案：③、④ (多選題)
【綜合解析】

在 OSI 七層模型中，「應用層」是直接與使用者軟體（或背景服務）互動的最高層級。舉凡我們日常操作的網頁（HTTP）、遠端登入（Telnet）、檔案傳輸（FTP）、電子郵件（SMTP/POP3）都屬於這一層的範疇。

【各選項解析】
  • ①IP：網際網路協定，屬於第三層「網路層」。
  • ②TCP：傳輸控制協定，屬於第四層「傳輸層」。
  • ③Telnet：正確，遠端文字介面登入服務，為應用層協定。
  • ④FTP：正確，檔案傳輸協定，為應用層協定。
主題：流量控制機制 (多選題)
181. 下列哪些是流量控制機制？（多選題）
①緩衝（Buffering）
②直通（Cut Through）
③訊窗（Windowing）
④壅塞避免（Congestion Avoidance）
💡 點擊展開解答與解析
✅ 正確答案：①、③、④ (多選題)
【綜合解析】

「流量控制（Flow Control）」是網路傳輸（特別是 TCP 協定中）為了避免發送端傳送速度過快，導致接收端或中間路由器來不及處理而引發掉包的一系列調節技術。緩衝記憶體、滑動訊窗大小動態調整、以及壅塞避免演算法皆屬此類。

【各選項解析】
  • ①緩衝（Buffering）：正確，利用記憶體暫存來不及處理的封包。
  • ②直通（Cut Through）：錯誤，這是 Switch 交換器的一種「快速轉送模式 (不檢查完整封包)」，與調節流量無關。
  • ③訊窗（Windowing）：正確，透過 Sliding Window 協商發送數量。
  • ④壅塞避免（Congestion Avoidance）：正確，主動偵測網路擁擠並降速的演算法。
主題：OSI 參考模型優勢 (多選題)
182. 下列哪些是資通訊產業採用 OSI 參考模型之原因？（多選題）
①將網路通訊過程 (Process)分成可獨立發展、設計及除錯之小元件
②使不同廠商使用相同的元件，節省研發費用
③支持多個相互競爭標準的演進，為設備製造商提供商機
④定義此模型中各層應具備的功能，促進產業標準化
💡 點擊展開解答與解析
✅ 正確答案：①、④ (多選題)
【綜合解析】

ISO 制定的 OSI（開放式系統互聯）七層參考模型，最大的貢獻就是「標準化」與「模組化」。它把極度複雜的網路傳輸過程，精確切割成 7 個責任分明的階層。這樣一來，開發軟體的人只要專注高層、做網卡的人專注底層，出了問題也容易分層除錯；同時有了共通標準，不同品牌的設備才能順利串接互通。

【各選項解析】
  • ①分成可獨立發展及除錯之小元件：正確，這就是「模組化/分層化」的最大好處。
  • ②使不同廠商使用相同的元件：錯誤，模型是統一「通訊標準(語言)」，而非要求大家使用一模一樣的實體電子元件。
  • ③支持多個相互競爭標準的演進：錯誤，OSI 的初衷是「統一標準」而非助長混亂的競爭標準。
  • ④定義各層功能，促進產業標準化：正確，確保了跨品牌設備的互通性。
主題：電子郵件通訊協定 (多選題)
183. 下列哪些是 E-mail 所採用的通訊協定？（多選題）
①POP3
②IMAP4
③SNMP
④Telnet
💡 點擊展開解答與解析
✅ 正確答案：①、② (多選題)
【綜合解析】

完整的 E-mail 系統主要仰賴三種通訊協定來運作：
1. SMTP：負責「寄出」信件與伺服器間的轉遞。
2. POP3：負責將信件從伺服器「下載」到使用者的電腦設備中（下載後通常會從伺服器刪除）。
3. IMAP4：較新的收信協定，允許使用者在伺服器上直接「同步」管理與閱讀信件。

【各選項解析】
  • ①POP3：正確，用以收取電子郵件（Post Office Protocol）。
  • ②IMAP4：正確，用以雙向同步收取與管理電子郵件。
  • ③SNMP：簡單網路管理協定，用來監控網路設備（如 Router 狀態），與郵件無關。
  • ④Telnet：遠端終端機登入協定，與郵件無關。
主題：網路設備與 OSI 層級 (多選題)
184. 電腦中的網路卡運作在 OSI 模型中的哪些層？（多選題）
①實體層
②網路層
③資料鏈結層
④傳輸層
💡 點擊展開解答與解析
✅ 正確答案：①、③ (多選題)
【綜合解析】

電腦的網路介面卡（NIC）具備雙重身分：
1. 它有連接網路線或天線的實體插槽與傳收發晶片，負責將 0 與 1 轉換為電氣或電磁訊號，因此運作於第 1 層（實體層）。
2. 出廠時網卡內燒錄了獨一無二的 MAC 位址，並且負責處理 Ethernet 乙太網路訊框（Frame）的組裝與拆解，因此也運作於第 2 層（資料鏈結層，MAC 子層）。

【各選項解析】
  • ①實體層：正確，包含電氣訊號轉換等實體傳輸機制。
  • ②網路層：由作業系統的 IP 協定負責，而非網卡硬體本身。
  • ③資料鏈結層：正確，網卡負責處理 MAC 位址與訊框存取控制。
  • ④傳輸層：由作業系統的 TCP/UDP 協定負責處理。
主題：IPv4 子網路區間計算 (多選題)
185. 下列哪些屬於 130.110.8.0/22 的網段 IP 位址？（多選題）
①130.110.9.0
②130.110.10.0
③130.110.11.0
④130.110.12.0
💡 點擊展開解答與解析
✅ 正確答案：①、②、③ (多選題)
【綜合解析與計算】

1. 遮罩 `/22` 代表前 22 個位元為網路段。第三個位元組占了 6 個（22-16=6）。
2. 該位元組的區塊大小（Block Size）計算：256 - 252 (即 /22 對應的 11111100) = 4。
3. 網段切分點為 4 的倍數：0, 4, 8, 12, 16...
4. 本題網段為 130.110.8.0，其有效範圍一路涵蓋到下一個切分點之前。
5. 完整的子網路區間為：130.110.8.0 ～ 130.110.11.255。
因此，第三個數字只要落在 8、9、10、11 的 IP，都屬於同一個大網段！

【各選項解析】
  • ①130.110.9.0：第三碼為 9，落在 8~11 之間，正確。
  • ②130.110.10.0：第三碼為 10，落在 8~11 之間，正確。
  • ③130.110.11.0：第三碼為 11，落在 8~11 之間，正確。
  • ④130.110.12.0：第三碼為 12，這已經是「下一個」子網路的起點，不屬於此網段。
主題：IPv4 Class 分類 (多選題)
186. 下列哪些不屬於 Class C 的網路位址？（多選題）
①15.25.35.45
②150.25.35.45
③250.25.35.45
④200.25.35.45
💡 點擊展開解答與解析
✅ 正確答案：①、②、③ (多選題)
【綜合解析】

IPv4 的傳統 Class 分類是依據第一個位元組（First Octet）的數字範圍來判定的：
- Class A：1 ～ 126
- Class B：128 ～ 191
- Class C：192 ～ 223
- Class D (多播)：224 ～ 239
- Class E (實驗)：240 ～ 255
題目詢問「不屬於」Class C 的選項，因此只要第一個數字不在 192~223 範圍內的都是答案。

【各選項解析】
  • ①15.25.35.45：開頭為 15，屬於 Class A，不屬於 Class C（符合題意）。
  • ②150.25.35.45：開頭為 150，屬於 Class B，不屬於 Class C（符合題意）。
  • ③250.25.35.45：開頭為 250，屬於 Class E，不屬於 Class C（符合題意）。
  • ④200.25.35.45：開頭為 200，它剛好落在 192~223 的 Class C 範圍內，因此不選。
主題：RIPv2 路由協定特性 (多選題)
187. 關於 RIPv2，下列哪些正確？（多選題）
①RIPv2 送出多播(Multicast)更新到 224.0.0.7
②RIPv2 是 Distance Vector 協定並使用 Hop Count 作為計量
③RIPv2 提供明文以及 MD5 兩種身分驗證模式
④RIPv2 預設的 Hold Down Timer 是 240 秒
💡 點擊展開解答與解析
✅ 正確答案：②、③ (多選題)
【綜合解析】

RIPv2（路由資訊協定第2版）改良自第一代，支援了無級別路由（VLSM）與安全性驗證。它依舊屬於「距離向量 (Distance Vector)」家族，並以經過的路由器數量「躍點數 (Hop Count)」作為選擇最短路徑的唯一指標。為增強安全，它允許相鄰路由器交換資訊時加入明文或 MD5 雜湊的身分驗證。

【各選項解析】
  • ①送出多播更新到 224.0.0.7：錯誤，RIPv2 使用的多播位址為 224.0.0.9。
  • ②Distance Vector 並使用 Hop Count：正確，這是 RIP 系列最核心的演算法特性。
  • ③提供明文及 MD5 身分驗證：正確，提升了交換路由資訊的安全性。
  • ④預設 Hold Down Timer 是 240 秒：錯誤，RIP 的預設 Hold Down Timer 為 180 秒（Flush/Garbage collection 才是 240 秒）。
主題：PPP 身分驗證機制 (多選題)
188. 關於 PPP 驗證協定，下列哪些正確？（多選題）
①當 WAN 連接使用 CHAP(Challenge Handshake Authentication Protocol)時，不會加密使用者名稱以及密碼
②當 WAN 連接採用 PAP(Password Authentication Protocol)時，會加密使用者名稱及密碼
③當 WAN 連接採用 CHAP(Challenge Handshake Authentication Protocol)時，會加密使用者名稱以及密碼
④當 WAN 連接採用 PAP(Password Authentication Protocol)時，不會加密使用者名稱及密碼
💡 點擊展開解答與解析
✅ 正確答案：③、④ (多選題)
【綜合解析】

點對點協定（PPP）提供了兩種身分驗證方法：
1. PAP（密碼驗證協定）：採用「明文（Cleartext）」傳輸，完全不加密密碼，非常容易遭到網路竊聽攔截。
2. CHAP（挑戰握手驗證協定）：採用雜湊（Hash）技術與挑戰隨機數來進行驗證，不會在網路上傳送真正的明文密碼，安全性高。

【各選項解析】
  • ①CHAP 不會加密：錯誤，CHAP 會利用雜湊運算來保護密碼內容。
  • ②PAP 會加密：錯誤，PAP 是非常原始的明文傳輸協定。
  • ③CHAP 會加密使用者名稱及密碼：正確，採用挑戰應答機制保障安全。
  • ④PAP 不會加密使用者名稱及密碼：正確，PAP 確實是以明文傳輸。
主題：廣域網路協定 SLIP vs PPP (多選題)
189. 系統由 SLIP（Serial Line Interface Protocol）更新成 PPP（Point to Point Protocol）時，除可支援多種通訊協定外，還有哪些更新的原因？（多選題）
①PPP 可在傳輸層運作
②SLIP 不支援 TCP/IP
③PPP 更穩定
④PPP 包含錯誤檢查的功能
💡 點擊展開解答與解析
✅ 正確答案：③、④ (多選題)
【綜合解析】

早期的數據機撥接多使用 SLIP 協定，但它非常陽春，只能傳送 IP 封包，且「完全沒有錯誤檢查機制」。後來推出的 PPP（點對點協定）大幅改良了這些缺點，不僅支援 IP、IPX 等多種網路層協定，還加入了 FCS（訊框檢查序列）來進行傳輸錯誤偵測，並支援身分驗證，使得廣域連線變得更加穩定且安全。

【各選項解析】
  • ①PPP 可在傳輸層運作：錯誤，PPP 與 SLIP 都是運作在 OSI 第 2 層「資料鏈結層」。
  • ②SLIP 不支援 TCP/IP：錯誤，SLIP 恰好是為了傳輸 TCP/IP 而誕生的早期協定。
  • ③PPP 更穩定：正確，具備各種鏈路控制與協商機制。

這是一題非常基礎且重要的網路規格常識：

  • ④IPv6 長度為 128bit，以十六進制表示：正確，符合 IPv6 規格。

  • ④單一介面可有多個不同類型的位址：正確，如同時具備 Link-Local 與 Global 位址。

194. 關於 Classless 路由協定，下列哪些正確？（多選題）

早期路由協定（Classful，如 RIPv1）在傳送路由表時「不會」夾帶子網路遮罩，導致它只能死板地認定預設的 A/B/C Class 網段。後來進化的 無級別 (Classless) 路由協定（如 RIPv2、OSPF、EIGRP），其更新封包中會夾帶子網路遮罩資訊，因此完美支援了 VLSM（可變長度子網路遮罩）與不連續網路的架構，讓 IP 分配更具彈性。

【各選項解析】

  • ②允許使用不同長度的子網路遮罩：正確，完全支援 VLSM。
  • ③RIPv1 屬於 Classless：錯誤，RIPv1 是古老的 Classful (有級別) 協定。
  • ④RIPv2 屬於 Classless：正確，第 2 版加入了對遮罩的支援。

195. 關於 Distance Vector 與 Link State 路由協定，下列哪些正確？（多選題）

②Distance Vector 定期送出完整路由表予所有啟動的介面
③Link State 送出包括本身之連接的更新狀態予網路中所有路由器
④Distance Vector 送出包括本身之連接的更新狀態予網際網路中所有路由器
💡 點擊展開解答與解析
✅ 正確答案：②、③ (多選題)
【綜合解析】

這兩種主流演算法的行為模式截然不同：
- 距離向量 (Distance Vector, 如 RIP)：會定期地把「自己整張路由表」通通塞給隔壁的鄰居路由器。缺點是比較佔頻寬，且收斂速度慢。
- 鏈路狀態 (Link State, 如 OSPF)：平時不亂傳表，只有當網路拓撲發生變化時，才會產生「LSA (鏈路狀態通告)」廣播給網域內所有路由器，大家自己收集地圖碎片並透過演算法計算出最短路徑。

【各選項解析】
  • ①Link State 定期送出完整路由表：錯誤，這是 Distance Vector 的作法。
  • ②Distance Vector 定期送出完整路由表：正確。
  • ③Link State 送出本身之連接狀態予網路中所有路由器：正確，使用 LSA 進行洪泛廣播。
  • ④Distance Vector 送出本身更新狀態予所有路由器：錯誤，它只跟「相鄰的」路由器交換「完整的路由表」。

196. RIPv2 使用哪些方式以避免路由迴圈（Routing Loop）？（多選題）
①CIDR
②Split Horizon
③Authentication
④Holddown Timers
💡 點擊展開解答與解析
✅ 正確答案：②、④ (多選題)
【綜合解析】

距離向量演算法最怕遇到「路由迴圈（封包在兩台 Router 間像踢皮球一樣死循環）」。為了防堵此問題，RIP 等協定發展出了幾個關鍵機制：
1. 水平分割 (Split Horizon)：從某個介面學到的路由，絕對不再從同一個介面丟回去。
2. 壓制計時器 (Holddown Timers)：當收到某網段斷線的消息後，啟動一段冷凍期，期間內不接受比原本差的路由更新，避免學到錯誤的舊資訊。
3. 路由毒化 (Route Poisoning) 等。

【各選項解析】
  • ①CIDR：無級別網域間路由，是一種 IP 配置與路由聚合技術，與防迴圈無關。
  • ②Split Horizon：正確，水平分割是防迴圈的基礎機制。
  • ③Authentication：身分驗證，是為了網路安全性（防駭客假冒），非防止迴圈。
  • ④Holddown Timers：正確，壓制計時器用以防止錯誤路由死灰復燃。

197. 下列哪些是 VLAN 的優點？（多選題）
①增加碰撞網域的大小
②允許以部門將使用者進行邏輯分群
③強化網路安全
④減少碰撞網域的數量

✅ 正確答案：②、③ (多選題)
【綜合解析】

VLAN（虛擬區域網路）主要運作於 Layer 2 交換器上，它能夠將一台實體的 Switch 在邏輯上切分成好幾台獨立的虛擬 Switch。這樣做的最大好處是：能根據部門屬性彈性劃分群組，且不同 VLAN 的廣播封包被阻絕開來，大大強化了資料不被其他部門窺探的安全性。
至於「碰撞網域（Collision Domain）」，在使用現代交換器的環境中，每個 Switch Port 都是一個獨立的碰撞網域，VLAN 的切分主要是用來縮小「廣播網域（Broadcast Domain）」，而非改變碰撞網域的大小或數量。

【各選項解析】
  • ①增加碰撞網域的大小：錯誤，Switch 每個埠早已隔離碰撞，VLAN 切割的是廣播網域。
  • ②允許以部門將使用者進行邏輯分群：正確，提供不受物理位置限制的配置彈性。
  • ③強化網路安全：正確，VLAN 間無法直接通訊，隔離了廣播與非授權存取。
  • ④減少碰撞網域的數量：錯誤，VLAN 與碰撞網域的數量增減無關。

物聯網（IoT）的基礎架構被業界普遍劃分為三大層級（由底層到高層）：

2. 網路層 (Network Layer)：如 5G、Wi-Fi、光纖網路等，負責將感知層收集到的龐大數據安全、穩定地「傳輸」至雲端或伺服器。
3. 應用層 (Application Layer)：結合雲端運算與大數據分析，將資料轉換為智慧家庭、智慧交通等具體的「服務與應用」。

  • ③連結層：錯誤，這並非 IoT 三大標準架構階層之一。
  • ④應用層：正確，物聯網架構的最高層（處理與應用資料）。
