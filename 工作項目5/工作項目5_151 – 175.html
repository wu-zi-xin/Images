主題：雲端運算服務模式 (SaaS)
151. 下列雲端服務中，何者可提供「集中式託管軟體及其相關資料，使用者僅需透過網際網路，而不須安裝即可使用軟體」之相關服務？
①IaaS
②PaaS
③SaaS
④XaaS
💡 點擊展開解答與解析
✅ 正確答案：③
【綜合解析】

這描述的是軟體即服務（Software as a Service, SaaS）。在這種模式下，雲端供應商會把軟體安裝並運行在自家的伺服器上，使用者不需要在自己的電腦上安裝任何應用程式，只要打開瀏覽器連上網路，就能直接使用這些軟體功能（例如：Gmail、Google Docs 等）。

【各選項解析】
  • ①IaaS：基礎設施即服務，提供虛擬硬體資源，需自行安裝作業系統與軟體。
  • ②PaaS：平台即服務，提供開發者撰寫程式的平台環境。
  • ③SaaS：正確，軟體即服務，使用者隨開即用，免安裝維護。
  • ④XaaS：一切即服務，為所有雲端服務的統稱。
主題：雲端運算服務實例 (PaaS)
152. 下列何者屬於雲端運算中之平台即服務（Platform as a Service, PaaS）？
①Google Compute Engine
②Google Storage
③Google App Engine
④Google Apps
💡 點擊展開解答與解析
✅ 正確答案：③
【綜合解析】

Google 提供了各種類型的雲端服務來對應不同的架構層級。其中 Google App Engine 提供了預先配置好的伺服器環境與開發框架（如 Python、Java 執行環境），讓開發者只要把寫好的程式碼放上去就能直接運行，不需要去管底層作業系統的維護，這就是最典型的 PaaS 服務。

  • ①Google Compute Engine：提供虛擬機器，屬於 IaaS。
  • ②Google Storage：提供純資料儲存空間，屬於 IaaS 的一種儲存服務。
  • ③Google App Engine：正確，提供程式部署與執行環境，屬於 PaaS。
  • ④Google Apps：提供給終端用戶的線上辦公套件，屬於 SaaS。
主題：網路基礎服務 (DHCP)
153. 在物聯網（IoT）實作中，哪種伺服器將為感應器等終端設備提供 IP 定址資訊？
①檔案伺服器
②Web 伺服器
③DNS 伺服器
④DHCP 伺服器
💡 點擊展開解答與解析
✅ 正確答案：④
【綜合解析】

不論是傳統的電腦，或是物聯網中的智慧感應器，只要需要連上 TCP/IP 網路，就必須擁有一組 IP 位址。為了免去手動一一設定的麻煩，網路中通常會架設 DHCP（動態主機設定協定）伺服器，負責自動且動態地配發 IP 位址、子網路遮罩與預設閘道給這些終端設備。

【各選項解析】
  • ①檔案伺服器：負責儲存與分享檔案。
  • ②Web 伺服器：負責提供 HTTP 網頁內容。
  • ③DNS 伺服器：負責將網域名稱解析為 IP 位址，不負責「配發」IP。
  • ④DHCP 伺服器：正確，負責自動配發 IP 定址資訊。
主題：網路設備功能 (Router)
154. 以下何種網路裝置具有向目的地轉送網路層資料封包的資訊？
①中繼器
②橋接器
③路由器
④集線器
💡 點擊展開解答與解析
✅ 正確答案：③
【綜合解析】

在 OSI 七層模型中，運作在第三層「網路層（Network Layer）」並具備解讀 IP 封包位址、選擇最佳路徑以進行跨網段轉送的設備，就是「路由器（Router）」。其他選項的設備皆運作在較低的階層，無法讀懂網路層的封包資訊。

【各選項解析】
  • ①中繼器（Repeater）：運作於實體層，僅負責將微弱的電訊號放大延長。
  • ②橋接器（Bridge）：運作於資料鏈結層，根據 MAC 位址進行同網段轉送。
  • ③路由器（Router）：正確，運作於網路層，根據 IP 位址進行跨網段路由轉送。
  • ④集線器（Hub）：運作於實體層，以廣播方式盲目發送電子訊號。
主題：雲端運算特性
155. 何種技術可允許使用者隨時隨地存取資料？
①資料分析
②雲端運算
③虛擬化
④微觀行銷
💡 點擊展開解答與解析
✅ 正確答案：②
【綜合解析】

「雲端運算（Cloud Computing）」的核心特性之一就是「無所不在的網路存取能力」。使用者只要擁有任何連網裝置（手機、平板、電腦），就能隨時隨地透過網際網路連接到遠端伺服器存取自己的檔案或應用程式，徹底打破了實體儲存裝置的地理限制。

【各選項解析】
  • ①資料分析：是從大數據中提取有價值資訊的過程。
  • ②雲端運算：正確，提供無遠弗屆的資料與運算存取能力。
  • ③虛擬化：是雲端運算的底層基礎技術，但它本身不代表「隨時隨地存取」這項應用特性。
  • ④微觀行銷：是一種精準行銷策略，與網路存取技術無關。
主題：物聯網 (IoT) 架構
156. 新型智慧家庭中，冰箱內裝有感應器，可以偵測出牛奶容器已經快空了。該感應器會先將此訊息傳送給何種裝置，以便最終將訊息傳送給屋主？
①控制器
②網際網路提供者伺服器
③RFID 標籤
④RFID 讀取器
💡 點擊展開解答與解析
✅ 正確答案：①
【綜合解析】

在物聯網的邊緣網路架構中，單一的感應器（如重量感測器）通常不具備直接連上廣域網際網路的能力（為了省電與成本）。因此，感應器會先透過藍牙、ZigBee 等短距通訊將數據傳送給家中的「控制器（或稱為 IoT 閘道器/中樞）」，再由這個控制器統一將資料連上網路，最終推播通知到屋主的手機中。

【各選項解析】
  • ①控制器：正確，作為感應器與外網之間的資訊匯整中樞。
  • ②網際網路提供者伺服器：ISP 伺服器是外網通道，感測器不會直接對它發送。
  • ③RFID 標籤：是被讀取的被動元件，無法主動傳送「牛奶快空」的動態重量資訊。
  • ④RFID 讀取器：用來讀取標籤，非負責聯網通訊的家庭中樞。
主題：網路協定模型 (OSI)
157. 為什麼共同的網路協定模型對於網路之資料交換是必要的？
①可減少設備供應商的數量
②可增加網路連線的頻寬
③可確保來自多個供應商設備的互通性
④可彙總用於短距離網路及長距離網路的多種協定
💡 點擊展開解答與解析
✅ 正確答案：③
【綜合解析】

早期各大電腦廠商（如 IBM、Apple）都有自己獨家的網路通訊語言，導致不同品牌的電腦根本無法互相對話。後來國際標準組織制定了共同的網路協定模型（如 OSI 參考模型、TCP/IP），最大的目的就是打破品牌藩籬，讓全世界所有供應商生產的網卡、路由器、作業系統，都能用「共通的語言」對話，確保設備間的互通性。

【各選項解析】
  • ①可減少設備供應商的數量：相反，標準化反而促進了更多廠商投入生產競爭。
  • ②可增加網路連線的頻寬：頻寬取決於物理線材與調變技術，與邏輯協定模型無關。
  • ③可確保來自多個供應商設備的互通性：正確，這就是標準化最大的價值。
  • ④可彙總用於短距離及長距離的多種協定：模型是用來分層規範，而非單純的彙總。

159. 下列哪些 IPv4 位址表示子網廣播位址？（多選題）

  • ④172.16.4.95 /27：95 是第三網段(64~95)的最後一個數字，為廣播位址。正確。

160. 下列哪些 IPv4 位址表示子網路的有效主機位址？（多選題）

②10.11.12.32/28
③10.11.11.97/27

有效主機位址不能是網段的第一個數字（Network ID），也不能是網段的最後一個數字（Broadcast）。

  • ③10.11.11.97/27：位於網段 96~127 之間，為有效主機位址。正確。
  • ④10.11.11.128/27：128 剛好是 32 的倍數起點，為網路位址，無效。
主題：資訊安全 CIA (多選題)
161. 下列哪些措施可加強資料之機密性（Confidentiality）？（多選題）
①增加網路頻寬
②設定通行碼（Password）
③加密（Encryption）
④備份資料
💡 點擊展開解答與解析
✅ 正確答案：②、③ (多選題)
【綜合解析】

在資訊安全 CIA 三要素中，「機密性（Confidentiality）」的目的是確保資料只能被「有授權的人」看見，防止外洩。最直接的技術手段就是驗證身分（如設定密碼）以及將資料打亂（如加密），讓就算資料被偷走，駭客也看不懂內容。

【各選項解析】
  • ①增加網路頻寬：提升的是網路的傳輸效能，與資安防護無關。
  • ②設定通行碼：正確，透過密碼身分認證來阻擋未授權存取。
  • ③加密：正確，將明文轉為密文，為機密性最強防護。
  • ④備份資料：這是在加強系統故障時的「可用性（Availability）」。
主題：入侵偵測系統 IDS (多選題)
162. 關於入侵偵測系統，下列哪些正確？（多選題）
①以誤用偵測定義出異常行為
②以異常偵測定義出正常行為
③誤用偵測以列出黑名單方式運作
④異常偵測以列出黑名單方式運作
💡 點擊展開解答與解析
✅ 正確答案：①、②、③ (多選題)
【綜合解析】

IDS 判斷攻擊主要有兩種邏輯：
1. 誤用偵測 (Misuse Detection)：系統資料庫內存有已知的「病毒/攻擊特徵碼」，只要封包長得像特徵碼就被判定為異常，這就是標準的「黑名單」運作方式。
2. 異常偵測 (Anomaly Detection)：系統會先花時間學習並定義出網路的「正常行為輪廓 (白名單)」，日後只要行為偏離這個正常輪廓，就會發出警報。

【各選項解析】
  • ①以誤用偵測定義出異常行為：正確，使用已知特徵來直接判定何謂異常攻擊。
  • ②以異常偵測定義出正常行為：正確，異常偵測機制的核心前提是先描繪出正常行為的基線。
  • ③誤用偵測以列出黑名單方式運作：正確，特徵碼比對即為黑名單邏輯。
  • ④異常偵測以列出黑名單方式運作：錯誤，異常偵測是偏向「白名單 (偏離正常即擋)」邏輯。
主題：資訊安全稽核 (多選題)
163. 資訊安全管理稽核之目標，包含下列哪些？（多選題）
①確保所有資料均正確
②確保所有資料的存取均經過授權
③確保所有的運作均能按照既定的安全政策執行
④確保所有機密資料均受保護
💡 點擊展開解答與解析
✅ 正確答案：②、③、④ (多選題)
【綜合解析】

資訊安全稽核（IS Audit）的目的是在檢驗企業的 IT 系統運作是否合乎安全政策與法規要求。它關注的是「機制是否完善」，例如權限控管、機密保護、流程合規等。至於「資料內容本身打字有沒有錯誤（資料正確性）」，這屬於業務資料品管範疇，並非資安稽核能完全保證的目標。

【各選項解析】
  • ①確保所有資料均正確：內容正確性超越了資安防護的範疇。
  • ②確保存取均經過授權：正確，這是機密性與權限管理稽核的重點。
  • ③確保運作按照既定安全政策執行：正確，此為流程與合規性稽核的核心。
  • ④確保機密資料均受保護：正確，檢驗加密或實體隔離措施是否落實。
主題：資安保護機制 (完整性) (多選題)
164. 下列哪些屬訊息完整性（Integrity）之保護機制？（多選題）
①數位簽章
②訊息鑑別碼
③ID 及通行碼
④雜湊函數（Hash Function）
💡 點擊展開解答與解析
✅ 正確答案：①、②、④ (多選題)
【綜合解析】

「完整性（Integrity）」的目標是防範資料在傳輸或儲存過程中被駭客惡意竄改。密碼學中常用雜湊函數（Hash）來產生檔案指紋，或者使用訊息鑑別碼（MAC）與數位簽章來同時提供防竄改與來源驗證的雙重完整性保障。

【各選項解析】
  • ①數位簽章：正確，利用非對稱加密確保文件未被竄改且不可否認。
  • ②訊息鑑別碼：正確，(Message Authentication Code) 提供防竄改驗證。
  • ③ID 及通行碼：這是用來做「身分驗證 (Authentication)」的，而非檔案防竄改。
  • ④雜湊函數：正確，用以核對傳輸前後的檔案指紋是否一致。

✅ 正確答案：①、②、④ (多選題)
【綜合解析】

對稱式加密（如 AES、DES）是指傳送方和接收方使用「同一把鑰匙」進行加密與解密。它的數學運算較為簡單，因此速度極快，非常適合用來加密大量資料（機密性）。但它的致命缺點是：你必須先想辦法把鑰匙安全地交給對方（金鑰分配問題）；此外，因為雙方都有同一把鑰匙，任何人都能偽造，因此它「無法提供不可否認性」。

【各選項解析】
  • ①加解密速度較快：正確，通常比非對稱式快上百倍至千倍。
  • ②提供機密性保護功能：正確，資料加密的最基本功能。
  • ③提供不可否認性功能：錯誤，對稱加密無法證明是誰發送的，需仰賴非對稱式的數位簽章。
  • ④需額外機制安全傳遞金鑰：正確，這是對稱式加密最大的管理痛點。
主題：非對稱式加解密 (多選題)
166. 關於非對稱式加解密演算法，下列哪些正確？（多選題）
①經常須以傳遞對稱式加解密金鑰
②RSA 是非對稱式加解密演算法
③又稱作公開金鑰加解密演算法
④加解密速度較對稱式加解密演算法快
💡 點擊展開解答與解析
✅ 正確答案：①、②、③ (多選題)
【綜合解析】

非對稱式加密（如 RSA）使用一對金鑰：公開金鑰（公鑰）與秘密金鑰（私鑰）。因為公鑰可以隨意公開，完美解決了金鑰分配問題。但由於其背後仰賴複雜的數學質數運算，導致它的加解密「速度非常緩慢」。因此在實務上（如 HTTPS），系統通常會先用非對稱加密來「安全傳遞一把對稱式金鑰」，之後的大量資料傳輸再改用速度快的對稱加密來進行。

【各選項解析】
  • ①經常須以傳遞對稱式加解密金鑰：正確，利用其高安全性解決對稱金鑰分配的難題。
  • ②RSA 是非對稱式演算法：正確，RSA 是最著名的代表演算法。
  • ③又稱作公開金鑰加解密演算法：正確，Public Key Cryptography。
  • ④加解密速度較對稱式快：錯誤，非對稱式的運算負擔大，速度極慢。
主題：雜湊函數 Hash (多選題)
167. 關於密碼學的雜湊函數（Hash Function），下列哪些正確？（多選題）
①不同本文經雜湊運算後產出的雜湊值一定不同
②是一種沒有反函數的函數
③不同長度本文經雜湊運算後產出固定長度的雜湊值
④經常用在數位簽章及完整性檢查
💡 點擊展開解答與解析
✅ 正確答案：②、③、④ (多選題)
【綜合解析】

雜湊函數（如 SHA-256）是一種將任意長度檔案「攪碎」並濃縮成一串「固定長度指紋」的數學單向演算法。因為它是不可逆的（無法從指紋反推回原本的檔案），所以常用於存儲密碼或驗證檔案完整性。但因為輸出的指紋長度是固定的，而輸入的檔案無限多，數學上必然存在機率極低的「碰撞（兩個不同檔案產生相同指紋）」，所以「一定不同」的說法太過絕對。

【各選項解析】
  • ①不同本文產出的雜湊值一定不同：錯誤，理論上存在發生「碰撞 (Collision)」的機率。
  • ②是一種沒有反函數的函數：正確，它具備單向性 (One-way)。
  • ③產出固定長度的雜湊值：正確，不論檔案是 1KB 還是 10GB，Hash 值長度都固定。
  • ④經常用在數位簽章及完整性檢查：正確，常先 Hash 後再對指紋進行簽章以節省運算資源。

168. 客戶端通過單一通信鏈路，由伺服器下載 5MB（=5x2²⁰ byte）大小的檔案，假設鏈路頻寬為 100Mbps，若客戶端與伺服器間之距離為 4000 公里，通過介質之傳播速度（Propagation Speed）為 2x10⁸ m/s（公尺/秒）；關於傳播延遲（Propagation Delay）及傳輸延遲（Transmission Delay），下列哪些正確？（多選題）
①傳播延遲為 0.02 秒
②傳輸延遲為 0.01 秒
③傳播延遲較傳輸延遲大
④傳播延遲較傳輸延遲小
💡 點擊展開解答與解析
✅ 正確答案：①、④ (多選題)
【綜合解析與計算】

這題考驗的是「傳播延遲」與「傳輸延遲」的計算公式：
1. 計算傳播延遲 (Propagation Delay)：
公式：距離 ÷ 傳播速度
4000 公里 = 4,000,000 公尺 (4 × 10⁶ m)
時間 = 4,000,000 ÷ 200,000,000 = 0.02 秒。(選項①正確)
2. 計算傳輸延遲 (Transmission Delay)：
公式：檔案總資料量 ÷ 鏈路頻寬
檔案大小：5MB = 5 × 2²⁰ bytes × 8 bits ≈ 41,943,040 bits。
頻寬：100Mbps = 100 × 10⁶ bits/sec = 100,000,000 bits/sec。
時間 = 41,943,040 ÷ 100,000,000 ≈ 0.419 秒。(選項②錯誤)
3. 比較兩者：傳播延遲 (0.02秒) 確實 小於 傳輸延遲 (0.419秒)。(選項④正確，選項③錯誤)

【各選項解析】
  • ①傳播延遲為 0.02 秒：正確，透過距離除以光速計算得出。
  • ②傳輸延遲為 0.01 秒：錯誤，經計算約為 0.419 秒。
  • ③傳播延遲較傳輸延遲大：錯誤，0.02秒小於0.419秒。
  • ④傳播延遲較傳輸延遲小：正確。

  • ③至路由器 C 成本為 5：正確，由 E -> D -> C (4+1=5) 最快。
  • ④至路由器 D 成本為 4：正確，直接連線成本為 4。

172. 關於動態主機組態協定（Dynamic Host Configuration Protocol, DHCP）之訊息交換的敘述，下列哪些正確？（多選題）
①需求 IP 位址之主機，廣播 DHCP 探索(Discover)訊息
②DHCP 伺服器以 DHCP 提供(Offer)訊息單播(Unicast)回應 DHCP 探索(Discover)訊息
③需求 IP 位址之主機，廣播 DHCP 請求(Request)訊息，請求 IP 位址
④DHCP 伺服器以 DHCP 提供(Offer)訊息單播(Unicast)回應 DHCP 請求(Request)訊息
💡 點擊展開解答與解析
✅ 正確答案：①、②、③ (多選題)
【綜合解析】

DHCP 獲取 IP 的標準流程稱為 DORA 四部曲：
1. Discover (探索)：Client 廣播尋找伺服器。
2. Offer (提供)：Server 回應可提供的 IP（實務上視旗標而定，考題中視為可單播回應給客戶端 MAC）。
3. Request (請求)：Client 廣播確認要租用該 IP。
4. ACK (確認)：Server 回應 ACK 確認租約。
選項④錯在把「Offer 訊息」誤植為回應 Request，正確回應 Request 的應該是「ACK 訊息」。

【各選項解析】
  • ①主機廣播 DHCP Discover 訊息：正確，流程第一步。
  • ②伺服器以 Offer 訊息回應 Discover 訊息：正確，流程第二步。
  • ③主機廣播 DHCP Request 訊息：正確，流程第三步，用以告知所有潛在伺服器它的決定。
  • ④以 Offer 訊息回應 Request 訊息：錯誤，回應 Request 的應為 ACK (Acknowledge) 訊息。

②需維持終端使用者之連接狀態

④原始超文字傳輸協定（Hyper-Text Transfer Protocol, HTTP）為一種不具狀態協定

主題：乙太網路訊框結構 (多選題)
175. IEEE Ethernet 訊框標頭（Frame Header）包含下列哪些欄位？（多選題）
①來源與目的地 MAC 位址
②來源與目的地網路位址
③來源與目的地 MAC 位址以及來源與目的地網路位址
④FCS 欄位
💡 點擊展開解答與解析
✅ 正確答案：①、④ (多選題)
【綜合解析】

一個標準的第二層乙太網路訊框（Ethernet Frame）主要由三個部分組成：
1. Header (標頭)：包含目的 MAC 位址、來源 MAC 位址、以及 EtherType(協定類型)。
2. Payload (酬載)：這裡面才是裝載了第三層的 IP 封包（來源與目的網路 IP 位址藏在這裡）。
3. Trailer (標尾)：包含 FCS (Frame Check Sequence，訊框檢查碼) 用以偵測傳輸錯誤。此考題將 FCS 視為訊框基礎欄位之一併入選項正確範圍中。

【各選項解析】
  • ①來源與目的地 MAC 位址：正確，這是 Layer 2 乙太網路標頭的核心定址資訊。
  • ②來源與目的地網路位址：錯誤，網路(IP)位址屬於 Layer 3 封包內容，不在 Ethernet 標頭中。
  • ③來源與目的MAC 以及 網路位址：同上，網路位址不屬於此層標頭。
  • ④FCS 欄位：正確，為 Ethernet 訊框最後用以檢查資料正確性的必要欄位（Trailer）。
