102. 依 ANSI/TIA/EIA-568-B3 規範，多模光纖轉接器或面板的顏色為何？
①米黃色
②紅色
③綠色
④藍色
💡 點擊展開解答與全選項解析
✅ 正確答案：①
【綜合解析】 TIA/EIA 標準為了讓機房維運人員防呆辨識，定義了光纖接頭面板的顏色管理。 【各選項解析】
  • ⭕ ①米黃色：正確。多模光纖 (Multi-mode Fiber) 的轉接器面板標準顏色就是米黃色 (Beige)。
  • ❌ ②紅色：非光纖介面主流標準色。
  • ❌ ③綠色：通常代表斜角研磨 (APC) 規格的單模光纖接頭。
  • ❌ ④藍色：代表一般的單模光纖 (Single-mode, UPC) 面板顏色。
103. 光纖接合（熔接或機械式迅接）後，最大光纖衰減值（dB）為下列何者？
①0.2
②0.3
③0.4
④0.5
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 光纖兩段接合時會產生光訊號的損耗 (衰減)。根據標準規範，不管是使用熱熔接還是機械式接續，接點的損耗皆有嚴格限制。 【各選項解析】
  • ❌ ①0.2 dB：雖然優良的熔接可達 0.1 以下，但規範規定的「最大容許值」不是 0.2。
  • ⭕ ②0.3 dB：正確。標準明定任何光纖接續點的最大衰減容許值為 0.3 分貝 (dB)。
  • ❌ ③0.4 dB / ④0.5 dB：這兩個數值損耗過大，已不符合標準檢驗要求。
104. 多模光纖在光纖接合（熔接或機械式迅接）後，最小回傳損失（Return loss）（dB）為下列何者？
①18
②20
③24
④26
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 回傳損失 (Return Loss) 是指「光打到接點時被反彈回來的光量比率」，**這個數值越高越好** (代表被反彈的光極少)。多模光纖因傳輸距離較短，標準要求相對寬鬆。 【各選項解析】
  • ❌ ①18 dB：非標準規定值。
  • ⭕ ②20 dB：正確。多模光纖接合的最小回傳損失標準要求為 20 dB。
  • ❌ ③24 dB / ④26 dB：26 dB 是單模光纖的標準，多模不需到這麼高。
105. 單模光纖在光纖接合（熔接或機械式迅接）後，最小回傳損失（Return loss）（dB）為下列何者？
①18
②20
③24
④26
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 承上題，單模光纖通常用於長距離、高頻寬的電信骨幹傳輸，如果光線在接點處反彈(反射)太嚴重，會干擾發射端的高速雷射光源，因此單模的標準比多模更嚴格。 【各選項解析】
  • ❌ ①18 dB / ③24 dB：皆非標準數值。
  • ❌ ②20 dB：這是多模光纖的標準。
  • ⭕ ④26 dB：正確。單模光纖接合的最小回傳損失必須達到 26 dB (數值越高代表抗反射品質越好)。
106. 無線區域網路架構下，以何者識別網路節點？
①服務組識別碼（Service Set Identifier，SSID）
②MAC 位址
③Port 編號
④IP 位址
💡 點擊展開解答與全選項解析
✅ 正確答案：①
【綜合解析】 在 Wi-Fi (無線區域網路) 環境中，當我們打開手機要連線時，會看到許多不同的「Wi-Fi 名稱」，這個名稱就是用來區分不同基地台或無線群組的標識。 【各選項解析】
  • ⭕ ①SSID：正確。服務組識別碼就是俗稱的 Wi-Fi 網路名稱，用以在空中識別特定的無線網路節點。
  • ❌ ②MAC 位址：這是實體網卡的硬體位置，主要用於內部封包轉發，非用戶端連線時用來識別整個「無線網路群組」的依據。
  • ❌ ③Port 編號：TCP/UDP 傳輸層用來區分應用程式的號碼。
  • ❌ ④IP 位址：連上網路後用來通訊的邏輯位址，在連線前並無法用 IP 來識別無線節點。
107. 下列何者不是雲端運算的基本部署模型（Deployment model）？
①Private cloud
②Home cloud
③Public cloud
④Hybrid cloud
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 依據美國國家標準技術研究所 (NIST) 的定義，雲端運算有四種標準的「部署模型」。 【各選項解析】
  • ❌ ①Private cloud：私有雲，專供單一組織使用，為標準模型。
  • ⭕ ②Home cloud：正確，這「不是」標準的部署模型，家庭雲只是一般消費市場的行銷名詞。
  • ❌ ③Public cloud：公有雲 (如 AWS, Google Cloud)，為標準模型。
  • ❌ ④Hybrid cloud：混合雲 (結合公有與私有)，為標準模型。(第四種為 Community Cloud 社群雲)。
108. 電腦中所使用的憑證（Certificate）採用下列何種標準？
①ISO/IEC 15408
②X.509v3
③BS 7799
④ISO/IEC 27001
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 當您瀏覽 HTTPS 加密網站時，瀏覽器會核對伺服器的「數位憑證」，以確保它不是偽造的釣魚網站。該憑證的格式有國際通用標準。 【各選項解析】
  • ❌ ①ISO/IEC 15408：這是資訊技術安全評估共同準則 (Common Criteria)。
  • ⭕ ②X.509v3：正確。X.509 是國際電信聯盟 (ITU-T) 制定之公開金鑰基礎建設 (PKI) 數位憑證的標準格式，目前廣泛使用的是第 3 版 (v3)。
  • ❌ ③BS 7799：資訊安全管理的英國標準 (已演進為 ISO 27001)。
  • ❌ ④ISO/IEC 27001：資訊安全管理系統 (ISMS) 國際標準規範。
109. 數位資料管理者之角色不包括？
①回復遺失的資料
②定期備份資料
③規定資料的保存期限
④確保資料的可用性
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 在資訊安全職責劃分中，「資料擁有者 (Data Owner)」通常是管理階層，負責決定政策；而「資料管理者/保管者 (Data Custodian)」則是 IT 技術人員，負責執行防護與維運。 【各選項解析】
  • ❌ ①回復遺失的資料：系統崩潰時把資料倒回來，是 IT 管理者的職責。
  • ❌ ②定期備份資料：日常維運工作，是管理者的職責。
  • ⭕ ③規定資料的保存期限：正確。資料要留幾年才合法，這是由管理階層(擁有者)或法規來「規定」，IT 管理者無權也無法自行決定。
  • ❌ ④確保資料的可用性：維持系統上線讓大家能用，是管理者的職責。
110. 在相同實體媒介中，同時傳送多個訊號是屬於下列哪一項技術？
①數位傳輸
②多工
③非同步傳輸
④基頻技術
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 把很多條獨立的通訊對話，塞進同一條實體纜線(如光纖)中同時傳送，以節省成本並提升傳輸容量，這項技術的核心概念叫做多工。 【各選項解析】
  • ❌ ①數位傳輸：相對於類比傳輸，指的是傳送 0 與 1，未提及多個訊號共用。
  • ⭕ ②多工 (Multiplexing)：正確。常見的有 FDM(分頻多工)、TDM(分時多工) 等。
  • ❌ ③非同步傳輸：傳送端與接收端不依賴嚴格統一的時鐘進行通訊的方式。
  • ❌ ④基頻技術：(Baseband) 線路上一次只傳送單一個數位訊號 (例如一般的 Ethernet)，這與「同時傳送多個訊號(寬頻)」恰好相反。
111. 下列哪一項不是 SaaS 可行的計費方法？
①使用人數
②使用時間
③使用路由器數量
④使用頻寬
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 SaaS (Software as a Service，軟體即服務) 例如 Microsoft 365 或 Google Workspace，是供應商在雲端直接把「軟體」租給您用。 【各選項解析】
  • ❌ ①使用人數：最常見的 SaaS 收費法 (算人頭/帳號授權數)。
  • ❌ ②使用時間：按月或按年訂閱收費。
  • ⭕ ③使用路由器數量：正確。路由器是底層的硬體設備，SaaS 用戶根本不需要管底層硬體，因此 SaaS 絕對不會依據路由器的數量來跟您收費 (這比較可能是網管服務的計費項目)。
  • ❌ ④使用頻寬：影音串流類 SaaS 可能依傳輸流量計費。
112. 下列哪一項是 SaaS 使用者必須注意的項目？
①伺服器作業系統
②伺服器設備
③異地備份系統
④使用者瀏覽器安全
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 承上題概念，在 SaaS 模型下，幾乎所有的 IT 底層架構都由雲端供應商包辦了，使用者只要負責打開瀏覽器登入使用即可。 【各選項解析】
  • ❌ ①伺服器作業系統 / ②伺服器設備 / ③異地備份系統：這三者在 SaaS 模式下，皆為雲端供應商(如 Google, 微軟)的責任，使用者不需也無法插手管理。
  • ⭕ ④使用者瀏覽器安全：正確。由於 SaaS 是透過網頁瀏覽器存取的，如果用戶自己的電腦中了木馬、瀏覽器密碼被盜用，供應商也救不了您。端點(瀏覽器)安全是使用者自己的責任。
113. 下列哪一類型軟體最適合做為 Public SaaS 使用？
①Business logic 軟體
②Real time 軟體
③Bulk consumer data 軟體
④Critical 軟體
💡 點擊展開解答與全選項解析
✅ 正確答案：①
【綜合解析】 SaaS (軟體即服務) 是將應用程式部署在雲端供用戶直接使用。對於公有雲 (Public SaaS) 而言，最適合的是提供通用、標準化流程的商業服務。 【各選項解析】
  • ⭕ ①Business logic 軟體：正確。如企業的 CRM、ERP、會計或人事軟體等標準化的商業邏輯軟體，非常適合採用 Public SaaS。
  • ❌ ②Real time 軟體：即時系統 (如工業控制、自動駕駛) 對網路延遲極度敏感，通常不適合放在無法保證延遲的公有雲。
  • ❌ ③Bulk consumer data 軟體：大量消費者資料若全放公有雲，傳輸頻寬成本極高且容易有隱私與法規限制的風險。
  • ❌ ④Critical 軟體：攸關企業存亡或生命安全的關鍵核心軟體，基於高可用性與資安防護考量，多建置於私有雲或地端機房。
114. 下列何者為 IaaS 的消費者？
①程式設計師
②系統管理者
③終端使用者
④業務人員
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 雲端服務模式 (SaaS, PaaS, IaaS) 各有不同的目標客群與技術門檻。IaaS 提供的是運算、網路、儲存等「基礎架構」，就像租用一塊空地與虛擬空機。 【各選項解析】
  • ❌ ①程式設計師：程式開發人員通常需要的是已經架設好資料庫與開發環境的平台，因此他們是 PaaS (平台即服務) 的主要消費者。
  • ⭕ ②系統管理者：正確。System Administrator (IT 網管/系統工程師) 負責從無到有建置伺服器、規劃網路與儲存空間，因此是 IaaS 的主要消費者。
  • ❌ ③終端使用者 / ④業務人員：一般使用者只負責「用」現成的軟體，他們是 SaaS 的消費者。
115. 下列何者不是 IaaS 的消費者可以取得的資源？
①網路防火牆
②組態服務
③存取虛擬主機
④實體硬體
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 在 IaaS (基礎架構即服務) 模式下，雲端供應商會將實體硬體資源「虛擬化」之後再租給消費者。消費者只需透過網頁介面就能遠端控制這些虛擬資源。 【各選項解析】
  • ❌ ①網路防火牆：消費者可以在 IaaS 平台上取得並設定專屬的「虛擬防火牆」(如 AWS 的 Security Groups)。
  • ❌ ②組態服務：消費者可以取得虛擬網路與主機的組態設定服務。
  • ❌ ③存取虛擬主機：消費者能取得虛擬機器 (VM) 的完整存取權 (如 root/administrator 權限)。
  • ⭕ ④實體硬體：正確。IaaS 消費者只能操作「虛擬化」的資源，真正的實體硬體 (如伺服器機殼、實體硬碟、實體網路線) 是完全掌握在雲端供應商手中的，消費者無法也不需要直接取得。
116. IaaS 提供者對下列何者具有管理控制權？
①使用者 Middleware
②使用者作業系統
③使用者虛擬主機
④使用者應用系統
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 這題考驗的是雲端運算中的「共同責任模型 (Shared Responsibility Model)」。在 IaaS 架構下，供應商與客戶的管理責任有明確的上下分界。 【各選項解析】
  • ❌ ①使用者 Middleware：(中介軟體，如資料庫引擎、Web 伺服器軟體) 由客戶自行安裝並管理。
  • ❌ ②使用者作業系統：Guest OS (如客戶在 VM 內安裝的 Linux 或 Windows) 由客戶自行負責更新與修補漏洞。
  • ⭕ ③使用者虛擬主機：正確。IaaS 提供者負責維護並掌控底層的實體伺服器與「虛擬化層 (Hypervisor)」，也就是確保這台「虛擬主機」的基礎運行環境與硬體資源分配是正常的。
  • ❌ ④使用者應用系統：客戶寫的程式碼、架設的網站，完全由客戶自己控制與負責。
117. 下列何者不是雲端運算的基本服務模型（Service Model）？
①Software as a Service（SaaS）
②Platform as a Service（PaaS）
③Information as a Service（IaaS）
④Infrastructure as a Service（IaaS）
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 NIST 定義的雲端運算三大基礎服務模型簡稱為 SPI 模型 (SaaS, PaaS, IaaS)。 【各選項解析】
  • ❌ ①SaaS：軟體即服務，為標準模型。
  • ❌ ②PaaS：平台即服務 (提供開發環境)，為標準模型。
  • ⭕ ③Information as a Service (IaaS)：正確選出。因為 IaaS 的 "I" 是指基礎架構(Infrastructure)，而非資訊(Information)，所以這是一個用來混淆考生的錯誤名詞。
  • ❌ ④Infrastructure as a Service (IaaS)：基礎架構即服務 (租用虛擬主機、儲存空間)，為標準模型。
118. 線性遞增倍數遞減（Additive Increase Multiplicative Decrease, AIMD）控制定律使用於下列哪個協定之何種用途？
①TCP 之錯誤檢查
②TCP 之擁塞控制
③IP 之擁塞控制
④UDP 之流量控制
💡 點擊展開解答與全選項解析
✅ 正確答案：②
【綜合解析】 TCP 為了避免將網路塞爆，實作了擁塞控制 (Congestion Control) 演算法，AIMD 是其中的核心機制。 【各選項解析】
  • ❌ ①TCP 之錯誤檢查：錯誤檢查靠的是 Checksum (檢查和)，而非 AIMD。
  • ⭕ ②TCP 之擁塞控制：正確。當網路順暢時，TCP 會「線性地慢慢增加」發送速度(探測上限)；一旦發現網路塞車掉封包，就會立刻將速度「折半(倍數遞減)」以避免網路崩潰。這就是 AIMD。
  • ❌ ③IP 之擁塞控制：IP 協定不管擁塞，它是盡力而為(Best-effort)傳送。
  • ❌ ④UDP 之流量控制：UDP 射後不理，完全沒有流量控制機制。
119. 典型乙太網路（Ethernet）使用 Manchester 編碼。典型 10Mbps 乙太網路的鮑率（Baud/sec）為多少？
①5M
②10M
③20M
④40M
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 Baud rate (鮑率) 是指線路上「實體電位每秒變化的次數」。在 Manchester (曼徹斯特) 編碼中，為了夾帶時鐘同步訊號，**傳輸每個 bit 時，電位都必須在中間變化一次**。 【各選項解析】
  • ❌ ①5M / ②10M / ④40M：皆非正確換算結果。
  • ⭕ ③20M：正確。因為 1 個資料 bit 需要 2 次電位變化(2 Bauds)。所以要在 1 秒內傳輸 10M bits (10 Mbps)，線路上的電位就必須變化 20M 次 (20M Bauds/sec)。
120. IPv6 標頭（Header）之長度為多少個位元組（Byte）？

②56
③40

121. 假設量子密碼學（Quantum Cryptography）能被實際應用，則下列哪個加密系統能提供較難以破解的密文？
①OTP（One-time Pad）
②AES（Advanced Encryption Standard）
③DES（Data Encryption Standard）
④RSA
💡 點擊展開解答與全選項解析
✅ 正確答案：①
【綜合解析】 量子電腦強大的平行計算能力能輕易破解目前依賴數學難題的演算法。 【各選項解析】
  • ⭕ ①OTP (One-time Pad)：正確。一次性密碼本在資訊理論上被證明是「絕對安全 (Perfect Secrecy)」。只要金鑰與明文等長、絕對隨機且只用一次，即使是量子電腦也無法從密文中算出任何明文資訊。
  • ❌ ②AES / ③DES：皆為對稱式加密，在 Shor 演算法下，其金鑰有效強度會被量子電腦折半 (需加倍金鑰長度才能抵禦)。
  • ❌ ④RSA：非對稱式加密，極度依賴質數分解的困難度。量子電腦(Shor 演算法)可以輕易將其破解。
122. 於 6kHz 通道發送二進制訊號，若訊雜比（Signal-to-noise ratio）為 20分貝（dB），則根據 Shannon 定理可達成的最大資料速率為何？（可能需要資料：log2 1001= 9.967、log2 101=6.658、log2 51= 5.67）
①59.802kbps
②19.974kbps
③39.948kbps
④34.02kbps
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 這是一題計算題，依據 Shannon Capacity 定理公式：最大資料速率 C = W * log2(1 + S/N)。
步驟1：先將 dB 換算為實際的訊號雜訊比 (S/N)。公式：dB = 10 * log10(S/N)。
代入 20 = 10 * log10(S/N) ➜ 2 = log10(S/N) ➜ S/N = 10 的 2 次方 = 100。
步驟2：代入夏農公式。C = 6000 (Hz) * log2(1 + 100) = 6000 * log2(101)。
步驟3：參考題目給的 log2 101 = 6.658。C = 6000 * 6.658 = 39948 bps = 39.948 kbps。 【各選項解析】
  • ❌ ①59.802kbps：代錯數字算出的結果。
  • ❌ ②19.974kbps：代錯數字算出的結果。
  • ⭕ ③39.948kbps：正確。計算過程如上。
  • ❌ ④34.02kbps：代入 51 算出的結果 (若頻寬代錯)。
123. 具備 IP 智慧感應器的設定中，為何需要預設閘道位址？
①在感應器發生故障時，能緊急丟棄封包
②允許感應器將 URL 解析為 IP 位址
③使感應器能夠試圖將資料傳送到遠端目的地
④允許感應器與未啟用 IP 的裝置通訊
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 網路設定中的「預設閘道 (Default Gateway)」，就是指當設備要傳送資料給「不在同一個區域網段內」的目標時，必須把封包交給誰(通常是路由器)，由它幫忙轉發出去。 【各選項解析】
  • ❌ ①緊急丟棄封包：故障丟棄與閘道無關。
  • ❌ ②將 URL 解析為 IP：這是 DNS (網域名稱伺服器) 的功能。
  • ⭕ ③傳送到遠端目的地：正確。當感應器要將資料回傳給遠端雲端伺服器(跨網段)時，必須透過預設閘道才能離開目前的區域網路。
  • ❌ ④與未啟用 IP 的裝置通訊：IP 網路無法與未啟用 IP 的裝置直接路由通訊，這需要特殊的 L2 閘道器轉換，不是填寫 IP 預設閘道就能解決。
124. 在物聯網（IoT）實作中，哪種伺服器將為感應器等終端設備提供 IP 定址資訊？
①檔案伺服器
②Web 伺服器
③DNS 伺服器
④DHCP 伺服器
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 物聯網環境中通常有成百上千個感測器，如果人工一一設定 IP 將非常耗時。自動分發 IP 位址的任務會交給專責協定。 【各選項解析】
  • ❌ ①檔案伺服器：(FTP/SMB) 負責儲存檔案，不發 IP。
  • ❌ ②Web 伺服器：(HTTP) 負責提供網頁服務，不發 IP。
  • ❌ ③DNS 伺服器：負責將網址 (如 google.com) 轉換為 IP，不負責「配發給設備使用」的 IP。
  • ⭕ ④DHCP 伺服器：正確。動態主機設定協定 (Dynamic Host Configuration Protocol) 就是專門用來自動配發 IP 位址、子網路遮罩與閘道資訊給終端設備的伺服器。
125. IP 位址的用途是什麼？
①用於標識資料中心的實體位置
②用於標識執行程式的記憶體中的位置
③用於標識對電子郵件訊息做出應答的回覆位址
④用於標識網路上資料封包的來源位址和目的位址
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 IP 位址 (Internet Protocol Address) 是運作在 OSI 第 3 層的邏輯位址，是現代網路通訊的基礎，就像寄信必須寫上收件人與寄件人的門牌地址一樣。 【各選項解析】
  • ❌ ①標識實體位置：IP 不代表地理實體位置(如經緯度)，而是邏輯網段位址。
  • ❌ ②標識記憶體位置：那是記憶體位址(指標)，與網路無關。
  • ❌ ③標識電子郵件回覆：那是 Email 信箱地址 (如 user@mail.com)。
  • ⭕ ④標識來源與目的位址：正確。每一個在網際網路上傳送的 IP 封包，其標頭都包含了來源端與目的端的 IP 位址，路由器就是靠這個來決定封包怎麼走。
126. 無線傳輸速率可根據 Shannon 公式計算出其理論最大值，W = H log₂(1 + S/N)，其中 H 所代表意義為何？
①位元傳輸速率
②波長
③頻寬
④訊雜比
💡 點擊展開解答與全選項解析
✅ 正確答案：③
【綜合解析】 Shannon-Hartley (夏農-哈特利) 定理用來計算在含有白雜訊的通道中，可達成且無錯誤傳輸的最高資訊速率。其常見公式為 C = B * log₂(1 + S/N)，其中 B (或題目寫的 H、W) 代表一個關鍵物理量。 【各選項解析】
  • ❌ ①位元傳輸速率：這是公式等號左邊的計算結果 W (或 C)。
  • ❌ ②波長：夏農公式中不考慮傳輸波長。
  • ⭕ ③頻寬：正確。H (或 B) 代表傳輸通道的「頻寬 (Bandwidth)」，單位為赫茲 (Hz)。頻寬越大，可乘載的極限速率越高。
  • ❌ ④訊雜比：這是公式括號內的 S/N (Signal-to-Noise Ratio)。
127. 下列何者非 IEEE 802.15.4 實體層通訊協定所定義之操作頻段？
①868MHz
②915MHz
③2.4GHz
④3GHz
💡 點擊展開解答與全選項解析
✅ 正確答案：④
【綜合解析】 IEEE 802.15.4 是一種低速率的無線個人區域網路標準 (最知名的應用即為 ZigBee)，主要為物聯網的低功耗設備設計。它規範了三個主要的免執照操作頻段。 【各選項解析】

  • ❌ ②915MHz：這是定義給北美地區使用的頻段。
  • ❌ ③2.4GHz：這是全球通用的 ISM 頻段，為最主要的運作頻段。
  • ⭕ ④3GHz：正確選出。3GHz 頻段不包含在 802.15.4 的實體層規範之中。
