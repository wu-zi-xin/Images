CCNA MODULE 2 · 2.9 PRACTICE & LAB

基本交換器與終端設備設定
Basic Switch and End Device Configuration

本頁依你上傳的 2.9 課程影片與 Cisco Networking Academy 練習／Lab PDF 整理。重點是把一個兩台交換器、兩台 PC 的小型 LAN 從接線開始完成：設定靜態 IP、操作 Cisco IOS、設定 hostname、密碼、VLAN 1 SVI、MOTD、儲存設定，最後用 show 與 ping 驗證。

參考你提供的 HTML 模板影片＋PDF 整理詳細白話講解中英對照英文發音自適應圖解20 題測驗

1. 全章地圖：這一章到底在學什麼？

這個實作是一個最小型 LAN：兩台交換器 S1、S2，各接一台 PC。你要讓四個設備在同一個 IPv4 /24 網路裡可以互相通訊，並把交換器做成「有名字、有管理 IP、有基本存取保護、重開機後設定不會消失」的狀態。

① 建立實體連線

交換器彼此連線；PC 接到各自交換器。確認埠號與 Link LED。

② 建立邏輯位址

PC 的 NIC 與交換器 VLAN 1 SVI 都配置 192.168.1.0/24 內的唯一 IP。

③ 驗證與除錯

使用 show、ipconfig /all、ping 檢查設定、介面與端到端連線。

一句話記憶：「線要接對、IP 要同網段且不重複、介面要 Up、組態要存、最後一定要 Ping。」

2. 拓撲與位址規劃

依 2.9.2 Lab / Physical Mode：S1 F0/6 接 PC-A、S2 F0/18 接 PC-B、兩台交換器以 F0/1 互連。
設備 Device介面 InterfaceIPv4 位址子網路遮罩 Subnet Mask
S1VLAN 1192.168.1.1255.255.255.0 (/24)
S2VLAN 1192.168.1.2255.255.255.0 (/24)
PC-ANIC192.168.1.10255.255.255.0 (/24)
PC-BNIC192.168.1.11255.255.255.0 (/24)
白話：四個 IP 的前 24 位都一樣，所以它們都在 192.168.1.0/24 這個網路。這個拓撲沒有 Router，因此練習時 Default Gateway 可以先留白。

3. Part 1｜建立網路拓撲與接線

把 S1、S2 放到 Rack，兩台 PC 放到 Table，並開啟 PC 電源。
Physical Mode 的重點是你真的要找對實體埠，不是只看邏輯圖。
S1 F0/1 ↔ S2 F0/1：Copper Cross-Over。
PDF 指定在 Physical Mode 使用銅質交叉線。
S1 F0/6 ↔ PC-A FastEthernet0：Copper Straight-Through。
S2 F0/18 ↔ PC-B FastEthernet0：Copper Straight-Through。
看 Link Light。剛接上時可能先是琥珀色，約一段時間後轉綠，代表埠完成初始化並進入可轉送狀態。
考點：「某些 FastEthernet 介面 Up、某些 Down」最直接的原因通常是：Up 的埠有啟用且實際連到開機、正常的對端；Down 的埠沒有有效實體連線、對端關機、線路/埠錯誤，或介面被 shutdown。

4. Part 2｜設定 PC Hosts

PC-A

Packet Tracer：PC-A → Desktop → IP Configuration，輸入 192.168.1.10、遮罩 255.255.255.0。本拓撲沒有 Router，所以 Gateway 可留白。

PC-B

設定為 192.168.1.11 / 255.255.255.0。

驗證 PC 網卡

C:\> ipconfig /all

檢查 IP、Mask、NIC 資訊是否符合位址表。

測試 PC-A → PC-B

C:\> ping 192.168.1.11

教材範例為 4 封包送出、4 封包收到、0% loss。

Ping 成功代表什麼？至少代表來源主機 IP 設定、目標主機 IP 設定、途中 Layer 1/Layer 2 連線，以及 ICMP 往返路徑在這次測試中是可用的。

5. Cisco IOS CLI：先搞懂「模式」再背指令

看 Prompt 最快判斷自己在哪一層：>、#、(config)#、(config-line)#、(config-if)#。
Command-Line Interface｜命令列介面
CLI：用文字指令管理設備。
Privileged EXEC mode｜特權 EXEC 模式
Prompt 由 > 變 #；可執行更完整的 show / copy / configure 等命令。
Global configuration mode｜全域組態模式
進行 hostname、密碼、banner、介面等設備設定的入口。
Running configuration｜執行中組態
目前 RAM 裡正在生效的設定。

6. Part 3｜基本交換器設定：完整操作腳本

PDF 明確要求：Console 連線、命名交換器、密碼保護、MOTD、VLAN 1 管理位址、儲存、show 驗證。以下把這些要求對應成一組常用 Cisco IOS 指令，方便你實際操作與背考點。

教材密碼：本 Lab 使用 class 作為 privileged EXEC secret、cisco 作為 console password。這些只適合教學；實務環境不要使用弱密碼或共用密碼。

S1 參考設定

Switch> enable
Switch# configure terminal
Switch(config)# hostname S1
S1(config)# no ip domain-lookup
S1(config)# enable secret class
S1(config)# service password-encryption
S1(config)# line console 0
S1(config-line)# password cisco
S1(config-line)# login
S1(config-line)# exit
S1(config)# banner motd #Unauthorized access is prohibited.#
S1(config)# interface vlan 1
S1(config-if)# ip address 192.168.1.1 255.255.255.0
S1(config-if)# no shutdown
S1(config-if)# exit
S1(config)# end
S1# copy running-config startup-config

S2 差在哪裡？

把 hostname 改成 S2，VLAN 1 IP 改成 192.168.1.2/24；其餘本練習要求相同。

為什麼 no ip domain-lookup？

如果把打錯的字當成未知命令，IOS 可能嘗試做 DNS 查詢，讓你等一段時間。關掉不必要的 lookup，Lab 操作會更俐落。

為什麼要 service password-encryption？

教材要求「加密所有明文密碼」。這能避免某些 line password 直接以可讀文字顯示在組態中；但它不是現代強式密碼雜湊，不能把它當完整安全機制。

enable secret vs password

enable secret 用於保護特權 EXEC；console 的 password 則需搭配 login 才會在 console 登入時要求密碼。

MOTD Banner

Message of the Day｜每日訊息/登入警告用來顯示授權/未授權存取警語；教材要求配置適當的未授權存取警告。

SVI 是什麼？

Switch Virtual Interface｜交換器虛擬介面
二層交換器本身的實體 FastEthernet 埠主要拿來交換 Ethernet Frame，不是每一埠都像 Router 介面一樣配置 IP。為了「管理交換器」，我們把 IP 配在 VLAN 的虛擬介面（本 Lab 是 VLAN 1 SVI）。
常見陷阱：只輸入 interface vlan 1 與 IP，不代表 SVI 一定會立即 line protocol up。至少要確保 VLAN 存在、介面未 shutdown，而且通常需要該 VLAN 有至少一個有效的實體成員埠處於可運作狀態。

7. 驗證、儲存、Ping 與故障排除

必會的 show / save

S1# show running-config

看現在正在 RAM 裡生效的設定。

S1# show version

查看 IOS 版本與設備資訊。

S1# show ip interface brief

快速查看介面 IP、Status、Protocol。這是除錯非常高 CP 值的命令。

S1# copy running-config startup-config

把目前設定存進 startup configuration，避免重開機遺失。

Running-config 與 Startup-config

項目白話典型位置重開機後
running-config現在正在用的設定RAM沒有另存就會失去未儲存變更
startup-config開機時要載入的設定NVRAM保留並於開機時讀取

系統化 Ping 除錯圖

不要亂改設定。先定位故障層級，再動手。

為什麼 Ping 可能送不到？

  • PC IP / Subnet Mask 打錯，或兩台 PC 不在相同網段。
  • 兩台設備使用重複 IP。
  • 線插錯埠、線材錯、對端沒開機、實體介面 Down。
  • 交換器 VLAN / SVI 不在可運作狀態。
  • 若是跨網段環境，缺少正確 Default Gateway / Route；但本教材拓撲本身沒有 Router。
  • 實務環境還可能是防火牆或 ACL 阻擋 ICMP；這不是本 Lab 的核心設定，但要知道它是可能原因。

8. 影片中的測驗重點：由遮罩找 Network Address

影片最後的題目可見一題：使用 255.255.0.0 子網路遮罩時，IP 10.1.100.50 屬於哪個網路。答案是 10.1.0.0。

白話算法：255.255.0.0 = /16，表示前兩個 octet（10.1）是 Network 部分，後兩個 octet 是 Host 部分。找網路位址時把 Host 部分歸零：10.1.0.0。
IPMaskNetwork 部分Host 部分Network Address
10.1.100.50255.255.0.0 (/16)10.1100.5010.1.0.0
192.168.1.10255.255.255.0 (/24)192.168.110192.168.1.0
