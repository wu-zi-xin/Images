2.8.1 測試介面分配 (Test the Interface Assignment)

驗證設備介面與 IP 設定

在先前的單元中，我們透過設定交換器 (Switches) 和個人電腦 (PCs) 的 IP 位址來實現基本的連線能力。設定完成後，我們必須驗證這些設定是否正確生效。我們可以使用 ipconfig 檢查 PC 端的設定，並使用 show ip interface brief 指令檢查交換器的介面狀態。

命令列驗證 (Command Line Verification)
In the same way that you use commands and utilities like ipconfig to verify the network configuration of a PC host, you also use commands to verify the interfaces and addresses settings of intermediary devices like switches and routers.
中文解析
就像您使用 ipconfig 等指令和公用程式來驗證 PC 主機的網路設定一樣，您也需要使用指令來驗證交換器和路由器等中介設備 (intermediary devices) 的介面和位址設定。
交換器介面狀態檢查 (show ip interface brief)

在特權 EXEC 模式下，使用 show ip interface brief 指令是查看所有交換器介面狀態最快且最有用的方法。如果發現設定好的 VLAN 1 介面呈現 administratively down，代表該介面處於手動關閉狀態，必須進入設定模式將其喚醒。

show ip interface brief
顯示路由器或交換器上所有介面的摘要資訊 (包含 IP 位址與啟用狀態)。 在特權 EXEC 模式 (Privileged EXEC Mode) 下執行。
administratively down
代表介面處於「關機 (shutdown)」狀態。 這表示管理員必須手動將其啟用。
no shutdown
用來開啟/啟用介面的指令。 必須在全域設定模式下的介面設定模式 (Interface Configuration mode) 輸入。
指令 / 狀態 (Command/Status) 說明與解析 (Description)
show ip interface brief 顯示路由器或交換器上所有介面的摘要資訊 (包含 IP 位址與啟用狀態)。 在特權 EXEC 模式 (Privileged EXEC Mode) 下執行。
administratively down 狀態顯示欄位，代表介面處於「關機 (shutdown)」狀態。 這表示管理員必須手動將其啟用。
no shutdown 用來開啟/啟用介面的指令。 必須在全域設定模式下的介面設定模式 (Interface Configuration mode) 輸入。執行後狀態會轉為 'up'。

檢查與修復 VLAN 1 介面的終端機流程範例：

S1# show ip interface brief
Interface IP-Address OK? Method Status Protocol
Vlan1 192.168.1.2 YES manual administratively down down

! 發現 Vlan1 是關閉的，進入設定模式將其開啟
S1# configure terminal
S1(config)# interface vlan 1
S1(config-if)# no shutdown
%LINK-5-CHANGED: Interface Vlan1, changed state to up
S1(config-if)# end

S1# show ip interface brief
Interface IP-Address OK? Method Status Protocol
Vlan1 192.168.1.2 YES manual up up
💡 終端機小技巧：
在鍵盤上按下 Ctrl + C 可以快速退回特權 EXEC 模式 (Privileged EXEC Mode)；按下 方向鍵「上 (Up arrow)」 可以呼叫出剛才輸入過的指令歷史紀錄，節省重複打字的時間。

2.8.2 測試端對端連線 (Test End-to-End Connectivity)

使用 Ping 指令測試連通性

ping 指令可以用來測試本機與網路上或網際網路上其他設備的連線能力。它會發送 ICMP Echo Request 封包並等待對方的 Echo Reply 封包回覆。

典型的首次 Ping 回應
And you can see from the display that the first ping request timed out. However, I got successful replies for the last three. This response is typical when you're first testing a connection.
中文解析
您可以從顯示結果中看到，第一個 ping 請求逾時 (timed out)。然而，後面的三次都獲得了成功的回覆。當您「首次測試連線」時，這種回應是非常典型的 (因為設備可能正在進行 ARP 解析尋找 MAC 位址)。
雙向測試與防火牆阻擋 (Bidirectional Testing & Firewall)

在實際網路上工作時，養成「雙向測試」連線的習慣非常重要。如果可以從設備 A ping 通設備 B，但無法從設備 B ping 回設備 A，這通常表示存在防火牆問題。

防火牆阻擋 ICMP (Firewall Blocking)
It's also a good idea to test connectivity in the reverse direction... It's always a good idea to test connectivity in both directions when working on a real network because if you can ping from one device to another but not in the reverse direction, it usually indicates that there is an issue with your firewall.
中文解析
反向測試連線也是個好主意... 在真實網路上工作時，雙向測試連通性永遠是個好習慣。因為如果您能從一台設備 ping 通另一台，反方向卻不通，這通常指出您的防火牆設定有問題。
⚠️ Windows 防火牆預設行為：
在預設情況下，Windows 防火牆 (Windows Defender Firewall) 會阻擋所有外部進來的 ICMP Echo Requests (也就是 ping 的請求封包)。為了讓實驗室環境中的其他 PC 能夠成功 ping 通您的 Windows 主機，通常需要暫時關閉防火牆，或是在進階設定中允許 ICMPv4-In 規則。
PC-A> ping 192.168.1.2

Request timed out.
Reply from 192.168.1.2: bytes=32 time=1ms TTL=255
Reply from 192.168.1.2: bytes=32 time<1ms TTL=255
Reply from 192.168.1.2: bytes=32 time<1ms TTL=255

    Packets: Sent = 4, Received = 3, Lost = 1 (25% loss),

自我檢測：Verify Connectivity (翻轉卡片)

請試著回答以下問題，檢驗您對本章節 (Module 2.8) 結構與指令的掌握度。點擊卡片即可查看解答！

Q1. 檢查交換器介面

What command is highly useful for verifying the interfaces and IP addresses settings of a switch?

(哪一個指令非常適合用來驗證交換器所有介面的狀態與 IP 位址設定？)
👉 點擊翻開看解答
解答
show ip interface brief
解析：這是一個在特權模式下極常用的檢測指令，能快速列出所有介面的 IP、是否被分配，以及其實體層(Status)與資料鏈結層(Protocol)的運作狀態。
Q2. 介面關閉狀態

If a switch interface shows its status as "administratively down", what does this indicate?

(如果交換器的介面狀態顯示為 "administratively down"，這代表什麼意思？)
👉 點擊翻開看解答
解答
該介面處於手動關閉 (shutdown) 狀態
解析：這表示介面被設定了 shutdown，因此無法轉發流量。必須進入介面設定模式輸入 no shutdown 來將其喚醒 (state to up)。
Q3. 端對端連線測試

What command is primarily used to test end-to-end connectivity between devices on a network?

(主要用來測試網路上設備之間「端對端連線能力」的指令為何？)
👉 點擊翻開看解答
解答
ping
解析：Ping 指令利用 ICMP (網際網路控制訊息協定) 傳送 Echo Request，若對方有回應 Echo Reply，代表雙方 L3 網路層通訊正常。
Q4. Ping 的首次 Timeout

Why might the first ping request often result in a "Request timed out" when testing a connection for the very first time?

(為什麼在第一次 ping 某台設備時，第一個封包常常會出現 "Request timed out" 的結果？)
👉 點擊翻開看解答
解答
這是典型現象 (通常因為 ARP 查詢)
解析：影片中提到這是 typical response。背後原因是因為設備需要廣播 ARP 請求來解析目標 IP 的 MAC 位址，這段延遲常導致第一個 ICMP 封包逾時。
Q5. 單向 Ping 失敗原因

If PC-A can successfully ping PC-B, but PC-B fails to ping PC-A, what is the most likely cause of this issue?

(如果 PC-A 可以成功 ping 通 PC-B，但反向從 PC-B 卻無法 ping 通 PC-A，最可能的原因是什麼？)
👉 點擊翻開看解答
解答
防火牆 (Firewall) 阻擋了 ICMP
解析：Windows Defender 防火牆預設會阻擋外部進入的 ICMP Echo requests。因此 PC-A 發出的請求可以收到 B 的回覆，但 B 發給 A 的請求會被 A 的防火牆丟棄。
