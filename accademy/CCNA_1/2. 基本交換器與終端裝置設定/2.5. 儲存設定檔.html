1. 本段重點總覽

先把整支影片濃縮成四個問題。只要這四題能回答，你就掌握了 2.5 的骨架。

現在生效的是誰？Running-config。它是設備當下正在使用的設定。
重開後會讀誰？Startup-config。它是設備啟動時要載入的設定。
想保留變更？把 running-config 複製成 startup-config。
想捨棄變更？若尚未儲存，可用 reload 回到已儲存的狀態；重載時不要再把錯誤變更存起來。

2. 2.5.1 設定檔｜兩份設定到底差在哪？

Cisco IOS 設備最常考的觀念，就是 running-config 與 startup-config 的位置、用途與斷電後是否保留。

Running-config｜執行中設定

目前正在裝置上生效的設定。影片說明它位於 RAM 中，修改設定時會立即反映在 running-config。

  • 儲存位置：RAM
  • 是否立即生效：是
  • 重新啟動後：未儲存的變更可能消失
  • 查看：show running-config
Startup-config｜啟動設定

設備下一次開機時要讀取的設定。影片說明它儲存在 NVRAM，屬於非揮發性儲存。

  • 儲存位置：NVRAM
  • 主要用途：開機時載入
  • 斷電後：仍可保存
  • 查看：show startup-config
自製圖解：左邊是目前運作中的設定，右邊是下次開機的設定；儲存與開機的方向剛好相反。
show running-config
查看目前 RAM 內、正在生效的完整設定。
show startup-config
查看 NVRAM 中、下次開機會使用的設定。

4. 2.5.2 修改執行設定｜做錯了，怎麼回到原本狀態？

影片把情況分成兩種：變更「還沒存」與「已經存進 startup-config」。這兩種不能混為一談。

情況 A：錯誤變更尚未儲存

如果你改了 running-config，但還沒有把它存到 startup-config，可以用 reload 讓設備重新載入已儲存的啟動設定。

關鍵：reload 過程若詢問是否儲存目前變更，想丟掉錯誤設定時要選擇 no，否則錯誤設定反而會被保存。
情況 B：錯誤變更已經儲存

如果 startup-config 本身也已經被改壞，就不能只靠「重開讀回原設定」解決。影片示範了清除 startup-config，再重新載入。

S1# erase startup-config S1# reload
自製決策圖：先問「要不要保留」，再問「錯誤是否已存進 startup-config」。這比死背命令更容易避免做反。
reload 會中斷網路服務。影片明確提醒重新載入可能造成網路中斷；正式環境不能把 reload 當成隨手的 Undo 鍵。

5. 2.5.3 視訊實作｜畫面中的 CLI 在做什麼？

影片實作不是單純展示一條命令，而是把「儲存、查看 NVRAM、清除、重載、再設定、再回復」串成一段操作。以下依畫面順序拆解。

① 登入並進入 Privileged EXEC

畫面先出現 User Access Verification，輸入密碼後使用 enable 進入 # 提示字元。

② 進入設定模式並改 hostname

Switch# configure terminal Switch(config)# hostname S1 S1(config)# exit S1#

改 hostname 後，提示字元立即從 Switch 變成 S1，證明 running-config 的變更會立即生效。

③ 將 running-config 儲存為 startup-config

S1# copy running-config startup-config Destination filename [startup-config]? Building configuration... [OK]

④ 用 dir nvram: 查看 NVRAM

影片畫面可看到 startup-config 檔案出現在 NVRAM 目錄中，讓「startup-config 在 NVRAM」不只是背誦，而是能實際驗證。

⑤ 清除啟動設定並重新載入

S1# erase startup-config S1# reload

這一段用來示範當已保存的設定也不要了，如何移除啟動設定。

⑥ 重新設定 MySwitch、Console 密碼並儲存

Switch# configure terminal Switch(config)# hostname MySwitch MySwitch(config)# line console 0 MySwitch(config-line)# password cisco MySwitch(config-line)# login MySwitch(config-line)# exit MySwitch(config)# exit MySwitch# copy running-config startup-config

⑦ 再改成 S1，接著嘗試把 startup-config 複製回 running-config

影片最後用這個情境帶出一個非常重要的行為：copy 到 running-config 時是合併（merge），不是先把 running-config 清空再整份覆蓋。

6. 超重要考點：copy startup-config running-config 不是「完全還原」

影片後段的操作用來說明：把設定檔複製到正在運作的 running-config 時，IOS 會把內容合併進去。原本 running-config 中、而 startup-config 沒有明確移除的設定，不一定會被消掉。

Merge｜合併

把來源設定中的命令逐步套用到目前 running-config。它不像一般文字檔「整檔覆寫」。

為什麼不能當完整 Undo？

因為目前 running-config 可能已經多了額外命令；如果 startup-config 沒有對應的 no ... 去取消它，那些設定可能繼續留著。

白話：把 startup-config copy 到 running-config，比較像「把舊設定再貼一次進目前設定」，不是「把現在整張紙撕掉，再換成舊的那張」。想得到乾淨的開機設定狀態，通常是重新載入設備，讓它從 startup-config 重新建立 running-config。
課外補充
這個 merge 行為是 Cisco IOS 設定管理非常常見的觀念，也是故障排除時的重要差異。看到 copy startup-config running-config 不要自動翻譯成「rollback」。

7. 2.5.4 擷取設定至文字檔案｜PuTTY Session Logging

影片說明設定檔也可以保存成文字檔，方便備份、記錄與重複使用。示範工具是 PuTTY。

步驟 1｜開啟 PuTTY

先使用 PuTTY 連到設備。影片畫面顯示一般 Session 頁面，可選 SSH、Serial 等連線方式。

步驟 2｜進入 Session → Logging

在左側選單開啟 Logging，選擇 All session output，並指定 log file name。

步驟 3｜輸出設定

連線後執行例如 show running-config；因為終端畫面全部被記錄，設定內容就會寫入文字記錄檔。

步驟 4｜停止記錄

影片最後把 Session logging 改回 None，停止把後續工作階段輸出寫進記錄檔。

自製圖解：Logging 記錄的是終端機工作階段輸出，所以先開 Logging，再執行 show 指令。
安全提醒：文字記錄可能包含 hostname、IP、使用者名稱、雜湊或其他敏感設定。保存與分享前要先檢查內容，不要把正式環境設定直接公開貼出。

9. Part 1｜Verify the Default Switch Configuration

第一部分不是急著改設定，而是先進入 Privileged EXEC，觀察設備目前長什麼樣。

Step 1｜進入 Privileged EXEC Mode
Switch> enable Switch#

提示字元由 > 變成 #。PDF 強調：Privileged EXEC 可存取更多命令，而且因為其中包含會改變運作參數的命令，因此應該以密碼保護。

Step 2｜檢查目前設定
Switch# show running-config

先讀預設 running-config，再回答介面數量、VTY line 範圍、NVRAM 內容等觀察題。

PDF 有幾題是「Packet Tracer 實機觀察題」：例如 FastEthernet / GigabitEthernet 數量、VTY line 範圍。文件本身留白要你在 Packet Tracer 觀察後填入，所以本講義不把未在 PDF 直接給出的數字假裝成文件原文答案。
PDF 要你思考的關鍵題：
  • 哪一條命令可以查看 NVRAM 目前的內容？
  • 為什麼設備可能回覆 startup-config is not present？

第二題的核心觀察是：這台交換器目前尚未存在已保存的 startup-config；文件要求你透過實作情境理解原因。

10. Part 2｜Create a Basic Switch Configuration

第二部分開始正式設定 S1。PDF 特別要求你注意：隨著模式切換，提示字元也會跟著改變。

Step 1｜設定交換器名稱

Switch# configure terminal Switch(config)# hostname S1 S1(config)# exit S1#

hostname S1 執行後，prompt 立即改成 S1，方便管理者辨認目前操作的是哪台設備。

Step 2｜保護 Console Line

S1# configure terminal S1(config)# line console 0 S1(config-line)# password letmein S1(config-line)# login S1(config-line)# exit S1(config)# exit

PDF 指定 Console 密碼為 letmein。其中 password 是設定密碼值，而 login 是要求該 line 在使用者連入時執行密碼驗證。

Step 3｜驗證 Console 真的有被保護

S1# exit Switch con0 is now available Press RETURN to get started. User Access Verification Password: S1>

PDF 明確提醒：如果沒有出現 Password 提示，通常代表前一步漏了 login。

自製圖解：PDF 的重點不是只背 password，而是理解「line console 0 → password → login」的模式與邏輯。

11. Privileged EXEC 密碼、安全性與加密

PDF 從比較弱的 enable password 開始，再帶到較新的 enable secret，最後使用 service password-encryption 處理其他純文字密碼。

Step 4｜enable password
S1(config)# enable password c1$c0

PDF 指定密碼是 c1$c0，其中最後的 0 是數字零，不是大寫 O。

Step 6｜enable secret
S1(config)# enable secret itsasecret

PDF 說明：若 enable password 與 enable secret 同時存在，進入 Privileged EXEC 時要使用 enable secret。

Step 8｜service password-encryption
S1(config)# service password-encryption

PDF 前面觀察到 console 與 enable password 是 plain text，因此再用這個命令把這些明文密碼加密顯示。

一定要分清楚：enable secret 本身就以不同形式儲存在設定中；service password-encryption 則是文件用來處理其他原本會以 plain text 顯示的密碼。
PDF 的安全性理由
文件指出，如果 console 與 enable password 直接以明文出現在 running-config，旁人偷看畫面或取得備份設定檔，就可能構成安全風險。

12. Part 3｜Configure a MOTD Banner

MOTD = Message of the Day。它讓任何登入交換器的人在進入時看到指定訊息，也可用來警告未授權使用者禁止存取。

S1# config t S1(config)# banner motd "This is a secure system. Authorized Access Only!" S1(config)# exit
什麼時候顯示？

PDF 的描述是：任何登入交換器的人都會看到這類訊息。

為什麼要有？

PDF 明確提到這類 Banner 可警告 unauthorized users（未授權使用者）禁止存取。

語法：文件說 Banner 文字可以放在 quotation marks（引號）中，或使用一個不會出現在 MOTD 內容本身的 delimiter（分隔符號）。

14. Part 5｜Configure S2

最後一部分不再逐條教你，而是要求把前面 Part 1～4 的能力自己套用到第二台交換器 S2。這就是「從照著做」進到「能獨立完成」。

  4. Enable secret：itsasecret

8. 實務工作流程｜把影片觀念變成可以真的照做的 SOP

以下是根據影片核心觀念整理出的安全操作順序；這一段屬於補充，不是影片逐字內容。

補充整理
  1. 先看現況：show running-config、必要時也看 show startup-config。
  2. 做變更：一次改少量，避免同時改太多造成問題難定位。
  3. 立即驗證：確認設定是否真的達成目的。
  4. 變更正確才存：copy running-config startup-config。
  5. 如果錯而且還沒存：先判斷能否用 no 命令修正；若要整體回到已存狀態，可安排 reload。
  6. 如果需要留紀錄：使用終端機 Logging 或其他受控方式保存變更前後的文字紀錄。

9. 常見錯誤與 CCNA 易考陷阱

錯誤 1｜以為設定會自動永久保存

CLI 命令生效不代表已寫入 startup-config。重開後才發現設定消失，是最典型失誤。

錯誤 2｜想丟掉變更，reload 時卻按 Yes 儲存

這會把原本想捨棄的 running-config 保存起來，目的完全相反。

錯誤 3｜把 copy startup run 當成完整覆蓋

它是 merge。現有 running-config 裡的額外設定可能仍然存在。

錯誤 4｜混淆 RAM 與 NVRAM

Running-config → RAM；Startup-config → NVRAM。這組對應一定要熟。

錯誤 5｜只背縮寫，不知道完整命令

copy run start 很方便，但要能還原成完整語意，才不會換情境就看不懂。

錯誤 6｜Logging 完就忘了關

長時間記錄可能累積敏感資訊與大量輸出。完成後應停止記錄並妥善保存檔案。
