1. 本課總覽：先把交換器「命名、上鎖、公告、驗證」

這六件事就是 2.4 的主線。

① 命名用清楚的 hostname 辨識設備。
② Console 保護限制坐在設備前、直接接線的人。
③ 特權模式保護用 enable secret 守住高權限。
④ VTY 保護限制 Telnet / SSH 遠端登入。
⑤ 加密＋Banner避免設定檔明文暴露，並顯示警告訊息。
⑥ 驗證用 show running-config 檢查結果。
影片章節架構：2.4.1 設備名稱 → 2.4.2 選擇密碼指引 → 2.4.3 設定密碼 → 2.4.4 密碼加密 → 2.4.5 標語訊息 → 2.4.6 安全管理存取視訊 → 2.4.7 基本裝置設定語法檢查。

2. 2.4.1 設備名稱（Hostname）

如果每台交換器都只叫 Switch，遠端管理時很容易連錯、改錯。

課程中的命名原則
  • 以字母開頭。
  • 不包含空格。
  • 以字母或數字結尾。
  • 使用字母、數字與破折號。
  • 長度小於 64 個字元。
白話理解

名稱最好能讓你直接看出位置或用途。例如 Sw-Floor-1、Sw-Floor-2、Sw-Floor-3，比全部叫 Switch 清楚很多。

圖解：同一棟樓的交換器，用樓層命名最直觀
Sw-Floor-3
Sw-Floor-2
Sw-Floor-1
管理者連到哪一台，一眼就看得出來

清楚命名可以降低 SSH / Console 管理時選錯設備的風險，也讓紀錄與故障排查更容易。

這張圖重做成純 CSS 響應式版，手機上會改成上下排列，不會再出現文字互相蓋住。
Switch# configure terminal
Switch(config)# hostname Sw-Floor-1
Sw-Floor-1(config)#
看到 Prompt 從 Switch(config)# 變成 Sw-Floor-1(config)#，代表 hostname 已立即套用。

3. 2.4.2 選擇密碼指引（Password Guidelines）

課程特別提醒：弱密碼或容易猜到的密碼，仍是常見安全風險。

比較好的做法
  • 長度超過 8 個字元。
  • 混合大小寫、數字、特殊字元。
  • 不同設備不要全部使用相同密碼。
  • 避免常見單字與容易猜到的內容。
課堂密碼 ≠ 正式環境密碼

Lab 會使用 cisco、class 等簡單密碼，目的是方便教學。課程畫面也明確提醒，這些密碼不適合商業環境。

5. 2.4.4 密碼加密（Password Encryption）

目標是避免設定檔直接出現容易看懂的明文密碼。

設定
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# service password-encryption
它不是什麼？

課程內容說明這個命令是加密設定檔裡的密碼，不代表它會保護「網路傳輸中的密碼」。遠端安全傳輸是另一個層次的議題。

用 show running-config 驗證
Sw-Floor-1# show running-config
!
line con 0
 password 7 094F471A1A0A
 login
!
line vty 0 4
 password 7 094F471A1A0A
 login
畫面中原本的 cisco 不再直接顯示，而會看到 password 7 ... 之類的形式。

6. 2.4.5 標語訊息（Banner MOTD）

Banner 是登入前的警告牌，提醒使用者這是受管制的設備。

命令格式
banner motd #Authorized Access Only#

# 是分隔符號（delimiter），前後必須對應，而且分隔符號不要出現在訊息內容裡。

MOTD 是什麼？

Message of the Day。可以理解成「登入前的公告 / 警示訊息」。課程範例使用 Authorized Access Only。

登入前會先看到的警示
*** Authorized Access Only ***
Unauthorized access is prohibited.
Banner 的重點是清楚、可讀，不需要塞太多文字。

7. 2.4.6 視訊：交換器的安全管理存取

影片把前面分開學的指令串成一套完整流程。

進入命令列並命名設備：先設定清楚的 hostname。
保護 Console：設定 console password 並啟用 login。
保護高權限模式：設定 enable secret。
保護遠端 VTY：設定 line vty 0 15、password、login。
加密明文密碼：使用 service password-encryption。
加入 Banner：設定登入前的警告訊息。
驗證變更：用 show running-config 查看設定。

8. 2.4.7 語法檢查：基本裝置設定 Lab

這是整課最值得保留的一段「標準流程骨架」。

Lab 目標
  • 指定裝置名稱。
  • 保護使用者 EXEC 模式存取。
  • 保護特權 EXEC 模式存取。
  • 保護 VTY 存取。
  • 加密所有明文密碼。
  • 顯示登入標語。
建議記憶順序

Hostname → Console → Enable Secret → VTY → Password Encryption → Banner → Verify

考題若寫「完成交換器基本安全設定」，腦中就先跑這個順序。
Switch# configure terminal
Switch(config)# hostname Sw-Floor-1

Sw-Floor-1(config)# line console 0
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# exit

Sw-Floor-1(config)# enable secret class

Sw-Floor-1(config)# line vty 0 15
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# exit

Sw-Floor-1(config)# service password-encryption
Sw-Floor-1(config)# banner motd #Authorized Access Only#
Sw-Floor-1(config)# end
Sw-Floor-1# show running-config

9. 驗證與儲存：做完設定，不代表工作完成

課程影片明確示範用 running-config 驗證；下面的「儲存」是實務上很重要的補充。

課程內容：驗證
show running-config

確認 hostname、enable secret、line console、line vty、service password-encryption、banner 是否真的存在。

額外補充：儲存
copy running-config startup-config

把目前正在執行的設定保存成下次開機要載入的設定。

來源區分：show running-config 是本課影片內容；copy running-config startup-config 是為了實務理解而額外補充，不是用來取代影片的原始教學順序。

English中文白話解釋
Hostname 主機名稱設備在 CLI 裡的識別名稱。
Console 主控台直接接線到設備的本機管理入口。
User EXEC Mode 使用者 EXEC 模式較低權限，常見 Prompt 為 >。
Privileged EXEC Mode 特權 EXEC 模式高權限管理模式，常見 Prompt 為 #。
Enable Secret 特權模式密碼保護進入高權限模式。
VTY / Virtual Terminal 虛擬終端線路用於 Telnet / SSH 遠端登入。
Password Encryption 密碼加密避免設定檔直接顯示明文密碼。
Banner MOTD 每日訊息標語登入前的公告或警示。
Running Configuration 執行中組態目前設備正在使用的設定。
Startup Configuration 啟動組態設備下次開機會載入的設定。
