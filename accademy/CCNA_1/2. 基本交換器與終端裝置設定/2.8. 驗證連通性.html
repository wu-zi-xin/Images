CCNA MODULE 2 · 2.8 VERIFY CONNECTIVITY

驗證連通性
Verify Connectivity

網路設定完不代表一定能通。這一段的核心，就是學會用幾個最基本、最常用的工具去回答三個問題：介面有沒有啟用？IP 位址有沒有配對？兩端到底能不能互相到達？

影片畫面整理Packet TracerCLI 指令拆解中英對照＋發音互動模擬手機友善16 題測驗

1. 本段在學什麼？

影片的流程很實務：先檢查介面與位址，再用 ping 驗證端對端連通性。

Step 1｜看位址PC 用 ipconfig；交換器用 show ip interface brief。
Step 2｜看狀態確認介面是不是 up/up，避免因關閉或線路問題造成中斷。
Step 3｜逐段 ping先測自己附近的裝置，再測較遠端的主機。
Step 4｜判讀結果Reply 代表收到回應；Request timed out 代表這次沒有收到回覆。
白話記法：先確認「我自己設定對不對」，再確認「線有沒有通」，最後才確認「遠方那台找不找得到」。

2. 影片中的實驗拓樸與位址

影片畫面顯示兩台交換器與兩台 PC，位於同一個 192.168.1.0/24 網段。

依影片畫面重畫的拓樸示意。位址與介面標示以影片可辨識內容為準。
同網段的意義四個位址都在 192.168.1.0/24。在這個實驗裡，它們可以透過第 2 層交換器直接互通，不需要經過路由器。
為什麼交換器也有 IP？第 2 層交換器的 IP 通常配在 SVI（Switch Virtual Interface，交換器虛擬介面），主要供管理與測試，不是每個實體埠各配一個管理 IP。

3. 2.8.1 測試介面指派

影片先從 PC 連到交換器主控台，再進入 CLI 檢查與啟用 SVI。

① Console 連線
PC 透過 console cable 連到交換器。
→
② Terminal
開啟終端模擬程式並接受預設參數。
→
③ enable
進入 Privileged EXEC mode。
→
④ config mode
進 Global Configuration Mode。
→
⑤ no shutdown
在 VLAN 1 介面上解除管理性關閉。
影片中可辨識的 CLI 流程
S1> enable
S1# configure terminal
S1(config)# interface vlan 1
S1(config-if)# no shutdown

%LINK-5-CHANGED: Interface Vlan1, changed state to up

訊息中的 changed state to up 表示介面與線路協定狀態已經變為啟用。

4. 兩個一定要會的檢查指令

PC：ipconfig

用來查看 PC 的 IPv4 位址、子網路遮罩等基本 IP 設定。影片說明它就像先確認「我自己的門牌有沒有填對」。

C:\> ipconfig
交換器：show ip interface brief

快速列出各介面的 IP Address、Status 與 Protocol。比逐一進每個介面查看快很多。

S1# show ip interface brief
欄位英文白話解釋
InterfaceInterface你正在看的哪一個介面，例如 FastEthernet0/6、Vlan1。
IP-AddressIP Address該三層介面目前使用的 IP 位址；實體 switchport 常顯示 unassigned。
StatusStatus偏向實體／管理層面的介面狀態。
ProtocolProtocolLine protocol 狀態，代表資料鏈路層是否可運作。

5. up / down 到底怎麼看？

影片畫面中 VLAN1 先出現 administratively down/down，執行 no shutdown 後變成 up/up。

up / up介面可用，line protocol 也可用。這是最理想的狀態。
down / down通常表示實體連線沒有起來，例如線沒接、對端關閉等。
administratively down / down代表介面被人為用 shutdown 關閉；要用 no shutdown 開啟。
CCNA 判讀習慣：先看 Status，再看 Protocol。不要只看到一個 up 就以為一定能通。

6. 2.8.2 測試端對端連通性：ping

影片接著使用 ping，從 PC-A 測試交換器與另一台 PC 的連通性。

ping 是最常見的網路基本測試工具。它會送出 ICMP Echo Request，若對方可達並允許回應，便收到 ICMP Echo Reply。

C:\> ping 192.168.1.2
C:\> ping 192.168.1.3
C:\> ping 192.168.1.11
影片示範順序：先 ping S1 的管理位址 192.168.1.2，再測 S2 的 192.168.1.3，最後測 PC-B 的 192.168.1.11。這種「由近到遠」的測試方式很適合故障排除。
ping 的概念圖：請求去、回應回。中間的交換器負責轉送乙太網路訊框。

7. 為什麼第一次 ping 可能先出現逾時？

影片畫面中第一次測試 192.168.1.2 時，先出現一個 Request timed out，之後其餘回覆成功。這在區域網路剛開始通訊時很常見。

重要補充（非影片文字逐字內容）
常見原因是 ARP 解析。PC 在真正把 ICMP 封包送給同網段目的地之前，必須先知道對方 IP 對應的 MAC 位址。如果 ARP 快取還沒有資料，就要先送 ARP Request、等 ARP Reply；這個過程有時會讓第一個 ping 逾時。完成 ARP 後，後面的 ping 往往就正常。
① 我只知道 IP
例如 192.168.1.2
→
② ARP Request
「誰是 192.168.1.2？」
→
③ ARP Reply
對方回覆自己的 MAC
→
④ ICMP ping
有了 MAC，就能封裝並送出

9. CCNA 很重要的補充觀念

補充 1
ping 通 ≠ 所有服務都正常。
ping 主要測 ICMP 與基本 IP 可達性。Web、SSH、DNS 等服務還牽涉 TCP/UDP 連接埠與應用程式本身。
補充 2
同網段與跨網段的排錯順序不同。
同網段先看 ARP、VLAN、交換埠；跨網段還要看 Default Gateway 與路由。
補充 3
169.254.x.x 是警訊。
若主機本來應該透過 DHCP 取得位址，卻拿到 APIPA 位址，常代表 DHCP 沒成功。
補充 4
IPv6 常用 ping 也能測。
概念相同，但鄰居解析使用 NDP 而不是 IPv4 的 ARP。
