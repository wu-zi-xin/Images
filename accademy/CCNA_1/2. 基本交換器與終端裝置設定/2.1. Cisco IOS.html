Operating Systems, CLI, Access Methods & Terminal Emulators

2. 2.1.1 作業系統｜Operating System (OS)

所有終端裝置與網路裝置都需要作業系統。影片用「硬體 → 核心 → 外殼 → 使用者介面」來解釋它們彼此的關係。

圖解重點：Kernel 直接和硬體互動；Shell 提供使用者與系統互動的方式；CLI 與 GUI 都可視為使用者介面。
Hardware｜硬體真正執行運算與收發資料的實體元件，例如 CPU、記憶體、儲存裝置與網路介面。
Kernel｜核心作業系統最核心的部分，直接和硬體互動，管理硬體資源並滿足軟體需求。
Shell｜外殼讓使用者與系統溝通的介面層。影片指出可透過 CLI 或 GUI 發出請求。
白話：把電腦想成一家餐廳：硬體是廚房設備，Kernel 是廚房主管，Shell 是服務生；你（使用者）不需要直接碰爐子，只要透過 GUI 或 CLI 告訴系統「我要做什麼」。

3. 2.1.2 GUI 與 CLI｜兩種操作介面

影片以 Windows、macOS、Linux KDE、Apple iOS、Android 為 GUI 例子，也特別指出：網路設備通常仍偏向 CLI，因為 GUI 不一定提供 CLI 的所有能力。

GUI｜Graphical User Interface｜圖形化使用者介面
  • 用視窗、按鈕、選單、圖示操作。
  • 入門直覺，通常不需要先記住大量文字命令。
  • 適合一般使用者與常見操作。
  • 但某些網路設備 GUI 可能沒有 CLI 的完整功能。
CLI｜Command-Line Interface｜命令列介面
  • 在提示字元後輸入文字命令。
  • 系統通常回傳文字輸出。
  • 資源負擔通常較低，適合精準、快速的管理工作。
  • 缺點是使用者必須懂命令結構與語法。
影片的關鍵提醒：GUI 可能失敗、當機、凍結，或根本無法指定你要的精確操作。因此網路設備通常仍透過 CLI 存取；相較 GUI，CLI 的資源需求較低且通常較穩定。
額外補充
CCNA 不要求你「反 GUI」，而是要理解 CLI 的角色：網路工程常需要大量、精確、可重複的操作，CLI 更容易搭配文件、腳本與遠端管理流程。

4. 2.1.3 作業系統的用途｜PC OS vs Network OS

影片把一般 PC 的 GUI 操作和網路設備的 CLI 操作放在一起比較，目的不是說兩者完全不同，而是讓你知道「管理網路設備時最常接觸的介面」是哪一種。

一般 PC OS 常見操作
  • 使用滑鼠選取與執行程式。
  • 輸入文字與文字命令。
  • 在顯示器上檢視輸出。
以 CLI 為基礎的 Network OS 常見操作
  • 用鍵盤執行 CLI 型網路程式。
  • 以文字方式輸入命令。
  • 在顯示器或終端機中檢視文字輸出。
影片內容
思科網路裝置會執行特定版本的 Cisco IOS；使用哪個 IOS 版本，取決於設備型號與所需要的功能。影片並以 Cisco Catalyst 2960 交換器的 IOS 軟體下載頁面為例。

6. 2.1.4 存取方法｜How to Access Cisco IOS

影片列出三種主要方法：Console、SSH、Telnet；另外備註某些設備也可能有 AUX 連接埠。

自製比較圖：把「IP 是否已可用」與「是否加密」拉成最容易記的判斷軸。
方法是否需要已可用的 IP 網路是否加密典型用途
Console否不屬於 IP 遠端傳輸初始設定、故障、網路尚未可達
SSH是是安全的遠端 CLI 管理
Telnet是否舊式遠端 CLI；不建議正式環境使用

7. Console｜主控台連線：設備還沒上網也能管

影片把 Console 描述為 Cisco 裝置帶外存取（out-of-band access）的實體管理連接埠。

不需要網路服務設備就算還沒有設定 IP，或現有網路故障，也能透過 Console 進行管理。
需要實體連接電腦必須透過適當的 Console 連接線接到設備，並使用終端機模擬程式。
常用於初始設定剛開箱的交換器／路由器還沒有遠端管理條件時，Console 是最可靠的起點。
額外補充
Out-of-band management｜帶外管理的核心意思是「管理通道不依賴平常承載使用者資料的生產網路」。這也是為什麼在網路壞掉時，Console 仍有價值。

8. SSH 與 Telnet｜都能遠端，但安全性完全不同

兩者都可以透過網路建立遠端 CLI 連線，但 SSH 會加密，Telnet 不會。

SSH｜Secure Shell｜安全殼層

影片說明 SSH 是建議的遠端管理方式，透過虛擬介面在網路中建立遠端安全 CLI 連線；使用時，設備上必須有已啟用且已設定位址的介面。

考題關鍵字：secure、encrypted、remote management → SSH。
Telnet｜遠端終端協定

也是帶內（in-band）管理方式，但不提供安全加密。使用者名稱、密碼與連線內容可能以明文方式傳送。

考題關鍵字：plaintext / not secure → Telnet。
影片明確建議：大多數情況下，應使用 SSH 代替 Telnet。

9. 2.1.5 終端機模擬程式｜Terminal Emulator

你需要一個程式在電腦上顯示終端視窗，才能透過 Console 序列連線或 SSH／Telnet 連線來操作網路設備。

PuTTY影片展示的免費常見工具，可選 SSH、Telnet、Serial 等連線類型。
Tera Term影片列出的另一個終端機模擬程式。
SecureCRT影片列出的商用終端機工具之一。
影片內容
終端機模擬程式可透過主控台連接埠的序列連線，或透過 SSH／Telnet 連線來連線網路裝置；這些程式也能調整視窗大小、字型大小、配色方案等，提高工作效率。
容易搞混的地方：PuTTY 是「客戶端工具」，Cisco IOS 才是設備上的作業系統。

10. 一張決策流程：到底該用哪一種存取方式？

設備目前可透過 IP 網路到達嗎？
不行或尚未設定 → 優先想 Console。
如果可以遠端，是否要求安全？
正常答案幾乎都是「要」 → 使用 SSH。
如果題目提到明文、不安全？
那通常是在描述 Telnet，並考你為何不建議使用。
超短版口訣：「沒 IP 用 Console；有 IP 遠端用 SSH；Telnet 只拿來認出它不安全。」

11. CCNA 考點補充：影片沒有展開，但很重要

以下內容是我為了幫你把概念接到後續 CLI 章節而補充，並非影片逐字內容。

補充 1
Console 與 SSH 的先後關係
初次部署時常先用 Console 做基本設定；等設備已有管理 IP、帳號與 SSH 條件後，再改用 SSH 遠端管理。
補充 2
Terminal Emulator ≠ Protocol
PuTTY 是程式；SSH / Telnet 是連線協定／方式；Console 是實體管理連線方式。考題常故意把這些類型混在一起。
補充 3
In-band vs Out-of-band
SSH／Telnet 通常走生產 IP 網路，是 in-band；Console 不依賴該 IP 網路，是 out-of-band。
補充 4
CLI 為什麼重要
後續你會看到大量 IOS 模式、命令結構、設定與驗證。先把 CLI 當成「管理語言」而不是黑色視窗，會比較不容易害怕。
