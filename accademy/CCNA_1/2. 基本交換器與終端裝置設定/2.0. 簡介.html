2. 2.0.1 我為什麼要參加這個模組？

影片的核心理由很實際：不論你是建立新網路，還是維護、升級既有網路，都會碰到交換器與終端裝置。設備剛開箱時只有一般預設值，但真正上線前必須依你的網路需求做設定。

建立新網路｜Build a New Network新的交換器、PC 或其他終端裝置，不會自動知道你的命名規則、管理位址、密碼與網路參數。
維護既有網路｜Maintain an Existing Network網路變更、設備替換、故障排除或擴充時，都需要能讀懂並修改現有設定。
把預設值變成可用設定｜Initial Configuration開箱即用只代表能開機，不代表已符合你的安全、管理與通訊需求。
白話：交換器就像一台剛拿到的新手機：會開機不等於已經設定完成。你還是要設定名字、安全密碼、網路位址與其他參數，才真正適合放進你的環境。
影片特別帶出的觀念：網路管理還有更多進階功能，但前提是先把交換器與終端裝置的基本設定做好；基本設定是後續所有管理工作的地基。

5. 預習補充：Cisco IOS 與「如何存取設備」

以下開始是為了銜接後續課程的預習補充，不是這支 20 秒簡介影片逐項講解的內容。

Cisco IOS｜Cisco Internetwork Operating System思科路由器與交換器常見的網路作業系統。它提供 CLI，讓管理者檢視狀態、設定功能與排除問題。
Console｜主控台連線最典型的本機管理方式。設備還沒有 IP 或網路連線壞掉時，Console 特別重要。
SSH｜Secure Shell設備已有可達 IP 後，可透過網路進行加密遠端管理。正式環境通常優先選 SSH，而不是明文的 Telnet。
預習補充
考試思路：「第一次設定、還沒有管理 IP」常想到 Console；「遠端且要求安全」想到 SSH。這支影片只說「學會存取 Cisco IOS 裝置」，並沒有在畫面中細分這些方式。

6. 預習補充：IOS 導航與命令結構

Cisco IOS CLI 不是所有命令都能在任何地方輸入。不同模式代表不同權限與設定範圍。

修正版圖解：把 interface 標記放在 Interface Config 正上方，把 line 標記放在 Line Config 正下方，位置更直覺也更整齊。
Switch> enable
Switch# configure terminal
Switch(config)# hostname SW1
SW1(config)# interface vlan 1
SW1(config-if)# exit
SW1(config)# end
SW1#
常見初學陷阱：不是命令打錯，而是「模式不對」。看到錯誤訊息時，先看提示字元自己現在在哪一層。

7. 預習補充：裝置基本設定

影片明確說本模組會「使用 CLI 設定 Cisco IOS 裝置」。常見入門設定會包含設備名稱與存取安全。

Hostname｜主機名稱

讓設備名稱有辨識度，比所有交換器都叫 Switch 更容易管理。

Switch(config)# hostname SW1
SW1(config)#
Password / Secure Access｜密碼與安全存取

不同課程段落可能會設定 enable secret、console line、VTY line 等。核心概念是限制未授權管理存取。

SW1(config)# enable secret password
理解比死背重要：「名稱」解決辨識，「密碼／驗證」解決管理安全。命令細節會在後續章節逐步加入。

8. 預習補充：為什麼一定要儲存設定？

Cisco IOS 中，「目前正在生效」和「開機要讀取」通常是兩份不同概念的設定。

Running-config｜執行中設定目前在 RAM 中、立即生效的設定。修改命令通常直接改到這裡；斷電或重新啟動後，未保存的變更可能失去。
Startup-config｜啟動設定設備開機時要載入的設定，通常保存在非揮發性儲存區。要把目前成果留到下次開機，就要把 running-config 複製過去。
你輸入設定
立即改變 running-config
→
確認設定正確
先 show、測試、檢查
→
儲存
copy running-config startup-config
→
重開仍保留
開機時讀 startup-config
超常見失誤：設定做對、測試也成功，卻忘了 save。設備一重開，剛才的工作像沒發生過一樣。

9. 預習補充：連接埠、介面與位址

影片目標寫的是「說明裝置如何跨網路媒體進行通訊」。這裡要建立三個層次：實體媒體、介面、邏輯位址。

Media｜網路媒體銅線、光纖、無線等，負責實際承載訊號。
Port / Interface｜連接埠／介面裝置和媒體接上的位置；在 Cisco CLI 中常以 interface 進入特定介面設定。
Address｜位址用來識別通訊端點。IP 位址屬於 Layer 3 邏輯位址；乙太網路還會涉及 MAC 位址。

10. 預習補充：終端裝置的 IP 定址

影片畫面明確提到初始設定會包括「IP 位址和預設閘道參數」，而主題目標也包含「設定具有 IP 位址的主機裝置」。

修正版圖解：把 YES／NO 卡片和判斷菱形再拉開，並讓箭頭遠離文字，避免遮住「同網段？」與左右說明。
IP Address｜IP 位址辨識這台主機在 Layer 3 網路中的位址。
Subnet Mask / Prefix｜子網路遮罩／前綴告訴主機「哪些位址和我算同一個網段」。
Default Gateway｜預設閘道當目的地不在本地網段時，把封包交給能替你路由到其他網路的路由器介面。

11. 預習補充：驗證連通性不是最後才想起來

影片最後一個主題目標是「驗證兩個終端裝置之間的連線」。最常見的第一步工具就是 ping。

Ping｜連通性測試利用 ICMP Echo Request / Echo Reply 檢查 IP 層是否能互相到達。
成功 ≠ 全部都沒問題ping 成功代表基本 IP 可達性成立，但不代表 DNS、HTTP、SSH 等每一個應用都正常。
失敗也要逐層查先查本機 IP／遮罩，再查鏈路與介面，再查閘道與路由，不要一看到 timeout 就直接判斷「網路壞了」。
PC> ping 192.168.10.20
Reply from 192.168.10.20: bytes=32 time<1ms TTL=...
很實用的排錯順序：① 自己的 TCP/IP 設定 → ② 同網段鄰居 → ③ 預設閘道 → ④ 遠端 IP → ⑤ DNS 名稱。這能快速把問題範圍縮小。
