2. 2.3.1 基本 IOS 命令結構

影片先用 show ip protocols 與 ping 192.168.10.5 說明：IOS 命令通常由「提示字元 → 命令 → 空格 → 關鍵字或參數」組成。

依影片 2.3.1 概念重製：圖形重新排版，避免連線與文字互相遮擋。
Keyword｜關鍵字由 IOS 預先定義的固定字，例如 show ip protocols 裡的 ip protocols。你必須使用 IOS 認得的字。
Argument｜參數由使用者提供的值或變數，例如 ping 192.168.10.5 裡的目的 IP。它會依你的任務而變。
白話：「命令」像動詞，「關鍵字」像固定文法，「參數」像你自己填入的姓名、IP、介面編號。完整輸入後按 Enter，IOS 才會解析並執行。

3. 2.3.2 IOS 命令語法約定

文件裡的粗體、斜體、方括號與大括號不是裝飾，而是在告訴你「哪些字照打、哪些值自己填、哪些是選擇題」。

表示法意思怎麼讀
粗體 Bold輸入的命令與固定關鍵字。照文件顯示的字輸入。
斜體 Italic由使用者提供的參數。換成你實際要使用的值。
[x]可選元素。有需要才加。
{x}必要元素。不可省略。
[x {y | z}]方括號表示外層可選；大括號內為必要選項；垂直線 | 表示擇一。先判斷外層是否需要，再在 y/z 中選一個。
description stringdescription 是固定命令；string 是你自己輸入的描述文字。
例：description Connects to HQ switch
ping ip-addressping 是命令；ip-address 是目的裝置位址。
例：ping 10.10.10.5
traceroute ip-addresstraceroute 是命令；ip-address 由使用者指定。
例：traceroute 192.168.254.254
常見誤會：文件寫 ip-address 時，不是要你真的打出「ip-address」這幾個字，而是要換成實際位址。

4. 2.3.3 IOS 幫助功能

影片指出 IOS 有兩種非常重要的自救工具：上下文相關幫助（Context-sensitive Help）與命令語法檢查（Command Syntax Check）。

Context-sensitive Help｜上下文相關幫助可以回答「這個模式有哪些命令？」、「這個開頭能延伸成什麼命令？」以及「下一個參數該填什麼？」。
Command Syntax Check｜命令語法檢查按 Enter 後，IOS 會檢查輸入；若有錯，會回傳錯誤訊息，讓你知道是缺少、無效或模稜兩可。
三種最常用的「?」位置。注意 te? 中間沒有空格；clock ? 則是在完整命令後先打一個空格。

5. 2.3.4 上下文幫助與命令語法檢查

影片示範在 CLI 裡逐步查命令、Tab 補完，以及三種初學者一定會遇到的錯誤型態。

% Invalid input detected at '^' marker.^ 會指到 IOS 開始無法理解的位置。通常是拼字錯、語法錯、參數錯或命令不屬於目前模式。
% Ambiguous command你輸入的縮寫同時符合多個命令，IOS 無法判斷你要哪一個。多打一兩個字母再試。
% Incomplete command命令方向是對的，但少了必要的關鍵字或參數。最直接的做法是加一個空格再按 ?。
Switch(config)# interface 33
% Invalid input detected at '^' marker.

Switch(config)# i
% Ambiguous command: "i"

Switch(config)# interface
% Incomplete command.
Switch(config)# interface ?
Ethernet      IEEE 802.3
FastEthernet  FastEthernet IEEE 802.3
GigabitEthernet GigabitEthernet IEEE 802.3z
Port-channel  Ethernet Channel of interfaces
Vlan          Catalyst Vlans
range         interface range command
排錯口訣：先看 Prompt 判斷模式 → 看 ^ 指在哪 → 用 ? 看合法選項 → 若縮寫不唯一就多打幾個字母 → 再按 Enter。

6. 2.3.5 熱鍵和快捷方式

IOS CLI 可以接受「足夠唯一的命令縮寫」，也提供大量編輯快捷鍵。影片例子：configure 可縮寫成 conf，前提是此模式下它足以唯一識別該命令。

按鍵功能記憶方式
Tab補全已輸入且可唯一識別的命令。「幫我打完」
Backspace刪除游標左側的字元。一般文字編輯
Ctrl+D刪除游標所在的字元。D = Delete
Ctrl+K刪除從游標到命令列尾端的所有字元。砍掉後半段
Esc D刪除從游標到單字結尾。刪下一個 word
Ctrl+U 或 Ctrl+X刪除從游標到命令列開頭的字元。清前半段
Ctrl+W刪除游標左邊的單字。W = Word
Ctrl+A游標移到命令列開頭。A = 起點
← 或 Ctrl+B游標向左一個字元。B = Back
Esc B游標向左一個單字。Back one word
Esc F游標向右一個單字。Forward one word
→ 或 Ctrl+F游標向右一個字元。F = Forward
Ctrl+E游標移到命令列末尾。E = End
↑ 或 Ctrl+P叫出歷史記錄中前一個命令，從最近使用的往回找。P = Previous
Ctrl+R／Ctrl+I／Ctrl+L重新顯示系統提示字元與目前命令列（依 IOS/終端環境行為可能略有差異）。重畫命令列
輸出／模式控制作用
Enter在 --More-- 分頁時顯示下一行。
Space在 --More-- 分頁時顯示下一個畫面。
其他任意鍵結束分頁輸出並返回 EXEC 提示字元。
Ctrl+C在設定模式下中止目前操作並返回特權 EXEC；在 setup 模式中也可中止流程。
Ctrl+Z從任何設定模式直接結束設定並返回特權 EXEC。
Ctrl+Shift+6中止 DNS 查詢、traceroute、ping 等 IOS 處理序。
注意：一般鍵盤的 Delete 鍵在某些 IOS／終端環境下不一定像文字編輯器那樣工作；課程特別提醒要熟悉 IOS 支援的 CLI 編輯鍵。

8. EXEC 模式與 Global Configuration 模式

2.3.7 PDF 專門讓你比較 User EXEC、Privileged EXEC 與 Global Configuration。最簡單的辨識方法就是看提示字元最後長什麼樣子。

PDF 2.3.7 要求學員實際觀察 enable 後提示字元的變化，並進入 global configuration mode。
最常見新手錯誤：命令本身沒錯，但你在錯的模式下執行。遇到「Invalid input」時，先看左邊 Prompt，再決定要不要先 enable 或 configure terminal。

9. 2.3.7 Packet Tracer：Navigate the IOS

這份 4 頁 PDF 的目標分成三部分：建立基本連線、探索 EXEC 模式，以及利用 clock 命令練習 Help 與語法。

PART 1

連 Console、進 CLI、探索 Help

  1. 用淺藍 Console cable 連 PC1 RS-232 到 S1 Console。
  2. PC1 → Desktop → Terminal。
  3. 確認 Port Configuration 預設值。
  4. 看到 Press RETURN to get started! 後按 Enter。
  5. 在 S1> 輸入 ?、t?、te? 觀察可用命令。
PART 2

探索 EXEC Modes

  1. en<Tab> 觀察 Tab Completion。
  2. 輸入 enable，比較 Prompt 由 > 變成 #。
  3. 在特權 EXEC 再輸入 ?，觀察命令數量增加。
  4. 輸入 configure 並接受預設 [terminal]。
  5. 確認進入 S1(config)#。
PART 3

用 Clock 命令練習「不完整 → 問 ? → 逐段完成」

S1# show clock
S1# clock
% Incomplete command.
S1# clock ?
S1# clock set ?
S1# clock set 15:00:00 ?
<1-31> Day of the month
MONTH Month of the year
S1# clock set 15:00:00 31 Jan 2035
S1# show clock
環境差異：PDF 特別把這當成練習題；實際命令清單、可用縮寫與部分輸出可能會依 Packet Tracer／IOS 版本不同。觀念要學的是「使用 Help 確認當下設備真正接受什麼」。

10. 2.3.8 Console Connectivity：Tera Term 與 Packet Tracer Physical Mode

兩份 2.3.8 PDF 教的是同一件事：先建立「本機 Console 管理路徑」，再用終端模擬器進入 Cisco IOS。差別只是實體實驗用 Tera Term，PT Physical Mode 用 Packet Tracer 內建 Terminal。

依 PDF 2.3.8 兩種實作重繪：左側為 rollover serial console，右下補上 router mini-USB console。所有文字區塊分離，避免重疊。
Serial Console｜序列主控台交換器 RJ-45 Console ↔ PC serial COM；若電腦沒有 DB-9，PDF 建議可使用 USB-to-DB9 adapter。

11. Clock 命令：最適合練習語法與 Help 的範例

PDF 2.3.7 與兩份 2.3.8 都用 Clock 當練習。它很適合學語法，因為參數要按順序填，而且每一步都可以用 ? 問下一個格式。
