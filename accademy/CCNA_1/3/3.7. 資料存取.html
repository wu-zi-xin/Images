3.7.1 - 3.7.2 網址與第三層邏輯位址 (Addresses & Layer 3 Logical Address)

3.7.1 Addresses (位址的角色)

網路層 (Network Layer) 與資料鏈結層 (Data Link Layer) 負責將資料從來源設備傳送到目的設備。雖然兩層的協定都包含來源與目的位址，但它們的用途不同：

Network Layer Addresses (網路層位址 - IP)
Responsible for delivering the IP packet from the original source to the final destination, which may be on the same network or a remote network. 負責將 IP 封包從「最原始的來源 (Original Source)」傳遞到「最終目的地 (Final Destination)」。這兩端可以在同一個網路或不同的遠端網路上。
Data Link Layer Addresses (資料鏈結層位址 - MAC)
Responsible for delivering the data link frame from one network interface card (NIC) to another NIC on the same network. 負責將資料鏈結層的「影格 (Frame)」從同一個網路上的「一個網卡 (NIC)」傳送到「另一個網卡」。
3.7.2 Layer 3 Logical Address (第三層邏輯位址)

IP 位址是網路層的邏輯位址。一個 IP 位址包含兩個主要部分，並且可以透過子網路遮罩 (Subnet mask) 或前綴長度 (Prefix length) 來區分：

  • Network portion (IPv4) / Prefix (IPv6) 網路區段： IP 位址最左邊的部分，用來識別該 IP 位址所屬的網路。同一個網路上的所有設備都會有相同的網路區段。
  • Host portion (IPv4) / Interface ID (IPv6) 主機區段： IP 位址剩餘的部分，用來識別該網路中特定的設備。對網路上的每一個設備來說，這個部分都是唯一的。
💡 重要觀念：
IP 封包包含了「來源 IP 位址 (發送設備)」與「目的 IP 位址 (接收設備)」。這兩個位址可以幫助判定來源與目的地是否在同一個網路中。

3.7.3 - 3.7.4 同網段設備通訊 (Devices on the Same Network)

同網段通訊時的位址變化

當來源設備與目的設備在同一個 IP 網路時，資料鏈結層的影格會直接發送給接收設備。

Dest MAC: FTP Server
Src MAC: PC1
Src IP: 192.168.1.110
Dest IP: 192.168.1.9
Source MAC address (來源 MAC 位址)
發送設備 (PC1) 網卡的乙太網路 MAC 位址。這是將 IP 封包封裝進影格中的設備。
Destination MAC address (目的 MAC 位址)
當接收設備在同一個網段時，這會是接收設備 (FTP Server) 的 MAC 位址。
位址類型 說明 (Description)
Source MAC address 發送端設備的資料鏈結層 (乙太網路) MAC 位址。
Destination MAC address 當接收端位於同一網段時，此為接收端設備的 MAC 位址。
💡 資料封裝順序：
在 Ethernet Frame 中，Destination MAC (目的 MAC) 會放在 Source MAC (來源 MAC) 前面。這樣設計可以讓網卡在接收到影格的最開始，就能快速判斷這個影格是不是給自己的，藉此提升處理效率。

3.7.5 - 3.7.8 遠端網路通訊 (Devices on a Remote Network)

遠端網段通訊時的位址變化 (Hop-by-hop)

當發送端與接收端位於不同的 IP 網路時，乙太網路影格無法直接發送到目的主機。此時必須將影格送往「預設閘道 (Default Gateway)」，也就是路由器。

Dest MAC: Router R1
Src MAC: PC1
Src IP: 192.168.1.110
Dest IP: 172.16.1.99
  • 網路層位址 (IP)：
    在整個傳輸過程中，來源 IP (PC1) 與 目的 IP (Web Server) 保持不變 (不考慮 NAT 的情況)。它們負責端到端 (End-to-end) 的邏輯路由。
  • 資料鏈結層位址 (MAC)：
    由於 MAC 位址只能在同一個網段內傳輸，因此每經過一個路由器 (Router)，原有的 Ethernet 標頭都會被拆除，並換上新的來源 MAC 與目的 MAC。
💡 遠端傳輸中的 MAC 位址變化：
當封包從 PC1 傳送到遠端 Web Server 時：
1. PC1 到 Router R1: Dest MAC = R1 的介面 MAC。
2. Router R1 到 Router R2: Src MAC = R1 的出口 MAC，Dest MAC = R2 的介面 MAC。
3. Router R2 到 Web Server: Src MAC = R2 的出口 MAC，Dest MAC = Web Server 的 MAC。
結論： 資料鏈結層位址在每一站 (hop) 都會改變！

Q1. 不同網段的資料傳輸

True or false? Frames exchanged between devices in different IP networks must be forwarded to a default gateway.

(是非題：在不同 IP 網路的設備之間交換的影格，必須被轉發給預設閘道。)
👉 點擊翻開看解答
解答
True (正確)
解析：
因為資料鏈結層的廣播與 MAC 位址解析 (ARP) 只能在同一個區域網路 (LAN) 內運作。
如果目的地在不同網段，主機必須將 Frame 送交給「預設閘道 (Router)」，由路由器利用 IP 路由表進行跨網段傳輸。
Q2. IP 位址的結構識別

True or false? The right-most part of an IP address is used to identify the network that a device belongs to.

(是非題：IP 位址最右邊的部分，是用來識別設備所屬的網路。)
👉 點擊翻開看解答
解答
False (錯誤)
解析：
IP 位址是從左到右讀取的。「最左邊」(Left-most) 的部分才是用來識別網路 (Network Portion / Prefix)。
而「最右邊」的部分是用來識別該網路中的特定主機 (Host Portion / Interface ID)。
Q3. IPv4 網路區段判定

What is used to determine the network portion of an IPv4 address?

(什麼東西被用來決定 IPv4 位址中的網路區段 (Network portion)？)
👉 點擊翻開看解答
解答
Subnet mask (子網路遮罩)
解析：
設備會將 IPv4 位址與「子網路遮罩」進行二進制的 AND 邏輯運算 (Bitwise AND)。子網路遮罩為 1 的對應位元就是網路區段，為 0 的對應位元就是主機區段。
Q4. L2 與 L3 位址特性

Which of the following statements are true regarding network layer and data link layer addresses? (Choose three.)

(關於網路層位址與資料鏈結層位址，下列哪些敘述是正確的？請選三項)
👉 點擊翻開看解答
解答
1. Data link layer addresses are physical and network layer addresses are logical.
2. Network layer addresses are logical and data link addresses are expressed as 12 hexadecimal digits.
3. Network layer addresses are either 32 or 128 bits in length.
解析：
MAC (Data Link) 是硬體實體位址，長度為 48 bits，常以 12 個十六進位數字表示 (例如 AA-BB-CC-DD-EE-FF)。
IP (Network) 是邏輯位址，IPv4 是 32 bits，IPv6 是 128 bits。
Q5. Frame 標頭順序

What is the order of the two addresses in the data link frame?

(在資料鏈結層的影格中，兩個位址的排列順序是什麼？)
👉 點擊翻開看解答
解答
Destination MAC, source MAC
解析：
在 Ethernet Frame 中，「目的 MAC」會排在「來源 MAC」的前面。
這是一個針對硬體處理效率的設計。網卡 (NIC) 在接收訊號的第一時間讀到目的 MAC 後，就能立刻判斷這封包是不是給自己的。如果不是，就直接丟棄，不用浪費資源讀完剩下的資料。
Q6. 傳輸過程中的 MAC 變化

True or False? Data Link addresses are physical so they never change in the data link frame from source to destination.

(是非題：資料鏈結位址是實體位址，因此在從來源到目的地的過程中，它們在影格中永遠不會改變。)
👉 點擊翻開看解答
解答
False (錯誤)
解析：
這非常重要！IP 位址 (L3) 幾乎不會變，但 MAC 位址 (L2) 每一站 (Hop) 都會變。
當封包穿越路由器時，路由器會將舊的 L2 Frame 標頭拆掉，並根據下一個介面的網路類型，重新封裝上新的來源與目的 MAC 位址。
