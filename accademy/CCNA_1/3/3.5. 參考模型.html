3.5.1 分層模型的優點 (The Benefits of Using a Layered Model)

為何需要分層模型？

網路運作是複雜的概念。我們無法真正看到封包在真實網路中穿梭，因此使用「分層模型 (Layered Model)」能幫助我們將複雜的網路操作模組化，劃分為易於管理的階層，以利理解與設計。

  • 協助協定設計 (Assisting in protocol design)： 特定層次運作的協定具有定義好的資訊和介面，明確規範與上下層如何互動。
  • 促進市場競爭 (Fostering competition)： 由於介面標準化，來自不同供應商的設備或軟體產品能夠協同工作 (互通性)。
  • 防止技術變更的影響 (Preventing technology or capability changes)： 確保某一層的技術或功能改變時，不會影響到其上方或下方的其他階層。
  • 提供共通語言 (Providing a common language)： 為描述網路功能與能力提供了一致的專業術語與框架。
💡 兩大主要的網路參考模型：
網路界主要使用兩種分層模型來描述網路操作：
1. OSI 參考模型 (Open System Interconnection Reference Model)
2. TCP/IP 參考模型 (TCP/IP Reference Model)

3.5.2 OSI 參考模型 (The OSI Reference Model)

OSI 的 7 層架構

OSI 模型提供了每一層可能發生的功能與服務的詳盡列表。它描述了各層與其上下層互動的方式，但並沒有規定必須如何達成 (它是一個參考模型)。

OSI 模型層級 說明 (Description)
7 - Application
(應用層)		 Contains protocols used for process-to-process communications. (包含用於行程對行程通訊的協定，是與使用者應用程式互動的介面。)
6 - Presentation
(展示層)		 Provides for common representation of the data transferred between application layer services. (確保資料格式轉換、加密與壓縮，讓應用層服務能看懂彼此傳輸的資料。)
5 - Session
(會議層/會話層)		 Provides services to the presentation layer to organize its dialogue and to manage data exchange. (提供服務給展示層，用來建立、管理及終止端點之間的對話或資料交換。)
4 - Transport
(傳輸層)		 Defines services to segment, transfer, and reassemble the data for individual communications between the end devices. (負責將資料分段、傳輸與重組，處理端點設備間的個別通訊，並可提供可靠性。)
3 - Network
(網路層)		 Provides services to exchange the individual pieces of data over the network between identified end devices. (處理定址(IP)與路由，決定資料在不同網路間的最佳傳輸路徑。)
2 - Data Link
(資料連結層)		 Describe methods for exchanging data frames between devices over a common media. (描述如何在同一共同媒體(如同一個區域網路)上的設備間交換資料訊框(Frames)，處理實體MAC位址。)
1 - Physical
(實體層)		 Describe the mechanical, electrical, functional, and procedural means to activate, maintain, and de-activate physical connections for bit transmission. (定義機械、電氣與功能特性，負責在媒體上傳輸原始的位元流(0與1)。)
7 - Application (應用層)
負責應用程式間的互動溝通 (Process-to-process)。
6 - Presentation (展示層)
處理資料表示法、加密與壓縮。
5 - Session (會議層)
組織並管理通訊對話 (Dialogue)。
4 - Transport (傳輸層)
負責資料分段、傳輸與重組 (Segment & Transfer)。
3 - Network (網路層)
負責跨網路的定址與路徑選擇 (Routing)。
2 - Data Link (資料連結層)
在共用媒體上交換訊框 (Frames)。
1 - Physical (實體層)
處理電壓、接頭等實體訊號，傳送位元 (Bits)。

3.5.3 TCP/IP 協定模型 (The TCP/IP Protocol Model)

TCP/IP 的 4 層架構

TCP/IP 模型在 1970 年代初期建立，有時被稱為網際網路模型 (Internet Model)。與 OSI 不同，TCP/IP 是一個協定模型，因為它描述了 TCP/IP 協定套件中特定協定發生的功能。

TCP/IP 模型層級 說明 (Description)
4 - Application
(應用層)		 Represents data to the user, plus encoding and dialog control. (向使用者呈現資料，並包含編碼與對話控制。涵蓋了 OSI 的應用、展示與會議層功能。)
3 - Transport
(傳輸層)		 Supports communication between various devices across diverse networks. (支援跨越各種網路的不同設備間的通訊，如 TCP 或 UDP。)
2 - Internet
(網際網路層)		 Determines the best path through the network. (決定網路間傳輸的最佳路徑，負責 IP 定址與路由。)
1 - Network Access
(網路存取層)		 Controls the hardware devices and media that make up the network. (控制組成網路的硬體設備與媒體，涵蓋 MAC 位址與實體訊號。)
4 - Application (應用層)
呈現資料給使用者，包含編碼與對話控制。
3 - Transport (傳輸層)
支援不同設備跨網路的端對端通訊。
2 - Internet (網際網路層)
決定封包在網路中傳送的最佳路徑。
1 - Network Access (網路存取層)
控制底層網路硬體與傳輸媒體。

3.5.4 OSI 與 TCP/IP 模型比較 (Model Comparison)

模型對應關係

兩個模型在傳輸層與網路層非常相似，但在上層(應用)與下層(實體/資料連結)的劃分方式則有所不同：

7 - Application
6 - Presentation
5 - Session
⟷
4 - Application (應用層)
4 - Transport
⟷
3 - Transport (傳輸層)
3 - Network
⟷
2 - Internet (網際網路層)
2 - Data Link
1 - Physical
⟷
1 - Network Access (網路存取層)
  • 網路層 (Layer 3)： OSI 的網路層 (Network) 直接對應到 TCP/IP 的網際網路層 (Internet)。
  • 傳輸層 (Layer 4)： 兩者的傳輸層 (Transport) 相互直接對應。
  • 應用層整合： TCP/IP 的 Application 層包含了特定的協定(如 HTTP, DNS, DHCP)，而 OSI 則將這些功能細分為應用層、展示層與會議層 (Layers 7, 6, 5)。
  • 底層差異： 網路存取層 (Network Access) 在 TCP/IP 中並未詳細規範實體傳輸協定，而是仰賴 OSI Layer 1 與 Layer 2 來描述實體媒體存取的必要程序。

Q1. 模型映射

The TCP/IP Application layer maps to which three layers of the OSI model?

(TCP/IP 的應用層對應到 OSI 模型的哪三個階層？)
👉 點擊翻開看解答
解答
Application, Presentation, Session (Layer 7, 6, 5)
解析：TCP/IP 將應用程式溝通、資料格式化(展示)與對話控制(會議)全部整合在單一的「Application Layer」之中。
Q2. OSI 網路層

Which OSI layer provides services to exchange individual pieces of data over the network between identified end devices?

(哪一個 OSI 階層負責在識別出的端點之間，跨網路交換個別的資料區塊？)
👉 點擊翻開看解答
解答
Layer 3 - Network (網路層)
解析：網路層(Layer 3)負責邏輯定址(IP)與決定資料封包在不同網路間的最佳路徑(Routing)。
Q3. 實體層功能

Which OSI layer is responsible for the mechanical, electrical, and functional means for bit transmission?

(哪一個 OSI 階層負責處理位元傳輸的機械、電氣與功能方法？)
👉 點擊翻開看解答
解答
Layer 1 - Physical (實體層)
解析：實體層處理的是硬體的連線、電壓的高低，以及如何在纜線或無線媒體上打出 0 與 1 的原始位元(bits)。
Q4. 分層優勢

What is one major benefit of using a layered model regarding different vendors?

(關於不同供應商，使用分層模型的一個主要優點是什麼？)
👉 點擊翻開看解答
解答
Fostering competition (促進競爭與相容性)
解析：因為每一層的介面都是標準化的，來自不同廠商(如 Cisco, HP, Juniper) 的設備可以互相協作，這避免了單一廠商壟斷並促進了市場技術競爭。
Q5. TCP/IP Internet Layer

The TCP/IP Internet layer directly maps to which layer of the OSI model?

(TCP/IP 的網際網路層直接對應到 OSI 模型的哪一層？)
👉 點擊翻開看解答
解答
Layer 3 - Network (網路層)
解析：TCP/IP 的 Internet 層負責尋找最佳路徑 (Determines the best path)，這完全等同於 OSI 模型中 Network 層的核心功能。
