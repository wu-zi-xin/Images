3.8.1.1 規則與通訊協定 (The Rules & Protocols)

The Rules (通訊規則)

所有的通訊方法都有三個共通元素：訊息來源 (傳送者)、訊息目的地 (接收者) 和通道。傳送訊息由稱為「協定 (protocols)」的規則所控管。

  • 協定必須包含：識別傳送者與接收者、共通語言與文法、傳遞的速度與時序，以及確認或回報的要求。
  • 編碼 (Encoding)：將資訊轉換為另一種可接受的格式以便傳輸的過程。
  • 解碼 (Decoding)：接收端反向執行此過程以解譯資訊。
  • 訊息時序 (Message timing) 包含：流量控制 (flow control)、回應逾時 (response timeout) 和存取方法 (access method)。
  • 訊息傳遞選項 (Message delivery options) 包含：單播 (unicast)、多播 (multicast) 和廣播 (broadcast)。
Protocols (通訊協定)

協定透過終端裝置和中介裝置的軟體、硬體或兩者來實作。每一個網路協定都有其專屬的功用、格式和通訊規則。

協定功能分類 範例協定 (Examples)
Ethernet 家族 IP, TCP, HTTP 等等
提供認證、完整性與加密機制 SSH, SSL, TLS
交換路由資訊、選擇最佳路徑 OSPF, BGP
自動偵測裝置或服務 DHCP, DNS

IP, TCP, HTTP 等等。

定址 (addressing)、可靠性 (reliability)、流量控制 (flow control)、排序 (sequencing)、錯誤偵測 (error-detection) 和應用程式介面 (application interface)。

3.8.1.2 協定套件與標準組織 (Protocol Suites & Standards)

Protocol Suites (協定套件)

協定套件是一組為了執行通訊功能所必需的互相關聯的協定。協定堆疊 (protocol stack) 顯示了套件中的個別協定是如何實作的。

  • TCP/IP 是當今網路與網際網路所使用的協定套件。
  • 它提供兩項重要特性：
    1. 開放標準協定套件 (open standard protocol suite)
    2. 基於標準的協定套件 (standards-based protocol suite)
  • 通訊過程範例： 網頁伺服器將網頁資料向下層封裝 (encapsulating) 後傳送給客戶端，客戶端收到後向上解封裝 (de-encapsulating) 以在網頁瀏覽器中顯示。
Standards Organizations (標準組織)

開放標準鼓勵互通性、競爭與創新。標準組織通常是中立的非營利組織，旨在推廣開放標準的概念。

  • 網際網路標準 (Internet Standards)： 包含 ISOC (網際網路協會), IAB (網際網路架構委員會), IETF (網際網路工程任務組), 和 IRTF。
  • TCP/IP 開發與支援： 包含 ICANN (網際網路名稱與數字位址分配機構) 和 IANA (網際網路號碼分配局)。
  • 電子與通訊標準： 包含 IEEE (電機電子工程師學會), EIA, TIA, 和 ITU-T。

3.8.1.3 參考模型 (Reference Models)

OSI 與 TCP/IP 模型比較

這兩個參考模型被用來描述網路的運作方式。OSI 模型分為 7 層，而 TCP/IP 模型分為 4 層。

OSI 模型 (7 層) TCP/IP 模型 (4 層)
7 - Application (應用層) 4 - Application (應用層)
6 - Presentation (展示層)
5 - Session (會議層)
4 - Transport (傳輸層) 3 - Transport (傳輸層)
3 - Network (網路層) 2 - Internet (網際網路層)
2 - Data Link (資料連結層) 1 - Network Access (網路存取層)
1 - Physical (實體層)
TCP/IP: Application (應用層)
對應 OSI 模型的第 5, 6, 7 層 (Session, Presentation, Application)。
TCP/IP: Transport (傳輸層)
對應 OSI 模型的第 4 層 (Transport)。
TCP/IP: Internet (網際網路層)
對應 OSI 模型的第 3 層 (Network)。
TCP/IP: Network Access (網路存取層)
對應 OSI 模型的第 1, 2 層 (Physical, Data Link)。

3.8.1.4 資料封裝與存取 (Data Encapsulation & Access)

Data Encapsulation (資料封裝)

將長篇訊息分割成較小的區段 (Segmenting messages) 有兩個主要好處：

  • 多工 (Multiplexing)： 允許網路上交錯傳輸多個不同的通訊對話。
  • 提高效率： 如果傳輸過程中部分訊息遺失，只需要重新傳輸遺失的區段，而不必重傳整個訊息。TCP 負責將這些個別的區段進行排序 (sequencing)。

封裝的過程：

  • PDU (Protocol Data Unit)： 資料在任何一層的特定形式稱為協定資料單元。
  • 封裝 (Encapsulation)： 發送訊息時，過程是由上而下的。每一層接收到上層的 PDU 後，會根據使用的協定加上自己的標頭資訊。
  • 解封裝 (De-encapsulation)： 接收設備使用的過程，由下而上依序移除協定標頭，將資料還原後交給終端使用者的應用程式。
Data Access (資料存取)

網路層和資料連結層負責將資料從來源設備傳遞到目的地設備，這兩層都包含來源和目的地位址，但目的不同：

  • 網路層位址 (Network layer addresses) - IP 位址： 負責將 IP 封包從「原始來源 (original source)」遞送到「最終目的地 (final destination)」。IP 位址包含網路部分與主機部分。
  • 資料連結層位址 (Data link layer addresses) - MAC 位址： 負責將資料連結框架從同一個網路上的「一個網卡 (NIC)」傳送到「另一個網卡」。在乙太網路上，這些被稱為 MAC 位址。
💡 跨網段傳輸：
當封包發送者和接收者在不同的網路上時，來源和目的地 MAC 位址會代表不同網路上的主機。此時，乙太網路框架必須發送給另一個設備，也就是路由器 (router) 或預設閘道 (default gateway)。

Question 1

Which three acronyms/initialisms represent standards organizations? (Choose three.)

  • IETF
  • TCP/IP
  • IEEE
  • OSI
  • IANA
  • MAC
👉 點擊翻開看解答
解答
IETF, IEEE, IANA
解析：IETF 是網際網路工程任務組，IEEE 是電機電子工程師學會，IANA 是網際網路號碼分配局。TCP/IP 和 OSI 是模型/協定，MAC 是位址類型。
Question 2

What type of communication will send a message to all devices on a local area network?

哪種通訊類型會將訊息發送給區域網路上的所有設備？
  • Multicast
  • Allcast
  • Broadcast
  • Unicast
👉 點擊翻開看解答
解答
Broadcast (廣播)
解析：Broadcast 用於一對所有 (one-to-all) 的通訊，會傳送給同網段內的所有設備。
Question 3

In computer communication, what is the purpose of message encoding?

在電腦通訊中，訊息編碼 (encoding) 的目的是什麼？
  • To interpret information

  • To negotiate correct timing for successful communication

解答
To convert information to the appropriate form for transmission
解析：編碼是將資料轉換為適合在特定介質上傳輸的格式的過程。
Question 4

Which message delivery option is used when all devices need to receive the same message simultaneously?

當所有設備需要同時接收相同的訊息時，應使用哪種訊息傳遞選項？

  • Unicast

Broadcast (廣播)
解析：與 Q2 概念相同，廣播 (Broadcast) 可讓網路上所有節點同時接收到。

Question 7

Which logical address is used for delivery of data to a remote network?

哪種邏輯位址用於將資料遞送到遠端網路？

Question 8

What is the general term that is used to describe a piece of data at any layer of a networking model?

Question 9

Which two protocols function at the internet layer? (Choose two.)

哪兩個協定在網際網路層 (Internet layer) 運作？
  • PPP

  • POP

Question 10

Which layer of the OSI model defines services to segment and reassemble data for individual communications between end devices?

Transport (傳輸層)

Question 11

Multicast (多播)

Question 12

What process is used to receive transmitted data and convert it into a readable message?

什麼過程用於接收傳輸的資料並將其轉換為可讀的訊息？

  • Flow control
  • Decoding
  • Access control

Decoding (解碼)

Question 13

What is done to an IP packet before it is transmitted over the physical medium?

在實體介質上傳輸 IP 封包之前，會對它進行什麼處理？
  • It is tagged with information...
  • It is encapsulated into a TCP segment.
  • It is encapsulated in a Layer 2 frame.
  • It is segmented...
👉 點擊翻開看解答
解答
It is encapsulated in a Layer 2 frame.
解析：在向下封裝的過程中，L3 的 IP 封包會交給 L2，並被封裝進 Layer 2 的 Frame (框架) 裡面，然後才轉換成位元流 (bits) 透過實體層傳輸。
Question 14

What process is used to place one message inside another message for transfer from the source to the destination?

將一個訊息放入另一個訊息中以便從來源傳輸到目的地的過程稱為什麼？
  • Access control
  • Encapsulation
  • Decoding
  • Flow control
👉 點擊翻開看解答
解答
Encapsulation (封裝)
解析：每一層將上層的資料加上自己的標頭，就像是把信件放入信封中，這個過程稱為封裝。
Question 15

A web client is sending a request for a webpage to a web server. From the perspective of the client, what is the correct order of the protocol stack that is used to prepare the request for transmission?

網頁客戶端向伺服器發送請求。從客戶端的角度，準備傳輸請求所使用的協定堆疊正確順序為何？
  • Ethernet, IP, TCP, HTTP
  • Ethernet, TCP, IP, HTTP
  • HTTP, IP, TCP, Ethernet
  • HTTP, TCP, IP, Ethernet
👉 點擊翻開看解答
解答
HTTP, TCP, IP, Ethernet
解析：發送資料是由上而下封裝的。應用層產生 HTTP 請求 -> 傳輸層加上 TCP 標頭 -> 網路層加上 IP 標頭 -> 網路存取層加上 Ethernet 標頭。
