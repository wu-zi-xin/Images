3.6.1 訊息分段 (Segmenting Messages)

什麼是訊息分段？

在網路上傳送大型資料（如影片或附帶大檔案的電子郵件）時，如果將其作為龐大、不間斷的資料流傳送，會造成其他通訊延遲，且若傳輸失敗需整個重傳。

較好的方法是將資料分割成較小、易於管理的片段。將資料串流分割成較小單位以便傳輸的過程，稱為 分段 (Segmentation)。

💡 訊息分段的兩大好處：
  • Increases speed (提升速度) / Multiplexing (多工)：
    大型資料流被分割成封包後，可以在不佔用整個通訊鏈路的情況下發送大量資料。這允許許多不同的對話在網路上交錯進行，稱為多工。
  • Increases efficiency (提升效率)：
    如果單個片段未能到達目的地（因為網路故障或壅塞），只有該片段需要重新傳輸，而不是重新傳送整個資料流。

3.6.2 排序 (Sequencing)

處理分段與多工的挑戰

使用分段和多工在網路上傳輸訊息會增加過程的複雜性。因為各個片段可能會透過不同的路徑傳輸，導致它們 不按順序 (out-of-order) 到達目的地。

Sequencing by TCP
In network communications, each segment of the message must go through a similar process to ensure that it gets to the correct destination and can be reassembled into the content of the original message. TCP is responsible for sequencing the individual segments.
TCP 負責排序
在網路通訊中，訊息的每個片段都必須經過類似的過程，以確保它到達正確的目的地並能重新組裝成原始訊息。TCP 協定負責對各個片段進行排序 (Sequencing)。
💡 標籤的作用：
標籤提供了在片段到達時進行排序和組裝的功能 (Labeling provides for ordering and assembling the pieces when they arrive)。這就像是給每個信封編號，讓收件人知道如何按順序閱讀多頁的信件。

3.6.3 協定資料單元 (Protocol Data Units)

什麼是 PDU？

當應用程式資料在協定堆疊向下傳遞時，每一層都會加入各種協定資訊。這個過程稱為 封裝 (Encapsulation)。

資料在任何一層的型態稱為 協定資料單元 (PDU, Protocol Data Unit)。在每個階段，PDU 都有不同的名稱來反映其新功能。

PDU 名稱 對應的 OSI / TCP/IP 協定層 說明 (Description)
Data (資料) Application layer (應用層) 應用層使用的 PDU 的通用術語。
Segment (區段/分段) Transport layer (傳輸層) 傳輸層的 PDU。
Packet (封包) Network layer (網路層) 網路層的 PDU。
Frame (框架/幀) Data Link layer (資料連結層) 資料連結層的 PDU。
Bits (位元) Physical layer (實體層) 實體層透過媒介實體傳輸資料時使用的 PDU。

3.6.4 & 3.6.5 封裝與解封裝 (Encapsulation and De-encapsulation)

封裝 (Encapsulation) 過程

當訊息在網路上傳送時，封裝過程 由上而下 (from top to bottom) 進行。在每一層，上層的資訊被視為被封裝協定內的資料。

  • 網頁伺服器產生 Data。
  • 傳輸層加入 TCP 標頭，形成 TCP Segment。
  • 網路層加入 IP 標頭，形成 IP Packet。
  • 資料連結層加入乙太網路標頭與標尾，形成 Ethernet Frame。
  • 實體層將 Frame 轉換為 Bits (010101...) 送出。
解封裝 (De-encapsulation) 過程

這個過程在接收主機上被反轉，稱為解封裝。這是接收設備用來移除一個或多個協定標頭的過程。

隨著資料在堆疊中 向上移動 (moves up the stack) 朝向終端使用者應用程式，資料會被逐步解封裝。

  • 接收端收到 Bits 並重組為 Ethernet Frame。
  • 移除乙太網路標頭/標尾，將裡面的 IP Packet 往上傳。
  • 移除 IP 標頭，將裡面的 TCP Segment 往上傳。
  • 移除 TCP 標頭，將裡面的 Data 傳給網頁客戶端。

Question 1

What is the process of dividing a large data stream into smaller pieces prior to transmission?

(將大型資料流在傳輸前分割成較小片段的過程稱為什麼？)
👉 點擊翻開看解答
解答
Segmentation (分段)
解析：將龐大的資料流分割成可以放入網路傳輸媒介的較小區塊，這個動作就是 Segmentation。
Question 2

What is the PDU associated with the transport layer?

(與傳輸層相關的 PDU 是什麼？)
👉 點擊翻開看解答
解答
Segment (區段)
解析：在傳輸層 (Transport Layer)，資料的單位稱為 Segment。網路層則是 Packet，資料連結層是 Frame。
Question 3

Which protocol stack layer encapsulates data into frames?

(哪一個協定堆疊層將資料封裝成框架 (frames)？)
👉 點擊翻開看解答
解答
Data link (資料連結層)
解析：Frame 是 Data link layer 的 PDU 名稱。網路層的 Packet 會在資料連結層被加上標頭與標尾，封裝成 Frame。
Question 4

What is the name of the process of adding protocol information to data as it moves down the protocol stack?

(資料在協定堆疊向下移動時加入協定資訊的過程稱為什麼？)
👉 點擊翻開看解答
解答
Encapsulation (封裝)
解析：由上往下在各層加上標頭 (Header) 的過程稱為封裝 (Encapsulation)；由下往上拆解標頭的過程則稱為解封裝 (De-encapsulation)。
