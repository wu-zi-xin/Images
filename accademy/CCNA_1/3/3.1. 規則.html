3.1.2 - 3.1.4 通訊基礎與規則 (Fundamentals & Rule Establishment)

3.1.2 Communications Fundamentals (通訊基礎)

無論是面對面交談還是電腦網路通訊，所有通訊方法都有三個共同的核心要素：

Message source (sender) 訊息來源 (發送者)
Message sources are people, or electronic devices, that need to send a message to other individuals or devices. 訊息來源是需要將訊息發送給其他個人或設備的人或電子設備。
Message Destination (receiver) 訊息目的地 (接收者)
The destination receives the message and interprets it. 目的地接收訊息並對其進行解讀。
Channel (通道 / 媒介)
This consists of the media that provides the pathway over which the message travels from source to destination. 這是指提供訊息從來源傳輸到目的地之路徑的傳輸媒介 (如銅線、光纖、無線電波)。
3.1.4 Rule Establishment (規則建立)

在通訊開始之前，通訊雙方必須建立並遵守一定的規則 (協定 Protocols)，以確保訊息能夠被成功傳遞和理解。這些協定必須考量以下要件：

  • An identified sender and receiver： 必須明確辨識發送者與接收者的身分。
  • Common language and grammar： 必須使用雙方都能理解的共通語言和語法。
  • Speed and timing of delivery： 控制訊息發送的速度與時間點，以防接收方處理不及。
  • Confirmation or acknowledgement requirements： 某些通訊需要確認機制，確保訊息已成功送達。

3.1.5 - 3.1.8 訊息編碼、格式化與封裝 (Encoding & Formatting)

3.1.6 Message Encoding (訊息編碼)

發送訊息的第一步是進行編碼。在網路通訊中，這代表將資訊轉換成適合傳輸介質的形式 (例如：將位元轉換成電壓訊號、光訊號或無線電波)。

💡 Encoding (編碼)： 將資訊轉換為另一種可接受的格式，以便進行傳輸。
💡 Decoding (解碼)： 接收方將傳輸過來的訊號反向轉換回原本的資訊以進行解讀。
3.1.7 Message Formatting and Encapsulation (格式化與封裝)

當訊息從來源發送到目的地時，必須使用特定的格式或結構。就像寄信一樣，信件內容需要被放入信封中，並在信封上寫上寄件人與收件人的地址，這個過程稱為封裝 (Encapsulation)。

  • IP 封包 (Internet Protocol packet)： 網路中的訊息傳遞會使用類似信封的結構。IP 協定負責識別封包的來源與目的地。
  • 在 IPv6 封包的結構中，會明確包含 Source IP Address (來源 IP 位址) 以及 Destination IP Address (目的 IP 位址)。
  • 當接收方收到封包並將資料取出的過程，則稱為解封裝 (De-encapsulation)。
3.1.8 Message Size (訊息大小)

當人們交談時，通常會將長篇大論拆分成較短的句子；網路通訊也是如此，過長的訊息無法一次傳送，必須被切割。

  • 長訊息在網路上發送前，必須被切割成較小的片段，稱為影格 (Frames) 或 封包 (Packets)。
  • 每個 Frame 都會有自己的定址資訊 (addressing information)，確保它能獨立到達目的地。
  • 當所有片段到達目的地後，接收方會將這些片段重新組合 (reconstructed) 成原始的完整訊息。

3.1.9 - 3.1.11 訊息時序與傳送選項 (Timing & Delivery)

3.1.9 Message Timing (訊息時序)

訊息的時序在網路通訊中非常重要，包含以下三個關鍵要素：

時序組件 (Component) 說明 (Description)
Flow Control (流量控制) Manages the rate of data transmission. Defines how much information can be sent and the speed at which it can be delivered. (管理資料傳輸的速率。定義一次可以發送多少資訊以及發送的速度，避免接收方因來不及處理而遺失資料。)
Response Timeout (回應逾時) Rules that specify how long to wait for responses and what action to take if a response timeout occurs. (當發送端要求回應時，若在指定時間內未收到回覆，系統會假定該訊息未送達，並採取對應動作，例如重傳。)
Access method (存取方法) Determines when someone is able to send a message on a shared medium to prevent collisions. (決定設備何時可以將訊息發送到共用介質上。如果兩台設備同時發送，會產生「碰撞 (collision)」，因此需要有規則來管理發送時機。)
Flow Control (流量控制)
控制資料傳輸的速率，避免傳送過快導致接收端無法負荷。
Response Timeout (回應逾時)
設定等待回應的最高時間限制，若超時則可能觸發重新傳送機制。
Access method (存取方法)
管理共享網路介質的發話權，避免多台設備同時傳輸導致訊號碰撞 (Collision)。
3.1.10 Message Delivery Options (訊息傳送選項)

訊息可以透過不同的方式傳遞給網路上的設備，分為以下三種：

Unicast (單播)
Information is being transmitted to a single end device. (一對一：資訊只發送給單一的終端設備。)
Multicast (多播 / 群播)
Information is being transmitted to a one or more end devices. (一對多：資訊發送給網路上特定的一群設備，而非全部設備。)
Broadcast (廣播)
Information is being transmitted to all end devices. (一對全體：資訊發送給同一網路中的所有終端設備。)
💡 Node Icon (節點圖示)： 在網路拓撲與文件中，通常會使用「圓形圖示」來代表網路上的節點 (Nodes) 或終端設備，這有助於簡化圖表以表達 Unicast、Multicast 和 Broadcast 的資料流向。

Question 1

What is the process of converting information into the proper form for transmission?

(將資訊轉換成適合傳輸形式的過程稱為什麼？)
👉 點擊翻開看解答
解答 (Answer)
Encoding (編碼)
解析：在網路通訊中，傳送方必須先將訊息「編碼 (Encoding)」，轉換為介質可以傳遞的訊號格式（例如電壓、光脈衝）；接收方收到後再進行「解碼 (Decoding)」。
Question 2

Which step of the communication process is concerned with properly identifying the address of the sender and receiver?

(通訊過程中的哪一個步驟與正確識別發送方和接收方的位址有關？)
👉 點擊翻開看解答
解答 (Answer)
Formatting (格式化 / 封裝)
解析：這就像寫信一樣。將資料加上包含來源 IP 與目的 IP 的標頭，這個過程稱為格式化與封裝 (Formatting and Encapsulation)。
Question 3

Which three are components of message timing? (Choose three.)

(哪三個是訊息時序的組成部分？請選三項)
👉 點擊翻開看解答
解答 (Answer)
Flow control
Access method
Response timeout
解析：訊息時序 (Message Timing) 包含：管理傳輸速率的 Flow control、決定何時可發送訊號的 Access method、以及決定等待回覆時間的 Response timeout。
Question 4

Which delivery method is used to transmit information to one or more end devices, but not all devices on the network?

(哪一種傳送方法用於將資訊傳輸到網路中的「一個或多個」終端設備，但「不是全部」設備？)
👉 點擊翻開看解答
解答 (Answer)
Multicast (多播)
解析：Unicast 是一對一；Broadcast 是一對全部；而 Multicast (多播) 則是一對一組特定的設備 (one to a selected group, but not all)。
