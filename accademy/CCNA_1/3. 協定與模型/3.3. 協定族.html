3.3 協定族（Protocol Suite）與 TCP/IP 通訊協定堆疊

這一段是在講：電腦到底怎麼「有規則地」溝通。不是只知道有網路線、有 Wi‑Fi 就好，而是要知道資料在送出前會經過哪些規則、被包成什麼格式、由哪些協定處理，最後才會順利送到對方主機。

根據你提供的課程影片，本頁整理了 3.3.1 到 3.3.5 的重點，並補上容易理解的白話說明、圖像化整理、常見協定用途、專有名詞中英對照，以及課後練習題。

重點一：協定是一套規則 重點二：TCP/IP 是現代網路主流 重點三：資料會封裝與解封裝 重點四：分層可以讓網路更容易設計與除錯

3.3.1 網路通訊說明

簡單講，網路通訊不是隨便把資料丟出去，而是雙方都要遵守同一套規則。這些規則就叫做 協定（Protocol）。

白話理解：像兩個人在聊天

  • 內容層（Content）：你要講什麼內容，例如「晚點開會」。
  • 規則層（Rules）：你們要用同一種語言、輪流講話、講完要等回應。
  • 實體層（Physical）：聲音要透過嘴巴、耳朵與空氣傳出去。

電腦網路也一樣：內容、規則、實際傳送媒介，三者都要配合，通訊才會成功。

為什麼要分層？
  • 把複雜問題切小塊：每一層只做好自己的事。
  • 更容易替換技術：例如換成 Wi‑Fi，不一定要改上層應用程式。
  • 更容易除錯：可以定位是應用層、傳輸層，還是網路存取層出問題。
  • 更容易標準化：不同廠牌設備只要遵守同一套標準，就能互通。

3.3.2 協議套件的演變

所謂 協議套件（Protocol Suite），就是一組互相配合的協定，一起完成完整的網路通訊服務。

影片中提到，從 1970 年代以來，曾經出現過好幾種不同的協議套件；有些是正式標準，有些是特定廠商推出的方案。後來真正成為主流的是 TCP/IP。

協議套件 定位 代表特徵 現在的狀態
TCP/IP 現代 Internet 的主流協議套件 開放、可擴充、跨平台、支援大型互聯網 主流中的主流
ISO / OSI 由國際標準組織提出的參考模型 七層模型很重要，常用來教學、分析與除錯 模型很常用，但實際 OSI 協定本身並未成為主流
AppleTalk Apple 早期網路架構 在舊式 Apple 環境中使用 歷史性技術，現今幾乎淘汰
Novell NetWare Novell 早期網路系統 以 IPX/SPX 等協定著名 歷史性技術，現今少見
圖 2：協議套件演變（簡化）
影片的重點不是背歷史年份，而是要知道：最後真正統一全球網路世界的，是 TCP/IP。

為什麼最後是 TCP/IP 勝出？

  • 開放標準：不是某單一廠商獨佔，容易被不同設備採用。
  • 可以跨品牌互通：交換器、路由器、伺服器、電腦都能合作。
  • 可以擴展到大型網路：從家庭到全球 Internet 都能用。
  • 分層設計清楚：方便實作、維護與教學。
考試常見觀念：OSI 七層模型非常重要，但在真實網路運作中，主角是 TCP/IP 協定套件。

3.3.3 TCP/IP 協定範例

影片用「瀏覽網頁」當例子。當你在瀏覽器輸入網站、看到畫面時，其實背後已經有多層協定一起合作。

瀏覽網頁時會發生什麼事？

  1. 使用者在瀏覽器輸入網址，例如 www.example.com。
  2. 應用層會用 HTTP / HTTPS 與網站互動。
  3. 傳輸層通常使用 TCP 來建立可靠連線。
  4. 網際網路層使用 IP 來決定封包要送去哪台主機。
  5. 網路存取層使用 乙太網路（Ethernet） 或 WLAN 把資料實際送出去。
很重要的觀念：

「網際網路層」不是指 Internet 網站而已，而是指 IP 位址與路由 的那一層。它負責把資料送到正確的目的地。

而「網路存取層」則是最接近實際媒介的一層，例如網路卡、MAC 位址、乙太網路訊框、Wi‑Fi 無線傳輸等。

圖 3：瀏覽網頁的 TCP/IP 協定範例
你在看的網站畫面，背後其實是多層協定一起合作的成果，不是只有 HTTP 單獨完成。

3.3.4 TCP/IP 通訊協定堆疊

影片這一段是核心中的核心。它把 TCP/IP 協定套件拆成 四層，並列出每層常見協定。

圖 4：TCP/IP 四層通訊協定堆疊總覽
上圖整理了影片中的核心堆疊內容。注意：不同協定各司其職，不是所有情境都會同時用到每一個協定。
應用層（Application Layer）：最靠近使用者的一層。它負責提供各種網路服務，例如查網址、拿 IP、收發信、傳檔案、瀏覽網站。

DNS

Domain Name System｜網域名稱系統

把 網域名稱 轉換成 IP 位址。例如輸入 cisco.com，DNS 會幫你找到對應的 IP。

DHCPv4 / DHCPv6

Dynamic Host Configuration Protocol｜動態主機設定協定

自動分配位址與網路參數。DHCPv4 給 IPv4 用；DHCPv6 給 IPv6 用。

SLAAC

Stateless Address Autoconfiguration｜無狀態位址自動設定

IPv6 主機可以不依賴 DHCPv6，直接根據路由器資訊自動產生自己的 IPv6 位址。

SMTP / POP3 / IMAP

電子郵件相關協定

SMTP 用來寄信；POP3 常見做法是把信下載到本機；IMAP 則強調與伺服器同步，方便多裝置查看同一信箱。

FTP / SFTP / TFTP

檔案傳輸協定

FTP 是傳統檔案傳輸；SFTP 透過 SSH 加密，比較安全；TFTP 非常精簡，常見於設備啟動或備份，但功能少、也不加密。

HTTP / HTTPS / REST

Web 與 Web 服務

HTTP 用來傳網頁；HTTPS 是加密版 HTTP；REST 是一種常見 Web API 設計風格，常搭配 HTTP 使用。

傳輸層（Transport Layer）：負責主機與主機之間的端對端資料傳輸。它會處理資料切分、可靠性、流量控制、以及應用程式使用的連接埠（Port）。

TCP

Transmission Control Protocol｜傳輸控制協定

提供可靠傳輸。會確認資料是否收到、依序重組，若遺失還能重傳。常用於網頁、電子郵件、檔案傳輸。

  • 有連線（Connection-oriented）
  • 有確認機制（ACK）
  • 可靠但負擔較大

UDP

User Datagram Protocol｜使用者資料包協定

提供低負擔、低延遲傳輸，不做複雜確認。適合語音、影音串流、線上遊戲、DNS 查詢等注重速度的情境。

  • 無連線（Connectionless）
  • 不保證一定送到
  • 速度快、開銷小
網際網路層（Internet Layer）：主要負責 邏輯位址（IP） 與 路由（Routing）。換句話說，就是「資料要送去哪裡、怎麼繞路過去」。

IPv4 / IPv6

Internet Protocol｜網際網路協定

IPv4 與 IPv6 都是給封包用的邏輯位址系統。IPv4 比較舊；IPv6 位址空間更大，是未來趨勢。

ICMPv4 / ICMPv6

Internet Control Message Protocol｜網際網路控制訊息協定

用來傳送錯誤與控制訊息，像是 ping、traceroute 的基礎都與 ICMP 有關。

NAT

Network Address Translation｜網路位址轉換

把私有位址轉成公有位址，讓多台內部主機可以共用少量公網 IP 上網。

OSPF / EIGRP / BGP

路由協定

這些是路由器之間交換路由資訊用的協定：OSPF 是常見的開放式內部路由協定；EIGRP 是 Cisco 著名協定；BGP 則是 Internet 規模的路由王者。

ICMPv6 ND

Neighbor Discovery｜鄰居探索

IPv6 用它來做很多原本 IPv4 需要 ARP、路由器發現等功能的事情，是 IPv6 很重要的一塊。

網路存取層（Network Access Layer）：最接近實際媒介的層。它關心的是：資料如何在本地網路上送出去？要用哪種訊框？哪個 MAC 位址？走有線還是無線？

ARP

Address Resolution Protocol｜位址解析協定

在 IPv4 網路中，把 IP 位址 對應到 MAC 位址。主機要在本地網路把資料送給誰，常常得先問 ARP。

Ethernet

乙太網路

最常見的有線 LAN 技術。它定義了本地網路中的訊框格式、MAC 位址使用方式與媒介存取方式。

WLAN

Wireless LAN｜無線區域網路

也就是一般說的 Wi‑Fi。它讓資料透過無線方式在本地網路中傳輸。

3.3.5 通信過程

這一段講的是：資料從 Web 伺服器送到網頁客戶端時，會先一層一層包起來（封裝，Encapsulation），到對方後再 一層一層拆開（解封裝，Decapsulation）。

圖 5：資料從伺服器送到客戶端的封裝 / 解封裝流程
已重新優化這張圖：把容易被截掉的長句改成雙行排版、放寬方塊寬度，讓桌機與手機縮放時都不容易出現字被切掉的情況。
應用層產生資料： 例如使用者要開啟網頁，伺服器準備好 HTML、圖片、CSS 等內容。
傳輸層加入 TCP/UDP 資訊： 如果是網頁，通常會加上 TCP 標頭，形成 Segment（資料段）。
網際網路層加入 IP 資訊： 標示來源 IP 與目的 IP，形成 Packet（封包）。
網路存取層加入訊框資訊： 加上來源/目的 MAC 等資料，形成 Frame（訊框）。
實際傳輸： 訊框轉成 Bits，透過網路線、光纖或 Wi‑Fi 傳出去。
接收端解封裝： 對方主機收到後，會反過來一層層拆開，最後把原始資料交給瀏覽器或應用程式。
必背小觀念： Data → Segment → Packet → Frame → Bits。這串順序在考試與實務上都很常見。

2. TCP 跟 UDP 到底怎麼選？

比較項目TCPUDP
可靠性高，會確認與重傳低，不保證送達
速度 / 開銷較慢、開銷較大較快、開銷較小
常見用途HTTP/HTTPS、FTP、EmailDNS、語音、串流、遊戲
適合情境資料不能錯、不能少速度與即時性更重要
不要死背成絕對：有些即時服務也會在應用層做自己的補救機制，所以「TCP=可靠、UDP=快速」是基礎理解，但實際設計會更細緻。

常見 PDU 名稱

  • Data：應用層資料
  • Segment：TCP 資料段
  • Datagram：常用來指 UDP 資料報
  • Packet：IP 封包
  • Frame：乙太網路訊框
  • Bits：真正在線路或空中傳的位元

常見 Port（考試常見）

  • HTTP：80
  • HTTPS：443
  • DNS：53
  • SMTP：25
  • POP3：110
  • IMAP：143
  • FTP：21
  • SSH / SFTP：22
  • TFTP：69

除錯時的思考順序

  1. 有沒有連到媒介？（線、Wi‑Fi）
  2. 有沒有正確 IP？
  3. DNS 能不能解析？
  4. TCP/UDP Port 有沒有被擋？
  5. 應用程式本身有沒有正常？
