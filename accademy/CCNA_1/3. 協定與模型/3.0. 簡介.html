3.0 簡介：協定和模型
Protocols and Models

這一段課程的核心，不是在背很多英文，而是在理解：網路設備為什麼能彼此溝通？答案是因為它們遵守共同的 協定（Protocol）、由標準組織制定通用規範，並且能用 模型（Model） 把整個通訊流程拆成容易理解的層次。你把這段學懂，後面 IP、交換、路由、封包分析都會順很多。

2. 3.0.1 為什麼要參加這個課程？

影片裡的意思很明確：你可能已經知道簡單網路的基本元件，也會做一些初始設定；但是，當你把這些元件接起來之後，你怎麼知道它們真的可以一起運作？答案就是：要靠 協定（Protocol） 和 模型（Model）。

協定 Protocol 是什麼？

協定就是一組大家都遵守的規則。它會定義：資料格式、傳送順序、錯誤處理方式、速度與時機。就像聊天時要講同一種語言、約定輪流講、知道什麼叫做收到與回覆。

模型 Model 是什麼？

模型不是拿來直接傳資料的規則，而是拿來幫你理解網路流程。最常見就是 OSI 模型 與 TCP/IP 模型。它們把複雜通訊拆層，方便標準化與除錯。

圖解 1：通訊之所以能成功，不是因為「有線就好」，而是因為雙方都遵守共同規則。這就是協定的核心概念。
常見誤區：很多人以為「設備接起來就會通」。其實不是。接線只解決物理連線，但資料能不能被正確理解、能不能跨不同設備互通，還得靠協定與標準。

3. 3.0.2 我將在這個課程中學到什麼？

影片中出現了一個表格，列出本章「協定和模型」的主題與目標。我把它整理成更容易讀的版本，並加上白話說明。

主題標題 主題目標 白話解釋
規則（Rules） 描述規則的類型必須成功溝通。 先理解「能溝通」本身需要哪些條件，例如格式、時間、大小、流程、確認機制。
Protocols（協定） 解釋為什麼協議在網路通信中是必要的。 說明協定如何讓不同品牌、不同設備仍能彼此交換資料。
協定族（Protocol Suite） 解釋堅持協議套件的目的。 不是只有一條規則，而是一整組協定共同合作，例如 TCP/IP 套件。
標準組織（Standards Organizations） 解釋標準組織在建立協議方面的作用與網路互通性。 像 IEEE、IETF 這些組織會制定或推動標準，避免大家各做各的。
參考模型（Reference Models） 說明如何使用 TCP/IP 模型和 OSI 模型來促進標準化的溝通過程。 把通訊流程拆層，方便設計、學習、除錯、對照協定位置。
數據封裝（Data Encapsulation） 解釋數據封裝如何允許數據透過資訊。 資料往下交給每一層時，都會被加上對應控制資訊，最後才能上線傳送。
資料存取（Data Access） 解釋本地主機如何訪問網路上的本地資源與遠端資源。 理解電腦怎麼找同網段設備、怎麼透過閘道去外部網路。
這張表的意義：它不是單純列出考試項目，而是在告訴你「學網路的順序」：先知道規則為何存在，再知道協定如何工作，接著看標準、模型、封裝，最後才知道資料如何在實際網路中跑起來。

4. 規則與協定（Rules & Protocols）

在日常生活中，只要兩個人要合作，就一定會出現規則。網路也一樣。你可以把協定想成「設備之間共同承認的遊戲規則」。

格式 Format

資料長什麼樣、欄位順序怎麼排、要不要有標頭與結尾，都屬於格式問題。

時機 Timing

什麼時候能傳、多久重送一次、收到後多久要回應，這些都是時機控制。

確認 Acknowledgment

有些協定會要求收到資料後回覆「我收到了」，以提升可靠度。

常見協定例子

HTTP｜超文字傳輸協定

網站瀏覽常見協定，定義瀏覽器與網站伺服器怎麼交換資料。

IP｜網際網路協定

負責邏輯位址與封包在不同網路之間的傳送。

TCP｜傳輸控制協定

提供可靠傳輸、排序與重送機制。

Ethernet｜乙太網路

常見的有線區域網路技術，規範 Layer 1 / Layer 2 的很多細節。

白話理解：如果你把網路看成物流系統，IP 負責看地址，TCP 負責確認包裹有沒有完整送到，HTTP 則像是規定「你要買什麼商品、用什麼格式下訂單」。

5. 協定族（Protocol Suite）

一個完整的網路通訊，不會只靠一條協定。因為從「應用程式要送資料」到「網路卡把訊號送出去」，中間會牽涉很多不同工作，所以會需要一整組互相配合的協定，這就叫做 協定族（Protocol Suite）。

最重要的例子：TCP/IP 協定族

TCP/IP 是現代網際網路最核心的一組協定。它不是單一協定，而是一整個家族，裡面包含 IP、TCP、UDP、HTTP、DNS、ARP 等等。

為什麼要用協定族？

因為不同層次的問題，需要不同分工。有人管應用服務、有人管可靠傳輸、有人管位址與路由、有人管實體傳輸。分工清楚，比較容易標準化與維護。

Application
像 HTTP、HTTPS、DNS、SMTP。處理使用者應用服務。
→
Transport
像 TCP、UDP。處理連線、可靠性、分段、多工。
→
Internet
像 IP。處理位址與跨網路傳送。
→
Network Access
像 Ethernet、Wi-Fi。處理媒介存取與實體傳輸。
考試常考觀念：協定族不是隨便湊在一起，而是要彼此相容、能一層一層合作。這就是為什麼 CCNA 會一直強調「分層」與「封裝」。

6. 標準組織（Standards Organizations）

如果每一家廠商都自己訂規則，設備很可能彼此不通。標準組織存在的目的，就是盡量讓網路世界用共同語言運作。這也是影片提到「網路互通性（Interoperability）」的重要原因。

IETF｜Internet Engineering Task Force

主要推動網際網路協定相關標準，常見文件叫 RFC（Request for Comments）。

IEEE｜Institute of Electrical and Electronics Engineers

很常見在乙太網路與無線網路標準，例如 IEEE 802.3（Ethernet）、IEEE 802.11（Wi-Fi）。

ICANN｜Internet Corporation for Assigned Names and Numbers

負責網域名稱與 IP 位址資源分配的整體管理，例如 DNS 根區與名稱管理。

ISO｜International Organization for Standardization

提出很多標準化概念，對網路最有名的是 OSI 參考模型。

TIA / EIA

與通訊布線、接頭、機房相關標準常會提到，例如結構化佈線。

為什麼重要？

因為標準化之後，Cisco、Juniper、HPE、各種主機與作業系統，才有機會互通而不是各自為政。

圖解 2：不同標準組織分別處理不同面向的規格，但共同目標都是讓網路更標準化、更互通。

7. 參考模型（Reference Models）

參考模型是拿來「整理與理解」通訊流程的。最常見有兩個：OSI 模型 與 TCP/IP 模型。你可以把它們理解成兩種不同粒度的地圖：OSI 切得更細，TCP/IP 更貼近實際網際網路運作。

OSI Model｜開放式系統互連模型

共有 7 層：Application、Presentation、Session、Transport、Network、Data Link、Physical。優點是分層很細，教學與除錯很方便。

TCP/IP Model｜TCP/IP 模型

常見為 4 層：Application、Transport、Internet、Network Access。它和實際 Internet 的協定族關聯性很高，因此在實務上很常用。

圖解 3：OSI 切 7 層、TCP/IP 常看成 4 層。學習上 OSI 很方便，實作與協定定位上 TCP/IP 很常用。
很重要的補充：
1) OSI 模型不是實際運作的軟體，它是參考框架。
2) TCP/IP 模型更貼近 Internet 實務。
3) 除錯時常會問：問題出在第幾層？例如網線沒插好偏 Layer 1、MAC / VLAN 問題偏 Layer 2、IP / 路由偏 Layer 3。

8. 資料封裝（Data Encapsulation）

封裝是網路的關鍵流程之一。當你在瀏覽器輸入資料、按下送出後，資料不是直接原封不動上線，而是會在每一層被加上控制資訊。這個「一層一層包起來」的過程就叫封裝。

Data｜資料
使用者看到的原始內容，例如網頁請求、訊息、檔案。
→
Segment
傳輸層加入 TCP / UDP 資訊，例如連接埠號。
→
Packet
網路層加入 IP 資訊，例如來源 / 目的 IP。
→
Frame
資料連結層加入 MAC 位址與錯誤檢查等資訊。
→
Bits
實體層把資料轉成電／光／無線訊號傳送。
圖解 4：資料從應用層往下走時，會逐層加上控制資訊。Frame 中可清楚看到 Header、Payload、Trailer 的結構；到接收端則會做反向的「解封裝（De-encapsulation）」。
超白話版本：封裝就像寄包裹。你先把內容物放進盒子，再貼上收件資訊，再交給物流公司。不同層加上的資訊，就像不同部門貼上的標籤，讓資料知道要怎麼走。

9. 資料存取（Data Access）

影片的最後一個學習目標，是理解「本地主機如何存取本地資源與遠端資源」。簡單說，就是：同一個網路裡怎麼找別人？不同網路時又怎麼出去？

本地資源（Local Resource）

例如：同一個辦公室網段裡的印表機、檔案伺服器、同 VLAN 的其他主機。若在同網段，主機通常可以直接透過 MAC 位址與交換器轉送完成通訊。

遠端資源（Remote Resource）

例如：不同子網路的伺服器、外部網站、雲端服務。當目的地不在本地網段時，主機就需要把資料交給預設閘道（Default Gateway），通常是路由器。

圖解 5：如果目的地在本地網段，通常可直接透過交換器到達；若目的地在遠端網路，主機會先把封包交給預設閘道。
補充但超常用：
• Default Gateway｜預設閘道：幫你把封包送出本地網段。
• DNS｜網域名稱系統：幫你把網站名稱翻成 IP 位址。
兩者功能完全不同，但在真實環境中常常一起出現。

10. 3.0.3 課堂活動－設計通訊系統

影片畫面中用「你買了一台新車，開一週後發現有問題，於是送去附近維修廠」的故事做類比。到場之後，你發現每位技師都會說不同語言，雖然大家都想修好車，但彼此無法順利合作。這個活動就是要你想：要怎麼設計一個共同通訊系統，才能確保工作有效完成？

活動真正想教什麼？

  • 光有參與者，不代表能協作成功。
  • 必須有共同語言、流程、角色分工、回報方式。
  • 這就對應到網路中的協定、標準、封裝與回應機制。

你可以怎麼回答活動？

  • 先定義共同語言與術語。
  • 定義工作流程：誰先接單、誰檢測、誰修復、誰回報。
  • 定義訊息格式：工單上要寫哪些欄位。
  • 定義確認機制：誰收到、誰完成、誰驗收。
圖解 6：影片中的維修廠類比，不是在講修車，而是在講「協作一定要有共同規範」。這和網路世界是一模一樣的道理。

11. 快速複習（白話整理）

如果你只剩 3 分鐘要複習，先看這裡。

協定就是設備之間共同遵守的規則，規定資料怎麼表達、什麼時候送、如何確認、錯誤怎麼處理。

模型是把複雜通訊拆層，好讓你比較容易學習、設計、對照協定位置，也方便除錯。

因為實際通訊包含很多工作，不可能一條協定包辦全部，所以要有一整組協定分工合作。

制定或推動標準，讓不同廠商設備能互通，這樣你家電腦、公司交換器、網站伺服器才不會各說各話。

資料每往下一層，就會多一層控制資訊；接收端再把它一層層拆開。這是網路通訊能被正確引導的基礎。

同網段通常可直接通訊；不同網段則要先交給預設閘道，再由路由設備幫你送出去。

一句總結整章：網路之所以能運作，是因為資料傳輸被標準化了；而你之所以能學懂，是因為模型把這些標準分層整理好了。
