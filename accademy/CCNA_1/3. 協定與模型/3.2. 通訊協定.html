CCNA MODULE 3 · 3.2 PROTOCOLS

通訊協定
Protocols

網路裝置之所以可以互相溝通，不是因為「插上網路線就自然懂彼此」，而是因為雙方都遵守相同的 通訊協定 (Protocol)。協定會規定訊息如何形成、如何傳送、怎麼確認、怎麼排序、怎麼偵測錯誤，以及不同層級的協定如何彼此合作。

1. 本段在學什麼？

影片依序帶到三個核心：什麼是網路通訊協定、協定具備哪些功能、以及多個協定如何一起完成一次 Web 通訊。

3.2.1協定是裝置交換訊息時共同遵守的規則。
3.2.2不同協定負責不同功能，例如定址、可靠性、流量控制與錯誤偵測。
3.2.3實際通訊通常不是只靠一個協定，而是多個協定分工。
核心例子HTTP → TCP → IP → Ethernet，一層一層合作。
白話比喻：協定像「共同講好的交通規則＋郵寄規則」。每一層只負責自己的工作，但合起來才能讓資料從應用程式安全、正確地到達另一端。

2. 3.2.1 網路通訊協定

影片內容
影片說明：若終端裝置要透過網路通訊，每個裝置都必須遵守相同規則集。這些規則稱為「協定」，協定在網路中具有許多不同功能；同時，協定會定義一組共同的格式與規則，供裝置彼此交換訊息。
圖解依影片 3.2.1 表格重新整理：四類協定各自負責不同工作。圖為概念化重繪，不是原影片截圖。
協定類型影片中的功能與例子
網路通訊協定
Network Communication Protocols		讓兩個或多個裝置透過一個或多個網路通訊。影片例子包含 IP、TCP、HTTP。
網路安全協定
Network Security Protocols		保護資料，提供機密性、資料完整性與安全通訊。影片例子包含 SSH、SSL、TLS。
路由通訊協定
Routing Protocols		讓路由器交換路由資訊、比較路徑並選擇到目的地的最佳路徑。影片例子包含 OSPF、BGP。
服務發現協定
Service Discovery Protocols		用於自動偵測裝置或服務。影片例子包含 DHCP、DNS。

3. 3.2.2 網路協定功能

影片接著強調：電腦與網路裝置會使用「彼此同意的通訊協定」來通訊，而不同協定會提供不同功能。

定址 Addressing辨識來源與目的地，讓資料知道「從誰來、要去哪裡」。影片以 Ethernet、IPv4、IPv6 為例。
可靠性 Reliability在需要時提供可靠傳輸機制，避免資料在傳輸過程遺失或損壞。影片以 TCP 為例。
流量控制 Flow Control調整資料傳送速度，避免傳送端太快、接收端來不及處理。影片指出 TCP 提供此服務。
順序 Sequencing替資料片段標示順序，使接收端能重新組裝成正確資料。影片指出 TCP 提供排序服務。
錯誤偵測 Error Detection判斷資料是否在傳輸過程遭到損壞。影片列出 Ethernet、IPv4、IPv6、TCP 等例子。
應用程式介面 Application Interface讓網路應用程式彼此溝通。影片以瀏覽 Web 為例：HTTP、HTTPS 讓用戶端與 Web 伺服器互動。
額外補充
「可靠性」不等於「所有協定都要重傳」。不同層會用不同方式處理錯誤。CCNA 考題常拿 TCP 的可靠性與 UDP 的低負擔做比較；本影片畫面沒有展開 UDP，因此這裡只做觀念提醒，不把它當成影片原文。

4. 3.2.3 通訊協定互動

影片內容
影片指出：透過電腦網路傳送的訊息，通常需要使用數個通訊協定。每個協定有自己的功能與格式。範例情境是「裝置要求 Web 伺服器的網頁」時，會同時使用多個協定。

5. HTTP / TCP / IP / Ethernet 各自做什麼？

HTTP
Hypertext Transfer Protocol
應用層協定。定義瀏覽器與 Web 伺服器如何提出請求、傳回網頁資料。
→
TCP
Transmission Control Protocol
傳輸層協定。影片重點是可靠傳輸、流量控制與排序。
→
IP
Internet Protocol
網路層協定。負責 IP 定址以及封包跨網路的轉送。
→
Ethernet
乙太網路
負責區域網路中的資料鏈路傳送，讓資料可以在同一段 LAN 上移動。
常見誤區：HTTP 不是「負責把資料一路送到遠端主機」；它只規範 Web 應用層訊息。真正跨網路尋找目的地是 IP 的工作；可靠性與排序則由 TCP 負責。

6. 實務情境：打開一個網站時，到底發生什麼？

  1. 你在瀏覽器輸入網址並送出要求。
  2. HTTP 建立「我要哪個資源」的應用層訊息。
  3. TCP 讓資料可以可靠傳輸，並在需要時處理排序、流量控制。
  4. IP 加上來源與目的 IP 資訊，讓路由器知道封包應往哪裡送。
  5. Ethernet 在本地網路上以資料鏈路層框架傳遞到下一跳。
  6. 中間路由器依據 IP 資訊轉送，直到抵達伺服器。
  7. 伺服器依相反方向逐層解讀，再回傳 Web 內容。
額外補充
實際瀏覽網站通常還會碰到 DNS（把網域名稱轉成 IP）以及 TLS/HTTPS（加密保護 Web 流量）。影片 3.2.1 的協定類型表有列到 DNS、TLS/SSL，而 3.2.3 的示意核心則是 HTTP、TCP、IP、Ethernet。

7. 重點速記

一句話記協定：協定就是雙方都同意遵守的「通訊規則」。
一句話記分工：HTTP 管 Web 內容格式，TCP 管可靠傳輸，IP 管跨網路定址與轉送，Ethernet 管本地網路傳遞。
一句話記 TCP：影片明確把「可靠性、流量控制、順序」列為 TCP 提供的能力。
一句話記多協定：一次完整網路通訊，通常是多個協定疊加合作，而不是只靠單一協定。

9. 課後考題

先作答，再按「批改答案」。每題都附白話解析。

1. 網路「通訊協定」最接近下列哪個意思？

解析：影片直接把協定定義為裝置交換訊息時使用的共同格式與規則。

2. 下列哪一個是影片列出的路由通訊協定？

解析：影片 3.2.1 表格把 OSPF、BGP 列為路由通訊協定的例子。

3. 下列哪個協定在影片中被用來說明「可靠性」？

解析：可靠性這一列明確指出 TCP 提供可靠傳輸。

4. 哪個功能用來避免傳送端速度過快，讓接收端來不及處理？

解析：Flow Control 用來調整資料流動速度；影片指出 TCP 提供這項服務。

5. 「替資料片段標示順序，方便接收端重新組裝」是哪個功能？

解析：Sequencing 讓接收端知道各資料片段的先後順序。

6. 在 HTTP → TCP → IP → Ethernet 的例子中，哪個協定負責 Web 請求與回應的應用層格式？

解析：HTTP 是 Web 應用層協定，負責瀏覽器與 Web 伺服器如何交換 Web 訊息。

7. 在同一組例子中，哪個協定負責 IP 定址與跨網路轉送？

解析：IP 的核心工作是網路層定址與封包轉送。

8. 下列哪組最符合影片 3.2.3 的協定互動堆疊？

解析：這正是影片示意圖中的四層協定。

9. 下列哪一類協定主要用來保護資料的機密性、完整性與安全通訊？

解析：影片把 SSH、SSL、TLS 歸在網路安全協定。

10. DHCP、DNS 在影片表格中屬於哪一類？

解析：影片將 DHCP、DNS 列為服務發現協定的例子。

11. 為什麼一次 Web 通訊需要多個協定？

解析：影片 3.2.3 的重點就是「多個協定分工合作」。

12. 哪個敘述最正確？

解析：這三個功能都在 3.2.2 表格中明確連到 TCP。

13. 「錯誤偵測」主要在確認什麼？

解析：Error Detection 就是檢查資料是否遭到破壞或出錯。

14. 哪一項最接近「定址 Addressing」的作用？

解析：定址讓資料知道誰是來源、誰是目的地。

15. 如果考題問：「哪一個協定讓路由器交換路由資訊並選擇路徑？」最可能是在考哪類協定？

解析：路由通訊協定就是讓路由器彼此交換路由資訊並選擇最佳路徑。
