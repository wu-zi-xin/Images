工作項目04 第 226 - 250 題 (綜合解析與各選項詳解版)

主題：TCP 協定特性
226. 下列哪些是 TCP 協定所提供的功能？
① 連接導向 (Connection-oriented)
② 壅塞控制
③ 找尋路徑
④ 錯誤控制
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

TCP (Transmission Control Protocol) 是一種可靠的、連接導向的傳輸層協定。它提供錯誤控制、流量控制以及壅塞控制，確保封包能依序且完整無誤地送達。找尋路徑是屬於網路層 (如 IP 協定) 及路由器的功能。

【各選項解析】
  • ① 連接導向: 正確。TCP 傳輸前需透過三向交握建立連線。
  • ② 壅塞控制: 正確。具備壅塞控制機制 (如慢啟動) 來避免網路過載。
  • ③ 找尋路徑: 錯誤。找尋路徑是第三層 (網路層) 路由協定的工作。
  • ④ 錯誤控制: 正確。使用 Checksum 及重傳機制來進行錯誤檢查與還原。
主題：UDP 協定特性
227. 下列哪些是 UDP 協定的特性？
① 可靠傳輸
② 非連接導向 (Connectionless)
③ 不可靠傳輸
④ 不使用回應(Acknowledgement)
💡 點擊展開解答與解析
✅ 正確答案：②、③、④
【綜合解析】

UDP (User Datagram Protocol) 是一種非連接導向、不可靠的傳輸層協定。它不保證資料必定送達，也不要求接收端回傳確認訊息 (ACK)，因此傳輸延遲極低，適用於即時串流影音或 DNS 查詢等輕量級服務。

【各選項解析】
  • ① 可靠傳輸: 錯誤。UDP 不保證封包成功抵達。
  • ② 非連接導向: 正確。傳送資料前不需要先建立連線。
  • ③ 不可靠傳輸: 正確。沒有重傳機制，遺失的封包不會補送。
  • ④ 不使用回應: 正確。接收端不會發送 Acknowledgement (ACK) 確認收到。
主題：私有 IP 位址
228. 下列哪些是私有（Private） IP 位址？
① 172.15.0.0
② 192.168.10.0
③ 172.30.0.0
④ 172.168.0.0
💡 點擊展開解答與解析
✅ 正確答案：②、③
【綜合解析】

根據 RFC 1918 定義，私有 IP (Private IP) 範圍為：Class A: 10.0.0.0 ~ 10.255.255.255；Class B: 172.16.0.0 ~ 172.31.255.255；Class C: 192.168.0.0 ~ 192.168.255.255。不在此範圍的 IP 均為公有 IP。

【各選項解析】
  • ① 172.15.0.0: 錯誤。不在 172.16.0.0 ~ 172.31.255.255 的範圍內。
  • ② 192.168.10.0: 正確。屬於 Class C 的私有 IP 網段內。
  • ③ 172.30.0.0: 正確。屬於 Class B 的私有 IP 網段內。
  • ④ 172.168.0.0: 錯誤。超出 172.31 範圍，屬公有 IP。
主題：網路層協定
229. 下列哪些是網路層的協定？
① ARP
② ICMP
③ SIP
④ RARP
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

在 OSI 或 TCP/IP 模型中，網路層（Internet Layer）負責跨網路的封包轉送與邏輯定址。常見協定有 IP、ICMP（網路控制訊息）、ARP（將 IP 解析為 MAC，傳統上劃分於網際網路層）以及 RARP。SIP 則是負責通訊會話的應用層協定。

【各選項解析】
  • ① ARP: 正確。用於將網路層的 IP 位址對應解析為硬體 MAC 位址。
  • ② ICMP: 正確。負責傳遞路由錯誤與測試控制訊息，運作於網路層。
  • ③ SIP: 錯誤。SIP (Session Initiation Protocol) 用於 VoIP，屬於應用層。
  • ④ RARP: 正確。用於將 MAC 解析回 IP 位址，屬於網路層協定。
主題：傳輸協定類型
230. 下列哪些屬於非連接導向通訊（Connectionless Communication）？
① TFTP
② FTP
③ SNMP
④ Ping
💡 點擊展開解答與解析
✅ 正確答案：①、③
【綜合解析】

非連接導向通訊在傳送資料前不須事先建立專屬連線。通常基於傳輸層 UDP 協定的應用皆屬於此類。TFTP (簡單檔案傳輸) 和 SNMP (簡易網路管理) 都是在傳輸層使用 UDP 協定運作的標準應用。

【各選項解析】
  • ① TFTP: 正確。基於 UDP 協定，為非連接導向通訊。
  • ② FTP: 錯誤。基於 TCP，傳輸前需建立三向交握，是連接導向。
  • ③ SNMP: 正確。基於 UDP 協定，為非連接導向通訊。
  • ④ Ping: 錯誤。Ping 底層使用 ICMP，雖然本身不需建立連線，但依官方題庫標準答案分類中，此處主要考量依賴 UDP 的應用協定，未被選入。
主題：DHCP 特性
231. 下列哪些是 DHCP（Dynamic Host Configuration Protocol）的優點？
① 更多的 IP 位址
② 自動更新 IP 相關參數設定
③ 自動分配 IP 位址給主機
④ 避免 IP 位址衝突
💡 點擊展開解答與解析
✅ 正確答案：②、③、④
【綜合解析】

DHCP 最大的優勢是動態且集中化地分配 IP 位址、子網遮罩及預設閘道等網路參數。網管人員不需逐台手動設定，系統能自動避免分配重複 IP 造成衝突。但 DHCP 無法「創造」更多 IP 位址，IP 數量是由子網路遮罩切割決定的。

【各選項解析】
  • ① 更多的 IP 位址: 錯誤。無法無中生有增加 IP 總數量。
  • ② 自動更新參數設定: 正確。客戶端可於重新連線或租約到期時自動更新設定。
  • ③ 自動分配 IP 給主機: 正確。這是 DHCP 最核心的功能。
  • ④ 避免 IP 位址衝突: 正確。透過伺服器集中記錄與管理，避免 IP 重複發放。
主題：DNS 目的
232. 下列哪些是 DNS（Domain Name System）的目的？
① 協助使用者取得 某公司名稱
② 協助使用者取得某主機的 IP 位址
③ 將網域名稱轉成 IP 位址
④ 將 IP 位址轉成實體位址
💡 點擊展開解答與解析
✅ 正確答案：②、③
【綜合解析】

網域名稱系統（DNS）就如同網路的電話簿，主要功能是在易於記憶的網域名稱（如 www.test.com）與機器實際通訊使用的 IP 位址之間進行轉換解析（正向與反向查詢）。

【各選項解析】
  • ① 協助取得公司名稱: 錯誤。這不是 DNS 系統提供的服務。
  • ② 取得某主機的 IP 位址: 正確。透過域名可查出實際 IP。
  • ③ 將網域名稱轉成 IP 位址: 正確。即正解功能。
  • ④ 將 IP 位址轉成實體位址: 錯誤。這是 ARP 協定（解析 MAC 位址）的功能。
主題：資料鏈路層功能
233. 下列哪些是資料鏈路層（Data Link Layer）的功能？
① 流量控制
② 錯誤通知
③ 指定 IP 位址
④ 實體定址(Physical Addressing)
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

OSI 模型的第二層「資料鏈路層」負責將位元組成訊框（Frame），利用 MAC 位址進行實體硬體定址，並具備同網段相鄰節點間的流量控制（如 802.3x）以及利用 FCS 機制檢查訊框並發出錯誤通知。指定 IP 則是第三層網路層的工作。

【各選項解析】
  • ① 流量控制: 正確。確保相鄰設備間不會因傳送過快而掉包。
  • ② 錯誤通知: 正確。透過 FCS 檢查損壞訊框並做相應處理。
  • ③ 指定 IP 位址: 錯誤。這是網路層 (Network Layer) 的功能。
  • ④ 實體定址: 正確。利用 MAC 位址進行硬體辨識定址。
主題：應用層協定
234. 下列哪些應用是使用於應用層（Application Layer）？
① E-mail
② TCP
③ SIP
④ 雲端文書處理軟體
💡 點擊展開解答與解析
✅ 正確答案：①、④
【綜合解析】

應用層是 OSI/TCP 模型中最頂端的一層，直接為使用者的應用程式提供網路服務與介面。電子郵件（SMTP/POP3）與網頁上的雲端文書處理軟體（HTTP）都是使用者直接操作的應用服務。TCP 屬於傳輸層，而 SIP 雖為會話層次協定但在官方這題中未被選入。

【各選項解析】
  • ① E-mail: 正確。使用於應用層。
  • ② TCP: 錯誤。屬於第四層傳輸層協定。
  • ③ SIP: 錯誤。依官方答案定義，未將此項列為一般常見應用程式範疇。
  • ④ 雲端文書處理軟體: 正確。這是透過 Web 協定提供的終端應用服務。
主題：乙太網路 CSMA/CD
235. 有關乙太網路（Ethernet）運作，下列哪些正確？
① 碰撞發生後，工作站須後退（Back off）並等待一段時間
② 傳送資料前，工作站須先傾聽 （Listen）
③ 傾聽傳輸媒體前，工作站可以傳送資料
④ 當碰撞發生，工作站仍可傳送資料
💡 點擊展開解答與解析
✅ 正確答案：①、②
【綜合解析】

傳統乙太網路的核心控制機制為 CSMA/CD (載波感測多重存取/碰撞偵測)。工作站必須「先聽後說」(Carrier Sense)，確定線路無人使用才傳送；如果偵測到「碰撞」，則必須立刻停止傳送，並利用後退演算法 (Back-off algorithm) 隨機等待一段時間後再重新嘗試。

【各選項解析】
  • ① 後退並等待: 正確。這能避免參與碰撞的節點再度同時發送。
  • ② 傳送前須傾聽: 正確。「Listen before talk」是 CSMA 的基本原則。
  • ③ 傾聽前可傳送: 錯誤。未傾聽就傳送會導致嚴重的碰撞。
  • ④ 碰撞發生仍可傳送: 錯誤。偵測到碰撞必須立即停止傳輸。
主題：資料鏈路層協定
236. 下列哪些協定使用在資料鏈路層（Data Link Layer）？
① LLC
② IP
③ MAC
④ UDP
💡 點擊展開解答與解析
✅ 正確答案：①、③
【綜合解析】

根據 IEEE 802 標準，OSI 模型的第二層「資料鏈路層」被進一步細分為兩個子層：負責與網卡硬體互動與定址的下半部 MAC (媒體存取控制) 子層，以及負責與上層網路層溝通的上半部 LLC (邏輯鏈路控制) 子層。

【各選項解析】
  • ① LLC: 正確。邏輯鏈路控制，屬於第二層的上層部分。
  • ② IP: 錯誤。屬於第三層網路層。
  • ③ MAC: 正確。媒體存取控制，屬於第二層的下層部分。
  • ④ UDP: 錯誤。屬於第四層傳輸層。
主題：連接導向網路特性
237. 下列哪些是連接導向（Connection-oriented）網路協定的特性？
① 無路徑選擇
② 具動態路徑選擇
③ 具靜態路徑選擇
④ 需保留網路資源
💡 點擊展開解答與解析
✅ 正確答案：③、④
【綜合解析】

連接導向的通訊方式（如建立虛擬電路或 TCP 握手）在開始資料傳輸前，會先確立一條點對點的固定（靜態）邏輯路徑，並在沿途設備上建立狀態或保留所需的網路資源（頻寬、緩衝區），確保通訊穩定且有先後順序。

【各選項解析】
  • ① 無路徑選擇: 錯誤。建立連線時必定需要決定路徑。
  • ② 具動態路徑選擇: 錯誤。一旦連線建立，後續封包皆走固定確立的路徑，不會每個封包動態亂跑。
  • ③ 具靜態路徑選擇: 正確。連線確立後傳輸路徑即被固定下來。
  • ④ 需保留網路資源: 正確。沿途節點需維護連線狀態或保留資源。
主題：連接導向傳輸步驟
238. 連接導向（Connection-oriented）網路協定資料傳送包含下列哪些步驟？
① 建立連線
② 測試連線
③ 傳送資料
④ 中止連線
💡 點擊展開解答與解析
✅ 正確答案：①、③、④
【綜合解析】

任何標準的連接導向通訊（以 TCP 為例）都包含三個必然的生命週期階段：首先雙方協議「建立連線」；接著才能夠穩定可靠地「傳送資料」；通訊結束後，雙方必須進行「中止連線」的步驟以釋放網路資源。

【各選項解析】
  • ① 建立連線: 正確。為傳輸前的必備步驟。
  • ② 測試連線: 錯誤。這不是通訊協定標準的獨立步驟。
  • ③ 傳送資料: 正確。核心的通訊階段。
  • ④ 中止連線: 正確。用以關閉通道與釋放資源。
主題：區域網路壅塞原因
239. 在區域網路（LAN）中，造成壅塞的可能原因有哪些？
① 可用頻寬不足
② VLAN 分段
③ 同一個廣播領域中有太多網路裝置
④ 廣播風暴
💡 點擊展開解答與解析
✅ 正確答案：①、③、④
【綜合解析】

網路壅塞是指過多流量塞住傳輸通道。可能的原因包含網路設計初期頻寬就不足，或是因為實體廣播網域過大，導致過多無效廣播封包占用頻寬，甚至發生 L2 迴圈引發癱瘓網路的「廣播風暴」。相反地，切割 VLAN 則是為了隔離廣播網域，是解決壅塞的方法。

【各選項解析】
  • ① 可用頻寬不足: 正確。最直觀的壅塞主因。
  • ② VLAN 分段: 錯誤。切割 VLAN 能縮小廣播範圍，是減緩壅塞的好方法。
  • ③ 太多網路裝置: 正確。同網域裝置過多會衍生龐大的廣播與碰撞問題。
  • ④ 廣播風暴: 正確。無窮迴圈的廣播封包會瞬間耗盡所有交換器頻寬。
主題：FTP 協定特性
240. 關於 FTP（File Transfer Protocol）協定，下列哪些正確？
① 傳輸層採用 TCP 協定
② 傳輸層採用 UDP 協定
③ 支援主動式（Active）連線方式
④ 支援被動式（Passive）連線方式
💡 點擊展開解答與解析
✅ 正確答案：①、③、④
【綜合解析】

FTP 是一種依賴穩定傳輸的檔案協定，因此傳輸層必然採用 TCP 來確保檔案資料零遺失。為了應付現代網路防火牆及 NAT 的各種阻擋環境，FTP 發展出了兩種傳輸連線模式：主動式模式（Active）與被動式模式（Passive）。

【各選項解析】
  • ① 採用 TCP 協定: 正確。確保資料傳輸的可靠性。
  • ② 採用 UDP 協定: 錯誤。UDP 不具備檔案傳輸所需的可靠度檢核。
  • ③ 支援主動式: 正確。傳統由伺服器端連向客戶端建立資料通道的模式。
  • ④ 支援被動式: 正確。由客戶端連向伺服器隨機大埠號建立資料通道的模式。
主題：主動式 FTP
241. 關於主動式 FTP （Active File Transfer Protocol）協定，下列哪些正確？
① 不須經由三向交握（Three-way Hand-shaking）建立命令傳輸通道
② FTP 伺服器端預設使用 port 21 作為命令傳輸通道
③ FTP 伺服器端預設使用 port 20 作為資料傳輸通道
④ FTP 伺服器端主動向用戶端請求建立資料傳輸通道
💡 點擊展開解答與解析
✅ 正確答案：②、③
【綜合解析】

在主動式 FTP 模式下，客戶端會先連線到伺服器的 TCP Port 21 建立「命令通道」。當要開始傳輸資料時，伺服器會使用自己的 TCP Port 20，主動對客戶端開啟的接收埠發起連線建立「資料通道」。(依勞動部官方答案，僅採納 Port 的定義部分)。

【各選項解析】
  • ① 不須三向交握: 錯誤。FTP 基於 TCP，必定需要透過三向交握。
  • ② 預設 port 21: 正確。作為命令與控制訊號傳輸通道。
  • ③ 預設 port 20: 正確。伺服器利用 Port 20 傳輸檔案資料。
  • ④ 伺服器端主動請求: 錯誤。(備註：實務上此敘述概念無誤，但因官方題庫答案僅選②③，故依考題標準判定為不選)。
主題：被動式 FTP
242. 關於被動式 FTP（Passive File Transfer Protocol）協定，下列哪些正確？
① 須經由三向交握（Three-way Hand-shaking）建立命令傳輸通道
② FTP 伺服器端預設使用 port 21 作為命令傳輸通道
③ FTP 伺服器端預設使用 port 20 作為資料傳輸通道
④ FTP 用戶端主動向伺服器端請求建立資料連線
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

在被動式 FTP (Passive Mode) 下，伺服器依舊使用 Port 21 接收控制命令。但要傳輸資料時，伺服器不再使用 Port 20，而是隨機開啟一個高於 1024 的 Port，並等待「客戶端主動連過來」建立資料通道。這種模式能避免防火牆擋下由外而內的連線。

【各選項解析】
  • ① 須經由三向交握: 正確。因為底層是 TCP 協定。
  • ② 預設 port 21: 正確。控制命令通道始終維持 Port 21。
  • ③ 預設 port 20: 錯誤。被動模式下資料通道是由伺服器開大於 1024 的隨機埠號，不使用 Port 20。
  • ④ 用戶端主動連線: 正確。這是解決客戶端位於 NAT 背後無法被伺服器連線的關鍵機制。
主題：FTP 安全性
243. 關於 FTP（File Transfer Protocol）協定，下列哪些正確？
① 命令傳輸通道未加密
② 資料傳輸通道未加密
③ 命令傳輸通道加密
④ 資料傳輸通道加密
💡 點擊展開解答與解析
✅ 正確答案：①、②
【綜合解析】

傳統的 FTP 協定（未結合 SSL 的 FTPS 或 SSH 的 SFTP 前）在設計上完全是明文傳輸的。無論是用戶端登入時的帳號密碼（命令通道），或是實際傳送的檔案內容（資料通道），都能輕易被網路封包側錄軟體攔截並解讀，非常不安全。

【各選項解析】
  • ① 命令傳輸通道未加密: 正確。以明文傳輸帳密。
  • ② 資料傳輸通道未加密: 正確。以明文傳輸所有檔案內容。
  • ③ 命令傳輸通道加密: 錯誤。
  • ④ 資料傳輸通道加密: 錯誤。
主題：HTTPS 安全協定
244. 關於 HTTPS（Hypertext Transfer Protocol Secure）協定，下列哪些正確？
① 採用 SSL/TLS 協定
② 採用 SSH 協定
③ 支援加密通訊及對網頁伺服器身分的鑑別
④ 經常用於全球資訊網敏感訊息的傳輸
💡 點擊展開解答與解析
✅ 正確答案：①、③、④
【綜合解析】

HTTPS 是一種將 HTTP 運行於安全通道上的協定。它採用了 SSL（或現今更新的 TLS）協定進行資料加密，不僅能確保使用者瀏覽網頁與傳送表單（如密碼、信用卡號）不被中途竊聽，還能透過公開憑證（CA）機制來確認對方伺服器身分是否真實。

【各選項解析】
  • ① 採用 SSL/TLS: 正確。這是 HTTPS 用來加密底層通訊的核心技術。
  • ② 採用 SSH: 錯誤。SSH 主要用於系統遠端登入與指令操作，與網頁的 HTTPS 無關。
  • ③ 支援加密與身分鑑別: 正確。利用非對稱加密與憑證來達成。
  • ④ 用於傳輸敏感訊息: 正確。現代網站包含購物、登入都強制依賴此標準。
主題：Telnet 遠端登入
245. 關於 Telnet 協定，下列哪些正確？
① 採用 Client-Server 方式運作
② 可提供遠端登入之功能
③ 可提供加密功能
④ 為較不安全之遠端登入服務
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

Telnet 是網路上極早期發展的終端機遠端登入協定。使用者透過 Client 端連線到 Server 端，並在文字介面下操作伺服器。但是它最大缺點是所有資料包含指令、帳號與密碼都是「明文」傳送，不具備任何加密功能，容易被有心人截取。

【各選項解析】
  • ① 採用 Client-Server 方式: 正確。主從架構設計。
  • ② 可提供遠端登入: 正確。核心用途。
  • ③ 可提供加密功能: 錯誤。Telnet 毫無加密能力。
  • ④ 較不安全: 正確。因為明文傳輸，所以現代已被 SSH 大量取代。
主題：SSH 安全終端
246. 關於 SSH（Secure Shell） 協定，下列哪些正確？
① 採用 Client-Server 方式運作
② 可提供遠端登入功能
③ 可提供加密功能
④ 為安全考量，多數伺服器已停用 SSH 服務
💡 點擊展開解答與解析
✅ 正確答案：①、②、③
【綜合解析】

SSH (Secure Shell) 被設計用來替換掉不安全的 Telnet。它同樣採用主從架構提供遠端命令列登入，但連線全程都是經過高強度加密的，可防範監聽與中間人攻擊。正因它的安全性極高，現在幾乎所有 Linux 伺服器都「依賴並預設開啟」SSH 以進行遠端管理。

【各選項解析】
  • ① 採用 Client-Server: 正確。具備 SSH 用戶端與伺服器端。
  • ② 提供遠端登入: 正確。可安全地在終端機操作伺服器。
  • ③ 提供加密功能: 正確。全程使用公私鑰及對稱加密傳輸。
  • ④ 已停用 SSH 服務: 錯誤。停用的是不安全的 Telnet，SSH 反而是必備開啟的服務。
主題：通訊埠號對應
247. 關於通訊協定之敘述，下列哪些正確？
① HTTPS(Hypertext Transfer Protocol Secure)協定預設採用 port 24
② Telnet 協定預設採用 port 23
③ SSH(Secure Shell)協定預設採用 port 22
④ SMTP(Simple Mail Transfer Protocol)協定預設採用 port 25
💡 點擊展開解答與解析
✅ 正確答案：②、③、④
【綜合解析】

網路應用層服務大多具備國際網路號碼分配局（IANA）統一規定的「知名通訊埠（Well-known Ports）」。這能讓用戶端知道要連向伺服器的哪個門口。其中 HTTPS 正確的預設埠號是 443，其餘選項標示皆正確。

【各選項解析】
  • ① HTTPS 採用 port 24: 錯誤。HTTPS 預設的連接埠為 TCP 443。
  • ② Telnet 採用 port 23: 正確。預設為 TCP 23。
  • ③ SSH 採用 port 22: 正確。預設為 TCP 22。
  • ④ SMTP 採用 port 25: 正確。郵件發送服務預設為 TCP 25。
主題：SMTP 郵件發送
248. 關於 SMTP（Simple Mail Transfer Protocol）協定，下列哪些正確？
① 為 Server 與 Server 之間的通訊協定
② 可用於傳送（Transfer）電子郵件
③ 用戶端可自郵件伺服器接收電子郵件
④ 可用於轉送（Relay）電子郵件
💡 點擊展開解答與解析
✅ 正確答案：①、②、④
【綜合解析】

SMTP (簡易郵件傳輸協定) 在電子郵件系統中專門扮演「郵差」的角色。它負責將使用者寄出的信件發送到伺服器，並在不同郵件伺服器之間傳送與轉信（Relay）。但是，它不提供「使用者收信」的功能，收信下載必須依靠 POP3 或 IMAP 協定。

【各選項解析】
  • ① Server 與 Server 間通訊: 正確。MTA (Mail Transfer Agent) 之間互相傳信就是依靠 SMTP。
  • ② 傳送電子郵件: 正確。專門用於發送信件。
  • ③ 接收電子郵件: 錯誤。Client 接收/下載信件是 POP3/IMAP 的工作。
  • ④ 轉送電子郵件: 正確。這也就是大家常說的郵件 Relay 轉信。
主題：POP3 郵件接收
249. 關於 POP3（Post Office Protocol - Version 3）協定，下列哪些正確？
① 採用 Client-Server 方式運作
② 可用於伺服器間傳送（Transfer）電子郵件
③ 用戶端可自郵件伺服器接收電子郵件
④ 可用於轉送（Relay）電子郵件
💡 點擊展開解答與解析
✅ 正確答案：①、③
【綜合解析】

POP3 是一種專門用於「收信」的應用層協定。使用者利用郵件軟體（如 Outlook）作為 Client，連線至 POP3 Server，即可將信箱內的電子郵件一次性下載至使用者的電腦中。POP3 不負責信件的發送或伺服器間的轉信作業。

【各選項解析】
  • ① 採用 Client-Server 方式: 正確。由終端軟體連線伺服器取信。
  • ② 伺服器間傳送: 錯誤。這是 SMTP 的功能。
  • ③ 用戶端接收郵件: 正確。即下載郵件。
  • ④ 轉送電子郵件: 錯誤。POP3 無 Relay 轉信功能。
主題：IMAP 郵件接收
250. 關於 IMAP（Internet Message Access Protocol）協定，下列哪些正確？
① 採用 Client-Server 方式運作
② 可用於伺服器間傳送（Transfer）電子郵件
③ 用戶端可自郵件伺服器接收電子郵件
④ 可用於轉送（Relay）電子郵件
💡 點擊展開解答與解析
✅ 正確答案：①、③
【綜合解析】

IMAP 與 POP3 一樣都是提供用戶端「收信與管理郵件」的協定。其優勢在於用戶端能直接連線到伺服器管理信件狀態（已讀、分類等）而不需強迫下載刪除，方便多種裝置（手機、電腦）同步郵件。但與發送、轉信（SMTP）的功能無關。

【各選項解析】
  • ① 採用 Client-Server 方式: 正確。Client 連線至 Server 端進行同步與讀取。
  • ② 伺服器間傳送: 錯誤。屬於 SMTP 的範疇。
  • ③ 用戶端接收郵件: 正確。用於讀取伺服器上的信件。
  • ④ 轉送電子郵件: 錯誤。轉信是 SMTP 的專屬任務。
